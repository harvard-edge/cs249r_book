### Algorithmic structure {#sec-network-architectures-algorithmic-structure-99f2}

All-to-all feature interaction requires complete connectivity between adjacent layer representations. In an MLP, this manifests as a sequence of fully connected layers\index{Fully-connected layer} where every neuron connects to every neuron in the preceding layer. Dense connectivity\index{Dense connectivity} translates directly into matrix multiplication, the formulation that makes dense layers executable on parallel hardware. @Fig-mlp diagrams this structural lowering: the fully connected graph on the left maps directly to the matrix-vector products on the right, where each hidden neuron's activation computes a dot product against an entire column of the weight matrix.

::: {.column-margin .margin-pointer}
↩ The matrix multiplication formulation of a dense layer's forward pass is established in @sec-neural-computation-matrix-multiplication-formulation-417c.
:::

:::

@Eq-dense-layer expresses the dense layer's affine transformation followed by its activation.
$$
\mathbf{h}^{(\LayerIndex)} = f\big(\mathbf{h}^{(\LayerIndex-1)}\mathbf{W}^{(\LayerIndex)} + \mathbf{b}^{(\LayerIndex)}\big)
$$ {#eq-dense-layer}

$\mathbf{h}^{(\LayerIndex)}$ represents the layer $\LayerIndex$ output, $\mathbf{h}^{(\LayerIndex-1)}$ represents the input from the previous layer, $\mathbf{W}^{(\LayerIndex)}$ denotes the weight matrix for layer $\ell$, $\mathbf{b}^{(\LayerIndex)}$ denotes the bias vector, and $f(\cdot)$ denotes the activation function. This layer-wise transformation, while conceptually simple, creates computational patterns whose efficiency depends critically on how the runtime organizes these operations for different problem structures.

The dimensions of these operations reveal the computational scale of dense pattern processing. The input vector $\mathbf{h}^{(0)} \in \mathbb{R}^{\LayerInputWidth}$ (treated as a row vector in this formulation) represents all potential input features. Weight matrices $\mathbf{W}^{(\LayerIndex)} \in \mathbb{R}^{\LayerInputWidth \times \LayerOutputWidth}$ capture all possible input-output relationships. The output vector $\mathbf{h}^{(\LayerIndex)} \in \mathbb{R}^{\LayerOutputWidth}$ produces transformed representations. A four-pixel example turns this bookkeeping into arithmetic.

::: {#exmp-nn-architectures-concrete-computation-example .callout-example title="Concrete computation example"}

Consider a simplified 4-pixel image processed by a 3-neuron hidden layer:

**Input**: $\mathbf{h}^{(0)} = [0.8, 0.2, 0.9, 0.1]$ (4 pixel intensities)

```{=latex}
\begingroup
\renewcommand{\arraystretch}{1.05}
```

**Weight matrix**:
$$
\mathbf{W}^{(1)} = \begin{bmatrix} 0.5 & 0.1 & -0.2 \\ -0.3 & 0.8 & 0.4 \\ 0.2 & -0.4 & 0.6 \\ 0.7 & 0.3 & -0.1 \end{bmatrix}\quad (4{\times}3 \text{ matrix})
$$

**Computation**:
\begin{gather*}
\mathbf{z}^{(1)T} = (\mathbf{h}^{(0)}\mathbf{W}^{(1)})^T = \begin{bmatrix} 0.5{\times}0.8 + (-0.3)\times 0.2 + 0.2{\times}0.9 + 0.7{\times}0.1 \\ 0.1{\times}0.8 + 0.8{\times}0.2 + (-0.4)\times 0.9 + 0.3{\times}0.1 \\ (-0.2)\times 0.8 + 0.4{\times}0.2 + 0.6{\times}0.9 + (-0.1)\times 0.1 \end{bmatrix}
= \begin{bmatrix} 0.59 \\ -0.09 \\ 0.45 \end{bmatrix}
\end{gather*}
**After ReLU**: $\mathbf{h}^{(1)} = [0.59, 0, 0.45]$ (negative values zeroed)

```{=latex}
\endgroup
```

**Systems insight**: Each hidden neuron combines all input pixels with different weights, demonstrating unrestricted feature interaction. Dense layers buy generality by paying the maximum connectivity cost.

:::

The MNIST example makes this scale concrete. The 784-dimensional input connects to every neuron in the first hidden layer. A hidden layer with 100 neurons requires a $784{\times}100$ weight matrix (78,400 parameters), where each weight represents a learnable relationship between an input pixel and a hidden feature. This single layer anchors the computational analysis throughout this chapter.

This algorithmic structure enables arbitrary feature relationships while creating specific computational patterns that computer systems must accommodate. Dense connectivity provides the universal approximation capability but introduces computational redundancy: while the theoretical universality of MLPs enables modeling of any continuous function given sufficient width, this flexibility requires numerous parameters to learn relatively simple patterns. Every input feature influences every output, yielding maximum expressiveness at the cost of maximum computational expense. These trade-offs motivate later compression strategies that reduce computational demands while preserving model capability.
