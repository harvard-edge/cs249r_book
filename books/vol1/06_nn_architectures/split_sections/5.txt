### Portable building blocks {#sec-network-architectures-core-computational-primitives-b853}

The rows of @tbl-nn-architectures-machine-demands differ, but the operators inside them repeat. A transformer block reuses dense projections encountered in MLPs, residual paths illustrated by deep CNNs, normalization for activation stability, and gating-like routing in later variants. @Tbl-dl-evolution connects each building block\index{Architecture!building blocks} to a representative context and to other architectures that use it. Each block brings its hardware cost with it, so an optimization for residual additions or normalization kernels can transfer across families.

#### Dense projections: The universal baseline {#sec-network-architectures-evolution-perceptron-multilayer-networks-d06e}

General matrix multiplication is the one primitive every row of the profile shares. It is the feedforward layer inside every transformer block, the $1{\times}1$ pointwise convolution in MobileNets, the input and recurrent projections inside every RNN cell, and the bottom and top MLPs of DLRM. Convolution reaches the same path through the im2col patch unfolding diagrammed in @fig-im2col-diagram, and dedicated matrix engines, such as GPU Tensor Cores and the systolic arrays\index{Systolic array!CNN data reuse}[^fn-systolic-array-architecture] of TPUs, exist because this one primitive dominates the operation count of nearly every workload. Its hardware cost depends on shape rather than on the family that invokes it. Grouping independent samples or tokens into a matrix converts a matrix-vector product into a matrix-matrix product with greater reuse. The higher intensity can cross the target machine's balance point, which is why batch size changes the modeled regime of three rows of the table.

[^fn-systolic-array-architecture]: **Systolic array**\index{Systolic array!etymology}\index{Systolic array!TPU}: Named for the heart's rhythmic contraction, the array's lockstep "pulse" of data through a grid of multiply-accumulate processors directly implements the data reuse that matrix multiplication and convolution require. By passing input values between neighboring processors, an expensive round-trip to off-chip DRAM is avoided for every single multiplication. This is critical for efficiency, as a single off-chip memory access can cost over 100$\times$ more energy than a floating-point multiply-accumulate, and still more relative to low-precision arithmetic.

Dense connectivity also sets the cost baseline that the other families escape. At $\mathcal{O}(\HiddenDimension^2)$ parameters and operations for layers of width $\HiddenDimension$, GEMM is the reference point against which CNNs ($\mathcal{O}(K^2)$ parameters per location), attention ($\mathcal{O}(S^2)$ score interactions), and embedding lookups (no arithmetic per category) demonstrate their savings. None of them escapes GEMM itself; it reappears inside every architecture as the workhorse of feature transformation.

#### Skip connections: Solving the depth problem {#sec-network-architectures-evolution-dense-spatial-processing-2761}

Parameter sharing and dense projections made deep networks computationally tractable, but efficiency alone could not make them trainable. As networks grew deeper, repeated matrix multiplications and activation derivatives drove gradient signals either toward numerical underflow or toward floating-point overflow. Skip connections\index{Skip connection!cross-architecture portability} resolve this optimization barrier with additive identity shortcuts that bypass the layer transformations, and the shortcuts carry a concrete hardware cost that every deep network pays. Evaluating $\mathbf{y} = \mathcal{F}(\mathbf{x}) + \mathbf{x}$ requires the input tensor $\mathbf{x}$ to remain resident in memory throughout the execution of every operation in the branch $\mathcal{F}(\mathbf{x})$. This extended liveness window increases peak activation memory in accelerator HBM during the forward pass and preserves $\mathbf{x}$ for backpropagation unless activation checkpointing is used. The elementwise addition is also memory-bandwidth bound. It performs one addition per two loaded operands and one stored result, about 0.08 FLOP/byte in FP32 (one FLOP per 12 bytes), so un-fused residual merges become memory stalls.

The depth problem\index{Network depth!training difficulty} follows from the chain rule, whose layer-by-layer Jacobian form appears in @sec-neural-computation-error-signal-propagation-9eeb. For a deep network with layers $f_1, f_2, \ldots, f_{\NumberOfLayers}$, the gradient of the loss $\LossFunction$ with respect to the weights in layer 1 is:
$$
\frac{\partial \LossFunction}{\partial \mathbf{W}^{(1)}} = \frac{\partial \LossFunction}{\partial \mathbf{a}^{(\NumberOfLayers)}} \cdot \frac{\partial \mathbf{a}^{(\NumberOfLayers)}}{\partial \mathbf{z}^{(\NumberOfLayers)}} \cdot \frac{\partial \mathbf{z}^{(\NumberOfLayers)}}{\partial \mathbf{a}^{(\NumberOfLayers-1)}} \cdot \ldots \cdot \frac{\partial \mathbf{z}^{(2)}}{\partial \mathbf{a}^{(1)}} \cdot \frac{\partial \mathbf{a}^{(1)}}{\partial \mathbf{z}^{(1)}} \cdot \frac{\partial \mathbf{z}^{(1)}}{\partial \mathbf{W}^{(1)}}
$$
where $\mathbf{z}^{(\LayerIndex)}$ represents the preactivation and $\mathbf{a}^{(\LayerIndex)} = \sigma(\mathbf{z}^{(\LayerIndex)})$ the postactivation output of layer $\LayerIndex$. Each layer contributes both a weight transformation and an activation derivative $\sigma'(\mathbf{z}^{(\LayerIndex)})$. With sigmoid activations, whose derivative peaks at 0.25 (@sec-neural-computation-sigmoid-a98f), the activation-derivative factors alone contribute at most $(0.25)^{\NumberOfLayers}$ along a path. The full gradient also depends on the intervening weight matrices; when their transformations do not offset this attenuation, early layers receive negligible updates. Exploding gradients\index{Exploding gradient problem} are the destabilizing counterpart. If each layer Jacobian expands a shared direction by about 1.5, that component grows exponentially, producing overflow, NaN (not-a-number) values, and training divergence rather than a silent stall.

ReLU\index{ReLU} removes the activation's share of this decay, since its derivative is one on active paths (@sec-neural-computation-relu-7184), and that change made networks of 10–20 layers trainable. It does not remove the problem. Inactive units pass zero gradient, and a poorly initialized weight or a large update can leave a unit permanently dead\index{Dead neuron}\index{ReLU!dead neuron}; more fundamentally, ReLU does nothing to regulate the singular values of the weight matrices, which continue to attenuate or amplify gradients across depth. The original ResNet study showed the consequence on CIFAR-10: a 56-layer plain network had higher training and test error than a 20-layer plain network throughout training [@he2016]. Because the deeper network was worse on the *training* set, the failure was an optimization barrier, not overfitting.

ResNet blocks introduce residual learning\index{Residual learning} through skip connections that transform gradient flow\index{Gradient!flow in residual networks}. @Eq-residual adds the identity path $\mathbf{x}$ to the residual mapping $\mathcal{F}(\mathbf{x})$:
$$
\mathbf{y} = \mathcal{F}(\mathbf{x}) + \mathbf{x}
$$ {#eq-residual}
where $\mathcal{F}(\mathbf{x})$ represents the residual function (typically two convolutional layers with batch normalization and ReLU) and $\mathbf{x}$ is the identity skip connection. @Fig-example-skip-connection diagrams this original post-activation ResNet block: an identity shortcut bypasses two parameter weight layers and their intermediate ReLU to merge at the addition junction before the final activation.

During backpropagation, the gradient flows through this addition, and applying the chain rule gives:
$$
\frac{\partial \mathcal{L}}{\partial \mathbf{x}} =
\frac{\partial \mathcal{L}}{\partial \mathbf{y}} \cdot
\left(\frac{\partial \mathcal{F}(\mathbf{x})}{\partial \mathbf{x}} + \mathbf{I}\right)
= \frac{\partial \mathcal{L}}{\partial \mathbf{y}} \cdot
\mathcal{F}'(\mathbf{x}) +
\frac{\partial \mathcal{L}}{\partial \mathbf{y}}
$$

Here $\mathbf{I}$ is the identity matrix, and the gradient decomposes into two additive terms. Even if the residual term $\frac{\partial \mathcal{L}}{\partial \mathbf{y}}\mathcal{F}'(\mathbf{x})$ attenuates, the identity term passes $\frac{\partial \mathcal{L}}{\partial \mathbf{y}}$ directly to the earlier layer. While the residual branch can partially interfere with the identity signal, keeping $\|\mathcal{F}'(\mathbf{x})\|$ small keeps the block Jacobian close to identity and bounds its condition number. Through $\NumberOfLayers$ residual blocks, the gradient becomes:
$$
\frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(0)}} =
\frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(\NumberOfLayers)}} \cdot
\prod_{\LayerIndex=1}^{\NumberOfLayers}
\left(\mathcal{F}'_\LayerIndex(\mathbf{x}^{(\LayerIndex-1)}) + \mathbf{I}\right)
$$

Each factor $(\mathcal{F}'_\ell + \mathbf{I})$ contains the identity term, keeping the factor near identity when the residual-branch Jacobian is small. A plain network instead multiplies arbitrary layer Jacobians, and if their average gain is even slightly below one the product vanishes exponentially ($0.9^{50} \approx 0.005$). ResNets multiply near-identity factors. The deviations can still compound, and the additive path does not guarantee exact unit gain across arbitrary depth, but this structure improves conditioning enough to make networks with 100+ layers trainable. The CIFAR-10 experiments confirm it: a 56-layer residual network reached about 7.0 percent test error against 8.8 percent for its 20-layer residual counterpart, reversing the degradation seen in plain networks [@he2016]. There is no single depth at which skip connections suddenly become mandatory; trainability also depends on initialization, normalization, optimizer dynamics, and block architecture [@he2016identity].

Residual connections stabilize the backward gradient path, but they do not constrain the forward scale of intermediate activations. Unbounded variance across depth can still destabilize layer inputs, which calls for a complementary block: normalization.

#### Normalization: Stabilizing activations at depth {#sec-network-architectures-normalization-layers-mathematical-foundations-0fb7}

Normalization functions as the forward-pass partner to skip connections: where residual paths preserve backward gradient flow, normalization stabilizes the distribution of intermediate activations. Batch normalization in CNNs[^fn-batch-normalization-ioffe] [@ioffe2015batch], layer normalization for sequence models, and RMSNorm[^fn-rmsnorm-layer-efficiency] for large language models illustrate different choices of reduction axes and statistics.

[^fn-rmsnorm-layer-efficiency]: **RMSNorm (root mean square normalization)**\index{RMSNorm}\index{Normalization!RMSNorm}: Introduced by @zhang2019root at NeurIPS, RMSNorm simplifies LayerNorm by normalizing with the root mean square alone, dropping the mean-centering step. Across the paper's tested models and implementations, RMSNorm reduced overall running time by 7--64 percent relative to LayerNorm. LLaMA-family and Mixtral-style transformer reports use RMSNorm [@touvron2023llama; @touvron2023llama2; @jiang2024mixtral], illustrating why a simpler normalization kernel matters at large language model scale. \index{RMSNorm!efficiency}\index{RMSNorm!LLM adoption}

[^fn-batch-normalization-ioffe]: **Batch normalization (BatchNorm)**\index{Batch normalization!training speedup}\index{Batch normalization!training-serving skew}: The original normalization layer [@ioffe2015batch], which re-scales activations using per-mini-batch statistics. In one ImageNet experiment, it reached the target accuracy with 14$\times$ fewer training steps. Its batch-size dependency and training-serving skew (switching from batch statistics to running averages at inference) are systems limitations that motivated alternatives: LayerNorm removed batch dependency for transformers, and RMSNorm removed mean centering.

Batch normalization\index{Batch normalization}\index{Normalization!batch} standardizes activations using statistics computed across the mini-batch for each feature or channel during training. For fully connected activations, the reduction axis is the batch dimension. For convolutional activations, implementations compute per-channel statistics over both the batch and spatial positions ($\BatchSize \times H_{\text{img}} \times W_{\text{img}}$). For a mini-batch $\mathcal{B} = \{x_1, \ldots, x_\BatchSize\}$ of activations at a particular layer, the transformation proceeds in two stages.

First, compute the batch statistics:
$$
\mu_{\mathcal{B}} = \frac{1}{\BatchSize}\sum_{i=1}^{\BatchSize} x_i \qquad \sigma_{\mathcal{B}}^2 = \frac{1}{\BatchSize}\sum_{i=1}^{\BatchSize} (x_i - \mu_{\mathcal{B}})^2
$$

Then, over the batch, normalize and apply learnable scale and shift. The normalization step in @eq-batchnorm-normalize centers and scales activations, while @eq-batchnorm-transform lets the network learn a useful output scale and offset:
$$
\hat{x}_i = \frac{x_i - \mu_{\mathcal{B}}}{\sqrt{\sigma_{\mathcal{B}}^2 + \epsilon}}
$$ {#eq-batchnorm-normalize}
$$
y_i = \gamma \hat{x}_i + \beta
$$ {#eq-batchnorm-transform}

The parameters $\gamma$ (scale) and $\beta$ (shift) are learned during training, while $\epsilon$ (typically $10^{-5}$) prevents division by zero. The affine transform restores learned scale and shift flexibility, but fixed $\gamma$ and $\beta$ cannot exactly invert varying statistics for every batch. Normalization permits larger learning rates by preventing intermediate activations from exploding into saturating non-linear regimes, accelerating convergence relative to unnormalized networks.

While batch normalization enabled training of much deeper CNNs, it introduces severe distributed systems and sequence modeling constraints. In distributed training, computing true mini-batch statistics requires an all-reduce operation across accelerator nodes over PCIe or NVLink, adding communication latency to every normalized layer. If instead computed locally on small per-accelerator batches, noisy empirical statistics destabilize optimization. Furthermore, batch normalization cannot handle variable-length sequences or autoregressive token-by-token generation without complex padding masks and training-serving skew. Layer normalization\index{Layer normalization}\index{Normalization!layer} resolves these limitations by normalizing across the feature dimension rather than across the batch [@ba2016layer].

For an input vector $\mathbf{x} \in \mathbb{R}^{d}$ with $d$ features:
$$
\mu_{\text{LN}} = \frac{1}{\HiddenDimension}\sum_{i=1}^{\HiddenDimension} x_i \qquad \sigma_{\text{LN}}^2 = \frac{1}{\HiddenDimension}\sum_{i=1}^{\HiddenDimension} (x_i - \mu_{\text{LN}})^2
$$

@Eq-layernorm defines the complete layer normalization operation, where $\odot$ denotes element-wise multiplication:
$$
\text{LayerNorm}(\mathbf{x}) = \frac{\mathbf{x} - \mu_{\text{LN}}}{\sqrt{\sigma_{\text{LN}}^2 + \epsilon}} \odot \boldsymbol{\gamma} + \boldsymbol{\beta}
$$ {#eq-layernorm}

Because each token or sample is normalized independently, the computation stays within an accelerator's on-chip SRAM and registers, with no cross-sample or cross-device communication. That independence makes layer normalization the standard choice for transformers, where sequences vary in length and autoregressive generation evaluates a single token at a time. @Tbl-normalization-comparison contrasts the three variants along the machine and operational dimensions that decide between them.

| **Characteristic**        | **BatchNorm**                          | **LayerNorm**            | **RMSNorm**                   |
|:--------------------------|:---------------------------------------|:-------------------------|:------------------------------|
| **Normalization Axis**    | Batch and, for CNNs, spatial positions | Feature dimension        | Feature dimension             |
| **Batch Size Dependency** | High (noisy for small batches)         | None                     | None                          |
| **Typical Use Case**      | CNNs, vision models                    | Transformers, RNNs       | LLaMA, efficient transformers |
| **Computation Cost**      | Higher (mean + variance)               | Higher (mean + variance) | Lower (RMS only)              |
| **Training/Inference**    | Different (running stats)              | Identical                | Identical                     |

: **Normalization Variant Comparison**: Different normalization techniques trade off between computational efficiency, batch size sensitivity, and architectural compatibility. RMSNorm [@zhang2019root], used in LLaMA-family and other efficient transformer architectures [@touvron2023llama; @touvron2023llama2], omits mean centering: $\text{RMSNorm}(\mathbf{x}) = \mathbf{x} / \sqrt{\frac{1}{\HiddenDimension}\sum_i x_i^2 + \epsilon} \odot \boldsymbol{\gamma}$. {#tbl-normalization-comparison tbl-colwidths="[23,34,24,19]"}

The computational profile of normalization is defined by its arithmetic intensity. Because normalization applies elementwise operations to large activation tensors, execution is memory-bandwidth bound rather than compute bound. A straightforward LayerNorm kernel makes two reductions across the hidden dimension $\HiddenDimension$, one for the mean $\mu_{\text{LN}}$ and one for the variance $\sigma_{\text{LN}}^2$, although Welford's algorithm can compute both in a single pass. RMSNorm drops the mean-centering reduction, leaving a single sum of squares, which simplifies the kernel and eases fusion with neighboring operations; its authors report 7--64 percent lower running time across the models they tested.

The table's last row is an operational cost. BatchNorm keeps nonlearned running mean and variance buffers and switches from mini-batch statistics in training to those running statistics at inference, so a mismatch between the buffers and deployment data is a frequent source of training-serving skew. LayerNorm and RMSNorm compute identically in both modes and carry no running state.

#### Gating: Controlling information flow {#sec-network-architectures-evolution-sequence-processing-d809}

Skip connections and normalization stabilize depth, the first by preserving gradient flow and the second by bounding activation variance. Gating\index{Gating mechanism} addresses a different problem: routing information selectively according to the input. Recurrent networks provide a useful example, because simple recurrent loops suffer gradient degradation across long sequences. LSTMs[^fn-lstm-gating-mechanism] [@hochreiter1997] and GRUs[^fn-gru-gated-recurrence] [@cho2014] address this through **gates**\index{Gating mechanism!sequence models}: parameter-weighted transformations that act as differentiable valves to protect, update, or discard stored state.

[^fn-lstm-gating-mechanism]: **LSTM (long short-term memory)**\index{LSTM!gating mechanism}: Invented by Hochreiter\index{Hochreiter, Sepp} and Schmidhuber\index{Schmidhuber, Jürgen} in 1997, LSTMs introduced a "Constant Error Carousel," a gated cell state that protects error signals from exponential decay during backpropagation through time. The systems cost of this solution: a standard LSTM computes input, forget, and output gates plus a candidate cell update, giving roughly four affine transformations per time step vs. one in a vanilla RNN. This compute overhead explains why transformers, which solve long-range dependencies through parallelizable attention, replaced LSTMs in many large-scale language workloads. \index{LSTM!compute overhead}

[^fn-gru-gated-recurrence]: **GRU (gated recurrent unit)**\index{GRU!efficiency}: @cho2014 describes a gated hidden unit for encoder-decoder translation that uses reset and update gates to control how the hidden state is updated. Relative to an LSTM's input, forget, and output gates plus candidate cell update, this gives a simpler gated recurrence. The broader systems lesson: architectural simplification can reduce state and matrix operations when it preserves task performance, a principle that recurs in efficiency-oriented designs from MobileNet to distilled transformers. \index{GRU!parameter efficiency}

Gating generalizes beyond recurrence as the basic mechanism for data-dependent routing. Highway Networks used gates to interpolate between a transformation and an identity bypass, directly inspiring residual shortcuts. Encoder-decoder\index{Encoder-decoder!definition} attention\index{Architecture!encoder-decoder} [@bahdanau2015neural] computes a dynamic routing distribution over input representations, and in transformers the softmax attention weights act as data-dependent routing coefficients that decide how features aggregate across tokens. Mixture-of-experts architectures extend the idea to dispatch each token to a subset of feedforward experts. The hardware cost of gating is irregularity. Dense attention keeps static tensor shapes even though its weights vary per token, but sparse attention, expert routing, and dynamic graph execution\index{Dynamic computation} introduce data-dependent control flow and runtime tensor sizes that defeat static memory allocation and balanced work dispatch.

↪ The irregular memory access that unstructured sparsity, embedding lookups, and dynamic routing impose on hardware is developed in @sec-hardware-acceleration-irregular-memory-access-c6ec.
:::

A transformer block is where all four building blocks meet. In the encoder tower diagrammed in @fig-transformer, residual paths bypass each multi-head attention and feed-forward sub-layer to preserve gradient flow through deep stacks, dense GEMM projections carry the attention and feedforward transformations, LayerNorm or RMSNorm stabilizes activations around each sub-layer, and softmax attention weights gate information across positions. What the transformer changed was the dependency structure. Replacing recurrence with all-to-all attention cut the sequential depth for tokens to interact from $\mathcal{O}(\SequenceLength)$ steps to $\mathcal{O}(1)$, which let the other three blocks run at full width on parallel hardware. Vision Transformers[^fn-vision-transformer-patching] carry the same block set to images [@dosovitskiy2021image].

[^fn-vision-transformer-patching]: **Vision transformers (ViTs)**\index{Vision transformer}: Google's 2020 ViT paper split $224{\times}224$ images into $16{\times}16$ patches (196 "tokens") and applied standard transformer attention. ViTs replace CNN's local convolutions with $\mathcal{O}(S^2)$ global attention over patch tokens. In the original study, large-scale pretraining improved ViT's competitiveness, illustrating how data and compute can compensate for weaker spatial inductive bias [@dosovitskiy2021image]. \index{Vision transformer!compute trade-off}

This portability separates optimizations that transfer from those that do not. GEMM tiling and mixed-precision arithmetic help every row of @tbl-nn-architectures-machine-demands, residual memory management helps every deep network, and normalization kernel fusion helps CNNs and transformers alike. Attention-specific kernels remain tied to attention's memory pattern, but even they are built from the same GEMM and memory-access primitives. The profile and the building blocks describe what each family costs; choosing among families for a particular deployment requires turning those costs into a procedure.
