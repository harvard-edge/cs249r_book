### Efficient architectures: Keyword spotting {#sec-network-architectures-efficient-architectures-keyword-spotting-0625}

MobileNet challenged the trend of ever-larger models by prioritizing efficiency. It popularized depthwise separable convolutions\index{Depthwise separable convolution!MobileNet} (a per-channel spatial filter followed by a $1{\times}1$ channel mix) for efficient vision models, an architectural innovation that reduced FLOPs by 8--9$\times$ for $3{\times}3$ kernels with minimal accuracy loss.

The system implications in @sec-network-architectures-system-implications-6b63 assume standard CNN architectures with full convolutions. Standard convolutions scale as $\mathcal{O}(N_{\text{pix}} \times K^2 \times C_{\text{in}} \times C_{\text{out}})$, a compute volume that exceeds the strict energy budgets of always-on edge devices. To bridge this gap, efficient architectures like **depthwise separable CNNs (DS-CNN)**\index{Depthwise separable convolution}\index{Convolution!depthwise separable} decompose the standard convolution into two distinct operations. This factorization, introduced by Sifre in the context of feature extraction [@sifre2014rigid] and popularized by MobileNet [@howard2017mobilenets], decouples spatial filtering from cross-channel combination. The depthwise convolution\index{Convolution!depthwise} applies filters to each input channel independently ($K \times K \times C_{\text{in}}$ parameters), while the pointwise convolution\index{Convolution!pointwise} uses a $1{\times}1$ convolution to project channels to the output dimension ($1 \times 1 \times C_{\text{in}} \times C_{\text{out}}$ parameters). This decomposition reduces parameter count and FLOPs to a fraction of roughly $\frac{1}{C_{\text{out}}} + \frac{1}{K^2}$ of standard convolution (yielding a reduction factor of roughly $K^2 \times$, or ~8–9$\times$ for $3 \times 3$ filters with large $C_{\text{out}}$), making real-time execution feasible on resource-constrained microcontrollers. In keyword spotting, a continuous 1D audio stream is preprocessed via Short-Time Fourier Transform into a 2D time-frequency spectrogram (or Mel-frequency cepstral coefficients), allowing 2D convolutional kernels to slide across time and frequency bins to detect acoustic phoneme signatures.

The keyword spotting workload exemplifies this edge efficiency regime.

::: {#lhs-nn-architectures-kws-tinyml-lighthouse .callout-lighthouse title="KWS (TinyML lighthouse)"}

**Why it matters**: Keyword spotting models (like DS-CNN) represent the power-constrained end of the spectrum. Used in always-on applications like smart doorbells that wake a larger vision pipeline only after an audio trigger, these models must run on microcontrollers with milliwatt power budgets.

At `{python} LighthouseSpecs.kws_params_k_str` parameters, a DS-CNN keyword spotter's `{python} LighthouseSpecs.kws_fp32_kb_str` of FP32 weights already exceeds the few hundred kilobytes of memory a typical microcontroller can devote to a model, so the model fits only after 8-bit quantization cuts it fourfold. KWS is therefore the lighthouse for extreme quantization (INT8/INT4) and specialized architectural primitives (Depthwise Separable Convolutions) that trade theoretical representational power for maximum efficiency per watt.

:::

From ResNet-50's compute-heavy standard convolutions through MobileNet's depthwise separable variants to KWS's micro-power deployment, CNNs demonstrate how architectural constraints transform data structure into hardware efficiency. Local connectivity and weight sharing reduce parameter storage and expose reuse. The KWS example also shows that convolution can process temporal patterns. Its context is bounded by the network's receptive field, however. A streaming system that must carry information across variable time spans within a fixed state budget motivates a different trade-off: updating a compact recurrent state as each observation arrives.
