### System implications {#sec-network-architectures-system-implications-18c3}

Recurrent architectures impose a hard physical constraint: sequential dependency. The update $\mathbf{h}_t = \tanh(\mathbf{W}_{\text{hh}}\mathbf{h}_{t-1} + \mathbf{W}_{\text{hx}}\mathbf{x}_t)$ establishes a strict ordering: the recurrent transformation at time step $t$ needs the state produced by step $t-1$. An input sequence of length $S = 1{,}000$ therefore requires $1{,}000$ ordered state updates, even when a fused kernel executes several or all updates within one launch. Hardware can parallelize across batch instances and within each matrix operation; input projections can also be computed across time when the inputs are available. Faster arithmetic or memory shortens individual steps, while the recurrent dependency chain remains.

During inference, recurrent networks achieve exceptional memory efficiency. Because the recurrent state compresses history into a fixed-size vector $\mathbf{h}_t$, inference state memory scales as $\mathcal{O}(d)$ (for example, 2 KB for a 512-dimensional FP32 state), remaining completely flat whether sequence length $S$ is 10 or 10,000 tokens. This constant memory footprint contrasts sharply with attention mechanisms (@sec-network-architectures-attention-mechanisms-dynamic-pattern-processing-22df), whose stored context grows with every token because autoregressive generation maintains an $\mathcal{O}(S \cdot d)$ key-value cache. For streaming deployments on memory-constrained edge hardware, such as microcontrollers, an RNN's $\mathcal{O}(1)$ runtime state eliminates the memory-capacity exhaustion that limits transformers.

Recurrent execution exhibits distinct memory-hierarchy behaviors: high temporal locality for parameters, but poor operational intensity under standard framework dispatch. Weight matrices $\mathbf{W}_{\text{hh}}$ and $\mathbf{W}_{\text{hx}}$ are reused at every time step, residing comfortably in SRAM or L2 cache if the model fits on-chip. However, naively launching separate kernels for input projection, recurrent projection, bias addition, and activation at each time step incurs severe kernel-launch overhead and forces intermediate tensors back and forth across HBM. To mitigate this memory-bandwidth bottleneck, production recurrent runtimes fuse the projections, bias addition, and activation into a single monolithic kernel that maintains $\mathbf{h}_t$ within GPU registers and shared memory throughout the sequence execution.

::: {.column-margin .margin-pointer}
↪ Kernel fusion, which keeps intermediate tensors on-chip instead of round-tripping them through device memory, is developed in @sec-hardware-acceleration-kernel-fusion-7faf.
:::

This architectural tension between fixed-capacity state and serialized execution defined sequence processing before transformers. While recurrent networks maintain constant memory overhead regardless of sequence length, the sequential dependency\index{RNN!sequential dependency bottleneck} prevents hardware from parallelizing across time steps, the fixed-capacity state becomes an information bottleneck in which early inputs fade over long spans, and gradients through long chains of recurrent steps vanish or explode (the vanishing gradient problem\index{Vanishing gradient problem}). Overcoming both constraints required an architecture capable of establishing direct, content-addressable links across arbitrary sequence positions without intervening recurrent steps: the attention mechanism (@sec-network-architectures-attention-mechanisms-dynamic-pattern-processing-22df).
