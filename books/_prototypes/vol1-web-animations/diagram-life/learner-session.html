  1. Approximation: With the default activation scale 0.10 and zero-point 3, 0.31 maps to the representable level 0.30 and stored code 6. The code labels a level; it is not the original real magnitude. Rounding to a finite set of levels can lose information.
  2. Identity and retention: The second source pair is activation −0.52 and weight −0.18, with codes −2 and −4. Removing zero-points gives −5 and −4; their product 20 joins the existing 24 to produce 44. Source operands remain available; the running total is updated.
  3. Width and output: Products and sums can require a greater integer range than each INT8 operand. A wider accumulator reduces overflow risk within its supported range and avoids repeated output rounding after every addition. Convert after this reduction completes. The example ends with INT32 sum 84, output code 17, represented real value 0.42, and float reference 0.4086. The small sum 84 itself does not demonstrate a need for INT32; larger reductions motivate it.
