MLSysBook living figures — design proposal, October 16, 2026

Evidence and limits
Inspected the four canonical chapter configurations, the Volume I opportunity
map and ETL prototype, and the relevant Volume I fusion, checkpointing, and
quantization passages. The chapter map below is a candidate program, not a
completed passage-by-passage review of Volumes II–IV. Confirm placement and
prerequisites against each owning section before implementation.

Teaching contract
One figure answers one causal question. Establish the objects and terms locally;
show the mechanism in four to six stages; synchronize each state with persistent
explanatory text; end with an inspectable result and its cost. Preserve object
identity. Never replace explanation with decorative movement. No infinite loops,
scroll hijacking, or automatically vanishing text. Start paused. Offer play,
pause, back, next, restart, and expand; honor reduced motion and pause offscreen.
The expanded figure must include definitions and assumptions from its inline
version. Animate objects first; reveal captions at stage boundaries without
letter-by-letter effects. Captions remain readable while the diagram moves.

Implementation proposal
Use semantic HTML/CSS and SVG for diagrams, with JavaScript state machines and
the browser Web Animations API for transitions. The current prototype uses HTML
boxes. Native controls suit these modest sequences; a timeline library should
be introduced only if a real choreography requirement warrants the dependency.
State is the source of truth: both diagram and explanation derive from it.
Separate authored lesson data from renderer and playback controller. Stable
figure IDs preserve references and analytics. No external CDN or runtime AI.

Quarto integration
1. Put production CSS/JS under books/shared/assets; load the player once via
   the HTML theme config. Use scoped class names, inherited font/accent variables,
   and semantic resource colors. Test light/dark themes rather than hardcoding
   the prototype's white background.
2. Give each lesson a reusable include or shortcode with a stable figure ID,
   caption, full text transcript, static image, lesson data, and source section.
3. Use Quarto content-visible when-format="html" for the interactive form and
   content-hidden when-format="html" for the existing print equivalent. Preserve
   one logical figure reference and check numbering in both output formats.
4. Keep the figure inline in the argument. Expand the same component into a
   dialog only when requested; provide Escape, a focus trap, and focus restoration.
   The prototype has an expanded overlay, not a finished accessible dialog.
5. Pass HTML resources explicitly through the volume build's resources list.
   Lazy-initialize offscreen players; do not rely on _prototypes being published.
6. Bind real specs and derived physical values to MLSysIM-generated lesson data.
   Explicit toy inputs can teach arithmetic but must never resemble benchmarks.
7. Check keyboard/screen-reader behavior, reduced motion, narrow screens, dark
   theme, print fallback, figure numbering, playback pause, and numeric invariants.

Volume I — one candidate per chapter, canonical order
01 Introduction: shorten compute in the iron-law budget; reveal the remaining
   data and overhead terms. Distinguish sequential accounting from overlap.
02 System paradigms: trace request and reply across distant and local endpoints;
   separate propagation, transfer, service time, and a deadline.
03 ML lifecycle: propagate an edge memory constraint through model, data,
   validation, and deployment artifacts; only dependent decisions change.
04 Data engineering: compare the same event through ETL and ELT; later derive
   an omitted feature from retained raw input. Existing pilot available.
05 Neural computation: forward activations → loss → local backward rules →
   gradients → separate optimizer update. Never equate backward with updating.
06 Architectures: slide a shared convolution filter across a multi-channel input;
   accumulate channel contributions into one output cell.
07 Frameworks: follow intermediate values through separate and fused kernels;
   contrast HBM traffic while preserving the arithmetic. NEW PREVIEW.
08 Training: retain an activation boundary, release interior values, reconstruct
   them for backward, then release after their last consumer. NEW PREVIEW.
09 Data selection: select unlabeled examples, obtain labels, retrain, rescore;
   show the danger of selecting redundant uncertain examples.
10 Compression: map a real value to an integer grid, reconstruct, expose rounding
   error, then demonstrate clipping separately. NEW PREVIEW.
11 Acceleration: load operand tiles, reuse on chip, retain partial sums through
   the reduction, and write output only when complete.
12 Benchmarking: put component and end-to-end stopwatches around the same request;
   preserve queueing and preprocessing outside model-only timing.
13 Serving: finish one sequence, free its slot, prefill a new request, resume
   decoding. Admission consumes resources; never show free immediate insertion.
14 ML operations: compare shadow, canary, and blue-green routing using persistent
   request identities; shadow responses never reach users.
15 Responsible engineering: reveal how approval decisions select observed labels;
   contrast an independent audit sample without inventing rejected outcomes.
16 Conclusion: reuse earlier mechanisms as a D·A·M synthesis; no new animation.

Volume II — candidate mechanisms, canonical order
01 Introduction: follow one step from local compute to fleet communication.
02 Compute infrastructure: show allocation constrained by topology and capacity.
03 Network fabrics: follow contending flows through an oversubscribed link.
04 Data storage: trace sharded reads and identify a straggling shard.
05 Collective communication: animate ring reduce-scatter followed by all-gather;
   retain chunk identity and verify the final sum at every participant.
06 Distributed training: compare data, tensor, and pipeline partition boundaries;
   keep separate modes rather than animating all simultaneously.
07 Fault tolerance: fail a worker, restore a durable checkpoint, replay lost work.
08 Fleet orchestration: place jobs with topology and fragmentation constraints.
09 Performance engineering: trace a critical path and the exposed bottleneck
   after one optimization; avoid summing overlapped durations.
10 Inference: follow prefill/decode and changing batch membership.
11 Edge intelligence: partition execution across an intermittent boundary.
12 Operations at scale: propagate a failed dependency through a service graph.
13 Security and privacy: show clipping, noise, and aggregation with explicit
   privacy assumptions; noise alone is not a privacy guarantee.
14 Robust AI: change the input distribution and compare a held-out evaluation.
15 Sustainable AI: shift execution in time; distinguish energy from emissions.
16 Responsible AI: trace evidence through staged approval and deployment gates.
17 Conclusion: replay the fleet constraint and the resulting architecture.

Volume III — candidate mechanisms, canonical order
01 Introduction: trace one trajectory and its model, state, and tool boundaries.
02 Foundation model: reveal token-by-token conditional generation.
03 Test-time compute: branch, evaluate, and prune a search tree under a budget.
04 Context engineering: assemble a bounded context and reveal what was omitted.
05 KV cache: append keys/values during decoding; show retained versus recomputed
   work and capacity growth without implying constant-time attention.
06 Long-term memory: write, retrieve, and reconcile a stale memory record.
07 Tool calling: trace proposal → validation → dispatch → result, separating text
   generation from the side effect the tool actually performs.
08 Sandboxes: follow an attempted action to an enforced isolation boundary.
09 Security: carry untrusted text across a trust boundary and show policy checks.
10 Agent harness: step the execution loop with explicit state and stop conditions.
11 Durable execution: crash between a side effect and acknowledgement; distinguish
   retry from idempotent completion and expose duplicate-action risk.
12 Failure recovery: compare retry, compensation, and escalation for one failure.
13 Evaluation: align a trajectory trace with assertions and failure evidence.
14 Agent operations: trace a production failure backward through versioned state.
15 Trajectory curation: select complete traces without leaking evaluation data.
16 Fine-tuning: show which trajectory tokens contribute to the training loss.
17 RLVR: generate candidate solutions, verify outcomes, update from rewards;
   distinguish verifier acceptance from universal correctness.
18 Multi-agent: trace delegated tasks through shared-state contention; show how
   adding agents can increase coordination rather than useful work.
19 Agent economics: accumulate model calls, retries, tool charges, and failed
   trajectories; compare cost per attempt with cost per successful task.
20 Conclusion: reuse earlier trajectory mechanisms to synthesize the constraints.

Volume IV — candidate mechanisms, canonical order
01 Boundary: cross from a proposed command into an irreversible physical action.
02 Body: relate torque, compliance, and response for a declared mechanical model.
03 Brain: trace observation → inference → command under a deadline.
04 Nervous system: trace timestamped messages with jitter and stale feedback.
05 Data: align sensor, embodiment, and action records in a demonstration.
06 Training: roll out compounding error and demonstrate a feedback correction.
07 Evaluation: compare proxy success with a physical task failure mode.
08 Perception: let an observation age while the world continues moving.
09 Memory: update a scene representation after an object moves or is occluded.
10 Intent: expire an intent lease; stop using stale authorization.
11 Planning: commit an action chunk, reveal its open-loop horizon, then replan.
12 Enforcement: show nominal and constrained commands at a safety boundary;
   declare the model and assumptions rather than promising universal safety.
13 Placement: move computation across the robot/network boundary and account
   for transfer delay and missing connectivity.
14 Intervention: advance the world during detection, handoff, and human response.
15 Verification: grow a reachable set under uncertainty and show a failed bound.
16 Release: advance a candidate through evidence gates and a rollback boundary.
17 Responsibility: trace a physical incident through evidence and authority.

Recommended sequence
Polish one fusion lesson into the production component, validate it inside an
actual HTML chapter, then port ETL, checkpointing, and quantization. Next select
convolution, tiling, and continuous batching. Do not impose an animation quota:
some conceptual chapters benefit more from an annotated static figure.
