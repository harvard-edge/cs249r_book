First design brief: prefill → decode → cache lifetime

A proposed animation family, not another standalone dashboard. Start with the existing Volume I prefill/decode figure; use later-volume figures for scheduling, paging, and shared-prefix ownership.

Prefill · establish the stateShow a prompt entering a declared model layer. Compute prompt keys and values and write them into a cache. The final prompt position supplies logits for sampling the first output token. Distinguish token positions from physical storage.
Decode · reveal reuseFeed the previously sampled token into the next pass. Read retained keys and values, append that input token’s keys and values, then sample the next output. Keep earlier entries visible. The cache does not eliminate every model operation.
Lifetime · expose the systems costTrack growing cache occupancy per request. Release a finished request’s ownership; retain shared blocks until their last owner releases them. Keep bytes, traffic, and elapsed time distinct.

Inline: a few paused causal actions. Optional expanded lab: prompt length, generated length, and declared cache representation. Paging and prefix sharing belong in the chapters that introduce them. Every byte counter must use the chapter’s assumptions; motion speed must not imply measured latency.
