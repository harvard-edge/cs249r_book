calc_activation_memory

physics.memory.calc_activation_memory(
    n_layers,
    seq_len,
    batch_size,
    hidden_dim,
    n_heads=None,
    precision_bytes=2,
    strategy='selective',
)

Estimates the activation memory required for a Transformer model during training.

Implements the per-layer analytical bounds of Korthikanti et al. (2023), “Reducing Activation Recomputation in Large Transformer Models”, Sec. 4.1, whose constants are expressed in BYTES with FP16 (2-byte) activations baked in:

  • none (no recomputation): s*b*h*34 + 5*a*s^2*b
  • selective (recompute attention matrices): s*b*h*34
  • full (recompute everything; keep layer inputs): s*b*h*2

where s = sequence length, b = microbatch size, h = hidden dimension, and a = attention heads. The quadratic 5*a*s^2*b term is the attention softmax/dropout/score storage — dominant at long sequence lengths — and is exactly what selective recomputation discards. Activations stored at other precisions scale the FP16-based constants by precision_bytes / 2.

(Audit fix 2026-06-06: the previous implementation used 34/10/2 as precision-free coefficients AND multiplied by precision_bytes, double- counting the FP16 width at every strategy; its selective=10 matched no published convention; and the attention term was missing entirely.)

Parameters

Name Type Description Default
n_layers int Number of transformer layers per device (after pipeline parallelism). required
seq_len int Sequence length. required
batch_size int Microbatch size per device. required
hidden_dim int Hidden dimension of the model. required
n_heads int Number of attention heads. REQUIRED for strategy='none' (the quadratic attention term needs it); unused otherwise. None
precision_bytes float Bytes per activation element (default 2, i.e. FP16 — the paper’s convention). 2
strategy str Recomputation strategy: ‘none’, ‘selective’ (default), or ‘full’. 'selective'

Returns

Name Type Description
Quantity The total estimated activation memory in bytes.

calc_capped_exponential_scale

physics.memory.calc_capped_exponential_scale(mean_tokens, max_tokens)

Solves for the exponential scale whose context-capped mean is mean_tokens.

Request lengths are modeled as S = min(X, S_max) with X ~ Exponential(mu): short requests are common, long ones are rare, and a request that would run past the context window is cut off at S_max. The capped mean is E[S] = mu * (1 - exp(-S_max / mu)), which rises monotonically from 0 toward S_max as mu grows, so exactly one scale matches any 0 < mean_tokens < S_max. At mean_tokens == S_max every request fills the window (the fixed-length limit) and the scale is infinite.

The exponential shape is a modeling assumption, chosen because it is the maximum-entropy distribution for a positive length with a known mean. It is not fitted to a serving trace.

Parameters

Name Type Description Default
mean_tokens float Mean tokens per request after the cap, 0 < mean_tokens <= max_tokens. required
max_tokens float Context-window cap S_max in tokens (> 0). required

Returns

Name Type Description
float Exponential scale mu in tokens (math.inf in the fixed-length limit).

calc_checkpoint_memory_units

physics.memory.calc_checkpoint_memory_units(n_layers, checkpoints)

Activation memory of evenly spaced checkpointing, in units of one layer’s activations.

With k checkpoints over L equal layers, the forward pass keeps the k checkpoint activations and the backward pass rebuilds one segment of L/k layers at a time: k + L/k, smallest near k = sqrt(L) (Chen et al. 2016). (Added 2026-10-20.)

calc_csr_bytes

physics.memory.calc_csr_bytes(nonzeros, rows, value_bytes, index_bytes)

Bytes of a matrix in compressed sparse row (CSR) form.

B_CSR = nnz (b_value + b_index) + (rows + 1) b_index

Values and column indices are one each per nonzero; row pointers are one per row boundary, rows + 1 in all.

calc_decoder_matmul_weights

physics.memory.calc_decoder_matmul_weights(
    layers,
    hidden_dim,
    vocab_size,
    mlp_ratio=4,
)

Weights in the matrix multiplies of a GPT-style decoder, by kind.

Each block has four weight matrices: the fused query-key-value projection (d x 3d), the attention output projection (d x d), and the two MLP matrices (d x r d and r d x d). The output layer projects d to the vocabulary (d x V). Biases, layer norms, and position embeddings are not matrix multiplies and are left out.

Returns

Name Type Description
dict block (weights in all blocks), block_matrices (count of block weight matrices), and output (output-layer weights).

calc_expected_paged_kv_tokens

physics.memory.calc_expected_paged_kv_tokens(
    mean_request_tokens,
    max_seq_len,
    page_size_tokens=16,
)

Expected KV tokens a paged allocator holds per request, and the waste inside.

PagedAttention (Kwon et al., 2023, Sec. 4.2) hands a request fixed-size blocks on demand, so a request of S tokens holds ceil(S / p) blocks and wastes at most the unused tail of its last block. With request lengths S = min(X, S_max) and X exponential (calc_capped_exponential_scale), the expected block count has a closed form from summing tail probabilities:

E[ceil(S/p)] = sum_{j=0}^{K-1} P(S > j p) = (1 - r^K) / (1 - r)
r = exp(-p / mu),  K = ceil(S_max / p)

The expected allocation is p * E[ceil(S/p)] and the expected internal fragmentation is 1 - mean / allocation. When mu >> p the tail averages about p / 2 tokens, so larger pages waste proportionally more even when S_max divides evenly by p. In the fixed-length limit (mean_request_tokens == max_seq_len) the allocation is ceil(S_max / p) * p, matching calc_paged_kv_cache_size.

Parameters

Name Type Description Default
mean_request_tokens float Mean tokens a request fills, 0 < mean_request_tokens <= max_seq_len. required
max_seq_len int Longest context a request may reach, in tokens. required
page_size_tokens int Tokens per block (defaults to 16, the vLLM default). 16

Returns

Name Type Description
tuple A 2-tuple containing: - allocated_tokens (float): Expected KV tokens allocated per request. - internal_frag (float): Expected unused fraction of that allocation (0.0 to 1.0).

calc_kv_attention_design

physics.memory.calc_kv_attention_design(heads, kv_heads=None, kv_lora_rank=None)

The attention design a model’s KV geometry implies: “MLA”, “GQA”, or “MHA”.

Multi-head latent attention (MLA) caches one compressed latent per token per layer (kv_lora_rank set). Grouped-query attention (GQA) stores fewer key-value heads than query heads. Multi-head attention (MHA) stores one key-value head per query head.

calc_kv_resident_fit

physics.memory.calc_kv_resident_fit(pool, bytes_per_sequence)

Whole sequences of bytes_per_sequence that fit in pool.

B = floor(M_pool / (S * m_token))

Both arguments are byte quantities. The count is a memory-only bound: it ignores block rounding, headroom, and promised output growth unless the caller has folded them into bytes_per_sequence.

calc_low_rank_update_params

physics.memory.calc_low_rank_update_params(in_dim, out_dim, rank)

Trainable parameters of a rank-rank update to an out_dim by in_dim weight.

P_LoRA = r (d_in + d_out)

The update is the product of a down-projection (r by d_in) and an up-projection (d_out by r); the frozen weight itself holds d_in d_out.

calc_mla_cache_size

physics.memory.calc_mla_cache_size(
    n_layers,
    kv_lora_rank,
    qk_rope_head_dim,
    seq_len,
    batch_size,
    bytes_per_elem=2,
)

Calculates the cache size for Multi-Head Latent Attention (MLA).

MLA compresses keys and values into a single low-rank latent vector per token per layer, and carries a decoupled rotary position key alongside it. Only those two are resident, so the cache is:

n_layers * (kv_lora_rank + qk_rope_head_dim) * S * B * precision

There is no leading factor of two: unlike standard attention, MLA does not keep a separate K and V tensor per key-value head. That absence is the whole point of the scheme, and it is why an MLA model’s resident cache is an order of magnitude smaller than a grouped-query model of comparable depth.

Source: DeepSeek-AI, “DeepSeek-V2/V3 Technical Report” (Multi-Head Latent Attention), where the compressed latent has dimension kv_lora_rank and the decoupled rotary key has dimension qk_rope_head_dim.

Parameters

Name Type Description Default
n_layers int Number of transformer layers. required
kv_lora_rank int Dimension of the compressed key-value latent held per token per layer. required
qk_rope_head_dim int Dimension of the decoupled rotary position key held alongside it. required
seq_len int Total sequence length (context + generated tokens). required
batch_size int Number of parallel requests. required
bytes_per_elem Quantity or int Numerical precision of the cache (defaults to 2 for FP16/BF16). 2

Returns

Name Type Description
Quantity Total latent cache size in bytes.

calc_paged_kv_cache_size

physics.memory.calc_paged_kv_cache_size(
    n_layers,
    n_heads,
    head_dim,
    seq_len,
    batch_size,
    page_size_tokens=16,
    bytes_per_elem=2,
)

Calculates KV cache size accounting for PagedAttention fragmentation.

PagedAttention (Kwon et al., 2023) allocates KV cache in fixed-size blocks (pages). This eliminates external fragmentation but introduces internal fragmentation in the final allocated page.

This sizes one known sequence length. When seq_len is a multiple of the page size the waste is zero for every page size, so a single length cannot show the page-size trade-off. calc_expected_paged_kv_tokens averages the last-page tail over a distribution of request lengths, which is what makes page size matter for capacity planning.

Parameters

Name Type Description Default
n_layers int Number of transformer layers. required
n_heads int Number of Key/Value attention heads. required
head_dim int Dimension of a single attention head. required
seq_len int Current sequence length. required
batch_size int Number of parallel requests. required
page_size_tokens int Number of tokens per allocated page block (defaults to 16). 16
bytes_per_elem Quantity or int Numerical precision (defaults to 2). 2

Returns

Name Type Description
tuple A 2-tuple containing: - size (Quantity): Total allocated KV cache size in bytes. - frag_pct (float): Internal memory fragmentation (0.0 to 1.0).

Parameters of one residual bottleneck adapter, weights and biases.

calc_shared_prefix_fit

physics.memory.calc_shared_prefix_fit(
    pool_blocks,
    shared_blocks,
    private_blocks,
)

Requests that fit when shared_blocks are stored once for all of them.

B_shared = floor((N_blocks - N_common) / N_private)

Each request adds only its private_blocks; the common prefix is counted once, as unique physical blocks.

calc_sharing_gain_limit

physics.memory.calc_sharing_gain_limit(shared_fraction)

Large-pool limit of the resident-fit gain from sharing: 1 / (1 - f).

f is the shared fraction of each request’s blocks. As the pool grows, the one stored copy of the prefix becomes negligible and every request costs only its private share.

calc_sparse_breakeven_zero_share

physics.memory.calc_sparse_breakeven_zero_share(
    dense_bytes_per_value,
    bytes_per_nonzero,
)

Share of zeros above which a sparse format stores fewer bytes than dense.

z* = 1 - b_dense / b_nz

A dense tensor pays b_dense per entry, zero or not; a sparse one pays b_nz per survivor, so it wins only when fewer than b_dense / b_nz survive. Per-row overheads (CSR row pointers) are excluded.

calc_sparse_bytes_per_nonzero

physics.memory.calc_sparse_bytes_per_nonzero(
    value_bytes,
    index_bytes,
    indices=1,
)

Bytes one stored nonzero costs in an index-based sparse format.

b_nz = b_value + k b_index

CSR keeps one column index per value (k = 1; its row pointers are one per row, not per value); COO keeps a row and a column index (k = 2).

calc_update_step_traffic

physics.memory.calc_update_step_traffic(
    weights,
    gradients,
    optimizer_state,
    activations,
)

DRAM traffic of one full-update training step, one crossing per tensor use.

With no cache reuse, the forward pass reads the weights and writes the saved activations; the backward pass reads the activations and the weights and writes the gradients; an Adam-style optimizer reads the weights, the gradients, and its state, then writes the weights and its state back:

V_step = (W + A) + (A + W + G) + (W + G + S) + (W + S)

Returns (step_traffic, weight_reads): the total bytes moved and the bytes of the three weight reads (forward, backward, optimizer).
