\begin{frame}{The serial part caps speedup; overhead grows per worker}
  \begin{columns}[c]
    \begin{column}{0.26\textwidth}
      \centering\safeimg[width=\textwidth,height=4.0cm,keepaspectratio]{amdahl.jpg}\\[0.04cm]
      {\footnotesize Gene Amdahl, 2008}
    \end{column}
    \begin{column}{0.71\textwidth}
      \centering
      {\large $\text{Speedup}(N)=\dfrac{1}{(1-p)+\dfrac{p}{N}+c(N)}$}\\[0.35cm]
      \small\raggedright
      $p$: the fraction of the work that divides among $N$ workers\\[0.08cm]
      $c(N)$: \textbf{coordination tax}, the time spent on handoffs, as a fraction of the serial time\\[0.08cm]
      With $c=0$: \textbf{Amdahl's law}, capped at $1/(1-p)$\\[0.12cm]
      \uncover<2->{\textcolor{mlsysaccent}{\textbf{Any gain needs $c(N) < p\,(1-1/N)$.}}}
    \end{column}
  \end{columns}
  \mlsyscredit{Photo: Perry Kivolowitz, CC BY 3.0, Wikimedia Commons. Multi-Agent Coordination, equation 1 and Definition 18.1; Amdahl 1967.}
  \note{[2 min] [CORE] Gene Amdahl argued in 1967 that the serial housekeeping of a program limits what any number of processors can deliver; his paper has no equation, and later authors wrote the formula. For agents the housekeeping is planning, integration, and final assessment, which no added worker absorbs. The chapter adds the coordination tax $c(N)$: preparing and validating envelopes, delivering context, scheduling children, collecting receipts, and reconciling results, normalized by the serial time. Step 2: a split beats the serial reference only if the tax is smaller than the time the parallel part saves. ENGAGE: with $p = \val{scr_p1}$, what is the largest possible speedup with free coordination? (Expected: \val{scr_cap} times, at infinitely many workers.) WARN: the serial reference here is the partition run in sequence; the real baseline already overlaps tools, so a production decision benchmarks the capable controller instead. FLEX: [CORE].}
\end{frame}

      $\sigma$: work that serializes\\
      $\kappa$: pairwise reconciliation\\[0.15cm]

  \note{[2 min] [OPTIONAL] Neil Gunther's universal scalability law separates two costs with different fixes. \begin{frame}{Cancellation closes admission; admitted work must still settle}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=5.7cm,keepaspectratio]{cancel_step}{3}
  \mlsyscredit{Multi-Agent Coordination, \S18.7.1, \S18.8.2, and Tables 7 and 8.}
  \note{[2.5 min] [CORE] Subtree cancellation. Step 1: every grant is bound to the generation counter of each ancestor in its lineage, here generation 7 of the migration task. The interface worker's test job was admitted at the gateway before anything happened. Step 2: the supervisor cancels the task, which advances its generation to 8. The gateway checks every ancestor's generation at admission, so the caller's next tool call is rejected even if the worker has not yet heard about the cancel. One counter invalidates the whole subtree. Step 3: the test job admitted before the cancel keeps its operation identity, owner, reservation, and record until its outcome and charges settle; Lecture 10's settlement rule now spans a tree, and Lecture 12's cleanup graph orders the teardown under a separate administrative credential. The fallacy as true or false: release the parent's reservations as soon as cancellation is requested. False; in the chapter's cohort, failed and canceled work was \$\val{co_m_disc} of \$\val{co_m_spend} spent. WARN: a remote gateway that cannot reach the authoritative state must fail closed, or declare a bounded stale-policy window. FLEX: [CORE].}
\end{frame}

\begin{frame}{Each hop narrows authority; allowances are reserved}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=5.2cm,keepaspectratio]{atten_step}{2}\\[0.05cm]
  \small Child grant $\subseteq$ parent grant. Permissions can be shared; money and tokens are partitioned.
  \mlsyscredit{Multi-Agent Coordination, \S18.8.1 and Exercise 7 (allowances); Saltzer and Schroeder 1975; Birgisson et al. 2014.}
  \note{[2.5 min] [CORE] Attenuated delegation. Step 1: each hop passes authority no broader than the delegator's own: the root can read, edit callers, and publish; the caller worker can only edit callers; its inspection child can only read one file. This is Lecture 8's capability grants and attenuation, applied hop by hop, so authority travels in the reference a child holds. Chained-caveat tokens let a holder add restrictions without contacting the issuer. Budgets differ from permissions. Reading does not use up read access, but each dollar can be spent once, so allowances are partitioned: the inspection child's \$\val{al_nested} comes out of the caller's \$\val{al_equal}, never from a fresh pool. Step 2: the inspection child names the root as its parent. A runtime that resolved authority from that claimed name would hand it publication rights, Lecture 7's confused deputy built by the delegation tree. The runtime assigns the child's identity and grant; the model has no say. ENGAGE: a worker needs to publish, which its grant forbids. Where does the request go? (Expected: to the task owner, bound to the exact candidate hash under Lecture 9's action-bound approval, and rechecked against lineage at dispatch.) FLEX: [CORE].}
\end{frame}
