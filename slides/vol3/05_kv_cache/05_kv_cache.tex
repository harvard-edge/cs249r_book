\section{Footprint}

\begin{frame}{Every context token becomes keys and values at all 80 layers}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=6.1cm,keepaspectratio]{zones_step}{2}
  \mlsyscredit{KV Cache Management, \S5.2 and its context figure (zone sizes); 10.7 GB computed.}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  At the harness boundary, the r18 repair request splits its 32,768 tokens into Lecture 4's change-rate zones. Its invariant prefix accounts for 14,336 tokens, or 43.8\% of the request, combining 2,048 tokens of system prompt, 4,096 of tool schemas, and 8,192 of workspace state, followed by 16,384 tokens of turn history and 2,048 for the latest observation. Once the serving engine runs prefill, none of that semantic structure survives. Every token deposits one key vector and one value vector in each of the 80 transformer layers so later tokens can attend without recomputing those key and value vectors. At 327,680 bytes per token for Llama 3 70B, this single context claims 10.7 GB of HBM.

  \notecue{Watch for}{Peak footprint occurs at the end of decode because every generated output token appends its own keys and values. Because the KV cache is derived tensor state rather than compressed text, rebuilding it requires running the exact token sequence through identical weights.}

  \notecue{Next}{Derive 327,680 bytes per token directly from the model's real \texttt{config.json} file.}}

  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Every factor in that per-token cost comes straight from the model's \texttt{config.json}, here for Meta's Llama 3.1 70B, via Equation 1. First, head dimension equals the hidden vector width (\texttt{hidden\_size}) divided by the 64 query attention heads (\texttt{num\_attention\_heads}), giving $8{,}192 / 64 = 128$. Next, multiply 2 (keys and values) $\times$ 80 layers $\times$ 8 key-value heads $\times$ 128 head dimension $\times$ 2 bytes per \texttt{bfloat16} element. The product is 327,680 bytes, about a third of a megabyte, per token, so $32{,}768 \times 327{,}680\text{ B} = 10.7\text{ GB}$. Halving precision to 1-byte FP8 or INT8 storage halves the footprint, though task accuracy must be validated.

  \notecue{Watch for}{Count the 8 \texttt{num\_key\_value\_heads}, not the 64 query heads. Grouped-query attention shares each KV head across 8 query heads, shrinking the cache 8$\times$, whereas using 64 erroneously yields 2.6 MB/token. Llama 3 70B shares this exact geometry with an 8,192-token window, extended to 131,072 in Llama 3.1.}

\begin{frame}{Before paging, at most 38\% of KV memory held token state}
  \centering
  \safeimg[width=0.95\textwidth,height=5.1cm,keepaspectratio]{kwon_fig2.pdf}\\[0.05cm]
  {\small Chapter scenario: a request ending at 2,048 tokens under a 32,768 cap fills \textbf{6.25\%} of its slot.}
  \mlsyscredit{Measured: Kwon et al., ``PagedAttention,'' SOSP 2023, Figure 2 (OPT-13B serving, \S6.2 experiment), redrawn. Scenario: KV Cache Management, \S5.3.1.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Because a serving engine does not know a request's final length at admission, early allocators reserved one contiguous buffer per sequence. In the SOSP 2023 paper introducing PagedAttention, Kwon et al. profiled Orca, an earlier continuous-batching serving engine using contiguous KV buffers, on the OPT-13B language model under three policies, reserving the model's maximum length (Max), the next power of two (Pow2), or even the exact final length known in advance (Oracle). Actual token state occupied only 20.4\% under Max, 26.8\% under Pow2, and 38.2\% under Oracle, losing the rest to reserved future slots, internal slack, and unusable external gaps. By contrast, vLLM, the open-source serving engine recalled from Lecture 4, reached 96.3\% utilization with paged blocks. In Chapter 5's scenario, requests capped at 32,768 tokens that finish at 2,048 tokens fill 6.25\% of their slots while still capping admission at 48.

  \notecue{Watch for}{Even Oracle wastes 62\% because contiguous pre-allocation locks future decode slots and leaves external gaps between uneven spans. These 2023 OPT-13B measurements show the structural waste rather than universal percentages.}

  \notecue{Next}{Separate internal fragmentation from external contiguity gaps.}}
\end{frame}

\begin{frame}{Reservation strands slots inside; contiguity strands gaps outside}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=5.6cm,keepaspectratio]{frag_step}{2}
  \mlsyscredit{KV Cache Management, \S5.3.2 and table 2 (illustrative extents); Randell, CACM 1969.}
  \note{%
  \mlsysnotemeta{1.5 min}{Optional}%
  To see why even Oracle stranded most of the pool, separate the two storage losses Randell formalized in 1969 for multiprogrammed systems. First, internal fragmentation locks unused capacity inside an active allocation, stranding 30,720 slots when a 32,768-token reservation finishes at 2,048 tokens. Second, external fragmentation splits free memory into disconnected regions (extents). Three free 256-slot extents hold 768 slots in total, yet they reject a 512-slot request because a standard GPU attention kernel (the routine that computes attention) locates each token by stepping a fixed offset from one starting address, requiring one unbroken buffer. Knowing exact final lengths removes only internal over-allocation past the true end, while future-decode reservations and external gaps remain; on-demand fixed-size blocks remove those reservations and external gaps while shrinking internal waste to one partial tail block.

  \notecue{Teach}{In a 50-minute class, skip this diagram and note that the measured breakdown on Slide 12 already shows both fragmentation losses.}

  \notecue{Next}{Connect KV paging to its 1962 virtual-memory ancestor, the Manchester Atlas computer.}}
\end{frame}

\begin{frame}{Paging solved the same problem for programs in 1962}
  \centering
  \safeimg[width=0.78\textwidth,height=5.0cm,keepaspectratio]{atlas-manchester-1963.jpg}\\[0.1cm]
  {\small The Atlas one-level store mapped a program's contiguous addresses onto scattered page frames.}
  \mlsyscredit{Photo: University of Manchester Atlas, January 1963. Iain MacCallum, CC BY 3.0, Wikimedia Commons. Kilburn et al., IRE Trans. Electronic Computers, 1962.}
  \note{%
  \mlsysnotemeta{0.5 min}{Core}%
  Breaking the contiguity requirement was not a new problem. In 1962, when early programs outgrew physical core memory, the University of Manchester Atlas computer and its one-level store introduced paged virtual memory (Kilburn et al., 1962; photographed here in January 1963). A page table translated a program's contiguous logical addresses onto scattered fixed-size frames in physical core memory, freeing programmers from manual overlays and contiguous reservations. Sixty years later, PagedAttention applied that same indirection to KV caches.

  \notecue{Watch for}{Unlike Atlas, a KV block table is a software structure read by the GPU attention kernel, the routine that computes attention, and the hardware memory management unit (MMU) page table is not involved.}

  \notecue{Next}{Trace how a KV block table indexes tokens scattered across HBM.}}
\end{frame}

\begin{frame}{A block table maps token positions to blocks anywhere in HBM}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=6.0cm,keepaspectratio]{blocktable_step}{3}
  \mlsyscredit{KV Cache Management, \S5.4.1 (Explore: PagedAttention on mlsysbook.ai; 4-token blocks). After Kwon et al., SOSP 2023.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  To see that software indirection in action, consider 4-token blocks. A 10-token sequence splits into logical block 0 (tokens 0 to 3), logical block 1 (tokens 4 to 7), and logical block 2 (tokens 8 to 9, leaving two empty slots). The sequence's block table maps logical blocks 0, 1, and 2 onto non-contiguous physical blocks 3, 7, and 9 anywhere in HBM, letting a growing sequence claim any free block without copying or pre-reserving. To locate token 9, the attention kernel computes logical block $\lfloor 9/4 \rfloor = 2 \to$ physical block 9 at offset $9 \bmod 4 = 1$. Because any free block serves any request, external fragmentation vanishes. Worst-case internal tail waste stays under one block, at most 15 slots (4.92 MB) for 16-token blocks, or 20.64 MB (0.2\% of 32K) for 64-token blocks.

  \notecue{Watch for}{A mapped physical block provides capacity, yet only initialized slots contain valid keys and values.}

  \notecue{Next}{Predict how many shorter requests fit in the same 526 GB pool once allocation is paged.}}
\end{frame}

  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  When Lecture 3's breadth allocation forks four branches from a parent's 8,192-token prefix, giving each new branch its own contiguous copy writes 10.7 GB of redundant KV state beyond the parent's original. Paged forking copies only the block table. Candidates A and B point to physical blocks 3, 7, and 9, raising each block's reference count (the count of owners pointing to it) to 2 with zero tensor copies. When Candidate B next decodes token 10, writing into shared partial block 9 would corrupt A. That rule adapts copy-on-write from the TENEX time-sharing system on the PDP-10 (Bobrow et al., 1972), where processes shared an address space and copied only pages they changed.

\begin{frame}{A radix tree finds the longest retained prefix and evicts leaves}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=6.0cm,keepaspectratio]{radix_step}{3}
  \mlsyscredit{KV Cache Management, \S5.5.2 to \S5.5.3 (Explore: Radix Cache on mlsysbook.ai). Zheng et al., ``SGLang,'' 2024.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  To match prefixes across separate requests without one node per token, SGLang, the serving system from Lecture 4 (Zheng et al., 2024), stores a compressed run of tokens and its KV blocks on each edge of a radix tree, so index size scales with distinct prefixes rather than token length. An active repair path runs from the root through instructions, tools, history, and the latest test log, and a new turn walks from the root until the first differing token to locate the longest reusable prefix. Under memory pressure, the engine evicts the least recently used unlocked dormant leaves, such as a rejected branch or another task's final turn. Removing a leaf turns a childless parent into a newly evictable leaf, preserving causal ancestors because a suffix is unusable without every prior token.

  \notecue{Watch for}{Pure recency eviction can drop a widely shared system prompt during brief idle lulls even though it saves the most aggregate prefill work.}

\begin{frame}[fragile]{SGLang's evictor pops the oldest unlocked leaf, then its parent}
  \begin{columns}[T]
    \begin{column}{0.76\textwidth}
      \begin{semiverbatim}\fontsize{8.4}{8.6}\selectfont
def evict(self, num_tokens: int,
          evict_callback: Callable):
    leaves = self._collect_leaves()
\hl{    heapq.heapify(leaves)}
    num_evicted = 0
    while num_evicted < num_tokens and len(leaves):
        x = heapq.heappop(leaves)
        if x == self.root_node:
            break
\hl{        if x.lock_ref > 0:}
            continue
        evict_callback(x.value)
        num_evicted += len(x.value)
        self._delete_leaf(x)
\hl{        if len(x.parent.children) == 0:}
\hl{            heapq.heappush(leaves, x.parent)}
      \end{semiverbatim}
    \end{column}
    \begin{column}{0.22\textwidth}
      \small\raggedright
      Oldest access first.\\[0.3cm]
      Locked: a running request uses it.\\[0.3cm]
      Childless parent becomes a leaf.
    \end{column}
  \end{columns}

  \note{%
  \mlsysnotemeta{1.5 min}{Optional}%
  SGLang v0.4.0 (\texttt{radix\_cache.py}) implements that leaf-first cascade in twenty lines of Python. For each unlocked leaf, \texttt{evict\_callback} frees its KV blocks, deletes the leaf, and pushes its parent onto the heap once the parent loses its last child.         \textbf{Dormant constraints}: a rule from turn 1 used in turn 30\\[0.05cm]
        \textbf{Exact identifiers}: a commit hash quoted once\\[0.05cm]

    \end{column}
  \end{columns}

  \note{%
  \mlsysnotemeta{2 min}{Core}%
  Keep, move, and drop cost bandwidth or prefill yet leave the next turn's computation lossless. Lossy schemes instead shrink memory in place by dropping low-attention tokens or keeping only a sliding window of recent tokens. In StreamingLLM (ICLR 2024), Xiao et al. showed why naive windows collapse on the PG19 text benchmark. Sliding windows drove perplexity (next-token prediction uncertainty; lower is better) to 5,158 on Llama-2-13B (using a 1,024-token window) and 3,360 on Llama-2-7B (using a wider window). Retaining the first 4 attention-sink tokens recalled from Lecture 4, where softmax parks leftover weight, restored perplexity to 5.40 and 9.59. Even with sinks preserved, three agent dependencies resist past-attention pruning, namely dormant turn-1 constraints needed at turn 30, once-quoted commit hashes, and tool-schema syntax. Section 4 thus separates lossless pause policies from lossy approximations.

  \notecue{Watch for}{Average perplexity hides single-token failures that break a task. Validate any lossy KV policy strictly on end-to-end task acceptance.}

\begin{frame}{Little's law turns occupied slots into a turn rate}
  \centering
  {\Large $L = \lambda\,W$}\\[0.15cm]
  {\small $L$: slots held on average \quad $\lambda$: turns per second \quad $W$: time each turn holds its slot}\\[0.3cm]
  \safeimg[width=0.92\textwidth,height=3.0cm,keepaspectratio]{residency.pdf}\\[0.1cm]
  \uncover<2->{\small Residency tax of a kept wait $= 1 + T_{\text{tool}}/T_{\text{model}} = 1 + 45/5 = \mathbf{\textcolor{mlsysaccent}{10}}$}
  \mlsyscredit{Little, Operations Research, 1961. KV Cache Management, theorem 5.1 and \S5.8.2.}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  Converting resident slots into a turn rate requires dividing by how long each turn holds its slot. Little's law (1961), $L = \lambda W$, holds for any stable queueing system where items arrive, hold a slot, and leave, regardless of arrival distribution. Average occupied slots $L$ equal turn rate $\lambda$ times mean slot residence time $W$, giving $\lambda = L / W$. For one repair turn, keeping KV state across the 45 s test sets $W = 5 + 45 = 50\text{ s}$, whereas releasing state during the wait sets $W = 5\text{ s}$. Keeping paused state therefore imposes a residency tax of $1 + T_{\text{tool}}/T_{\text{model}} = 1 + 45/5 = 10$, and a 90 s test would impose a 19$\times$ tax.

  \notecue{Watch for}{Omitting idle tool waits from $W$ overstates memory-bounded throughput by $1 + T_{\text{tool}}/T_{\text{model}}$. Because Little's law governs averages, burst sizing requires separate headroom. Later lectures on sandboxes, harnesses, and economics reuse this relation.}

  \notecue{Next}{Combine Little's law with workspace prefix sharing to compute full node turn rates.}}
\end{frame}
