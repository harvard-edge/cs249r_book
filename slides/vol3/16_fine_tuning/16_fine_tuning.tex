\begin{frame}{Weights hold procedure; context holds contracts; runtime enforces}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=5.7cm,keepaspectratio]{homes_step}{3}
  \mlsyscredit{Trajectory Fine-Tuning, \S16.2.1 and table 1.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Seeing prompts, schemas, and replies packed into one serialized string raises a boundary before any token receives loss. Every response combines static weights with dynamic context, whereas fine-tuning updates only weights. Weights therefore hold stable procedure that persists across tasks, such as inspecting diagnostics before editing or checking schemas after refusals. Context holds changing contracts, including tool schemas, permissions, observations, and a weekly refund policy that changes faster than a train-evaluate-release cycle. Enforcement stays in the runtime through validation, authorization, sandboxes, and timeouts. That split matches Lecture 2's proposal boundary and Lecture 15's intervention ladder, because token probabilities cannot enforce invariants.

    \notecue{Watch for}{The slogan ``Fine-tuning moves the prompt into the weights'' holds only for stable procedural instructions, never for volatile contracts or safety rules.}

    \notecue{Next}{Because dynamic context changes across turns, Slide 8 measures the storage expansion required when runtime compaction forces per-call serialization.}
  }
\end{frame}

\begin{frame}{The loss mask trains one author and conditions on the other}
  \centering
  \mlsyssteps[width=0.96\textwidth,height=5.7cm,keepaspectratio]{mask_step}{3}
  \mlsyscredit{Trajectory Fine-Tuning, figure 1 and Definition 16.1, redrawn at slide size (simplified: the schema query e3 and its reply are omitted).}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Once each trajectory prefix is serialized, the loss mask decides which tokens drive weight updates. Loss masking (Definition 16.1, equation 1) averages $-\log \pi_\theta(x_t \mid x_{<t})$, where $\pi_\theta(x_t \mid x_{<t})$ is the policy's probability of token $x_t$ given prior tokens $x_{<t}$, strictly over positions with binary mask $m_t = 1$, keeping every other token in the input. The diagram splits the serialized record into three author lanes for supplied prompts, policy turns e2, e4, and e6 (omitting the schema query and its reply for clarity), and tool replies. It sets $m_t = 1$ only on e4 and e6, leaving $m_t = 0$ elsewhere, including model-written e2, because curation selects targets, not authorship alone. Attention still reads masked tokens, so gradients from e4 and e6 update weights encoding the refusal without teaching or dropping e2.

    \notecue{Watch for}{Training without a mask causes role confusion. The model learns that tool outputs continue its own stream, fabricates tool replies past its call, and wastes output budget.}

    \notecue{Next}{Slide 10 examines an off-by-one alignment bug in causal language-model loss code.}
  }
\end{frame}

  \note{%
    \mlsysnotemeta{2 min}{Optional}%
    Turning Slide 9's loss mask into code requires exact alignment between inputs and labels, shown in ForCausalLMLoss from transformers 5.7.0 (loss\_utils.py). First, ignore\_index $-100$ disables loss at masked positions. Second, shift\_labels = labels[..., 1:] shifts labels by one because logits at $t-1$ (Lecture 2's raw next-token scores) predict token $t$. Before reading on, trace the code to explain why every target lands one token late and which boundary loses supervision.

    \notecue{Check}{Because ForCausalLMLoss already shifts, a pre-shifting loader creates a double-shift bug. Every target and mask lands one token late, moving supervision off the stop token onto the first observation token. Trusting the training curve is misleading because loss still falls smoothly. Shift in one place and decode a short synthetic batch first.}

    \notecue{Watch for}{Keep each selected turn's authentic stop token at $m_t = 1$, or the model generates past its call until the output limit.}

    \notecue{Teach}{Give pairs one minute to explain why every target lands one token late before revealing the double shift. For a 50-minute class, skip this slide and go to Slide 11.}

  \note{%
    \mlsysnotemeta{1.5 min}{Core}%

  \mlsyscredit{Quote: huggingface.co/blog/gradient\_accumulation. Run: transformers 5.7.0 ForCausalLMLoss, synthetic logits (images/tool\_runs.py). Trajectory Fine-Tuning, \S16.5.1.}
  \note{%
    \mlsysnotemeta{2.5 min}{Optional}%
    When micro-batches hold unequal target counts, gradient accumulation, which combines gradients across several micro-batches before one parameter update, can distort the loss. In October 2024, Hugging Face reported that its Trainer disagreed with full-batch training because it averaged each micro-batch's mean loss instead of summing total loss across micro-batches and dividing once by all non-padding targets. The table on the right runs ForCausalLMLoss on two micro-batches. One has 2,048 well-fit targets at 0.541 loss, and the other has 64 poorly fit targets at 7.309 loss. Averaging the two means yields 3.925 instead of the true global token average of 0.746, a 5.3-fold distortion that gives 64 tokens half the update. The two averages agree only when every micro-batch holds identical target counts. Across micro-batches and data-parallel ranks, which are workers holding separate model copies, sum numerators and denominators first and divide once.

    \notecue{Teach}{For a 50-minute class, skip this slide. Slide 15 covers loss normalization directly.}

    \notecue{Next}{Slide 15 contrasts token averaging against example averaging across unequal trajectory lengths.}
  }
\end{frame}

      \textbf{Example averaging:} every example's mean counts once.\\[0.35cm]

  \note{%
    \mlsysnotemeta{2 min}{Core}%
    Even when micro-batch reductions are exact, batching still demands a deliberate choice over how a 30-turn repair trace with 8,192 targets and a one-turn file lookup with 256 targets share one batch (equations 2 and 3, Napkin Math 16.2). Token averaging (blue) weights every target token equally, giving the long trace 96.97 percent against 3.03 percent, a 32-fold share that preserves Lecture 15's target-token corpus mixture. Example averaging (orange) gives each example 50 percent so long traces do not dominate. Serialization interacts directly with that choice. Across $B$ examples, splitting one trace into $H$ per-call records raises its example-averaged share from $1/B$ to $H/(B-1+H)$, whereas token averaging stays unchanged when each response is selected once.

  \note{%
    \mlsysnotemeta{2 min}{Optional}%
    Variable-length trajectories also waste buffer space when padded to the longest sequence, so sequence packing groups examples into fixed-length buffers. In Napkin Math 16.2, eight examples from 512 to 32,768 tokens total 50,176 tokens. Padding all eight rows allocates 262,144 positions, or 19.1 percent occupancy. Packing the longest example into one 32,768-token buffer and seven into a second reaches 76.6 percent occupancy with 4 times fewer positions. Krell et al. (2021) measured about 2$\times$ faster BERT language-model pretraining without cross-contamination, meaning attention or label leakage across examples. TRL 1.16.0 SFTConfig exposes packing and padding\_free, which uses FlashAttention 2 or 3 variable-length attention kernels to enforce boundaries without a dense mask matrix, both off by default.

    \notecue{Watch for}{Occupancy counts context and targets alike. Real wall-clock speedup depends on the attention kernel on your accelerator and must be measured.}

  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Packing variable-length trajectories into shared buffers is safe only when each example stays isolated. Under an ordinary causal mask, example 2's queries attend to example 1's keys across the red leak block. A block-diagonal mask instead sets cross-example scores to $-\infty$ before softmax, isolating every attention row within its own example, while per-example target masks block cross-boundary label shifts. Segment 2 established declared weighting and perturbation-tested isolation, ensuring faithful training on recorded prefixes before deployment visits unrecorded states.

  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Training on recorded prefixes leaves a policy exposed once its own mistake enters an unrecorded state. Exposure bias (Definition 16.3) arises because teacher forcing feeds recorded prefixes during training rather than the policy's own prior outputs. \begin{frame}{What does a 2\% error cost over 30 steps?}
  \mlsysactivity{Predict}{2.5 min}
  \begin{columns}[c]

    \end{column}
    \begin{column}{0.47\textwidth}
      \small
      Error measured on \textbf{reference} states:\\ \hspace*{0.3cm}$\le \min\{H,\ H^2\epsilon\}$\\[0.15cm]
      Error measured on \textbf{learner} states, each slip costing at most $u$:\\ \hspace*{0.3cm}$\le \min\{H,\ uH\epsilon\}$\\[0.25cm]
      \uncover<2->{\textbf{18} against \textbf{0.6}: a gap of $H/u = 30\times$.}
    \end{column}
  \end{columns}
  \mlsyscredit{Trajectory Fine-Tuning, Theorem 16.1 (Ross and Bagnell 2010; Ross et al. 2011) and Napkin Math 16.3 (illustrative); values derived.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    To price that drift, Ross and Bagnell (2010) proved a quadratic bound on offline imitation, and Ross et al. (2011) added a linear learner-state bound (Theorem 16.1, Napkin Math 16.3). Over horizon $H = 30$ with error $\epsilon = 0.02$, step cost in $[0,1]$, and recovery cost $u = 1$, compute both bounds on wasted turns before reading on.

    \notecue{Check}{On reference states, the bound is $\min\{H, H^{2}\epsilon\} = 900 \times 0.02 = 18$ wasted turns, saturating at $H = 1/\epsilon = 50$. A tempting mistake is missing the quadratic $H^{2}$ penalty, a second $H$ factor over Lecture 1's compounding because an early slip spoils later turns. On learner states, the bound is $\min\{H, uH\epsilon\} = 0.6$ turns, an $H/u = 30\times$ gap. Matching 0.6 offline requires $\epsilon = 0.067\%$.}

    \notecue{Watch for}{The linear bound needs small $u$. An irreversible action such as remediation lets $u$ grow with $H$ and restores $H^{2}$, so runtime checks must carry reliability.}

    \notecue{Teach}{Have the class predict both bounds before revealing 18 and 0.6.}

\begin{frame}{DAgger labels the states the learner visits}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=4.9cm,keepaspectratio]{dagger_step}{3}
  \mlsyscredit{Trajectory Fine-Tuning, figure 4(b) and \S16.6.2, redrawn; DAgger: Ross et al. 2011.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Closing that coverage gap requires labels on states the learner actually visits, and the diagram shows two methods. First, Dataset Aggregation (DAgger, Ross et al. 2011) rolls out the current policy, mixed with the reference early, collects visited states, queries an online labeler such as a stronger model or search, keeps only labels passing sandbox verification, aggregates them into the corpus, and retrains. Next, deliberate fault injection adds synthesized errors at mask 0 while placing loss at mask 1 on diagnoses and fixes. Those records must respect cause and effect and never teach a blind retry after a lost acknowledgment, violating Lecture 7's settlement-before-retry rule. Together they earn the linear $uH\epsilon$ bound. Fault injection covers designer-anticipated faults, whereas DAgger exposes errors the policy itself produces. Lecture 17 later replaces step labels with verifier-scored rollouts.

\begin{frame}{When both repairs pass, a preference pair ranks them}
  \centering

  {\small $\mathcal{L}_{\text{DPO}} = -\log \sigma\big(\beta\,[\,z_w - z_l\,]\big),\qquad z = \sum_{t\,\in\,\text{selected}} \log\dfrac{\pi_\theta(x_t \mid h_t)}{\pi_{\text{ref}}(x_t \mid h_t)}$}\par\vspace{0.04cm}
  \begin{columns}[c]
    \begin{column}{0.47\textwidth}
      \small Preference training by DPO. $\pi_{\text{ref}}$: frozen starting checkpoint. $\beta$: how strongly to resist drift from it.
    \end{column}
    \begin{column}{0.49\textwidth}
      \begin{logblock}[7.6]
        \# TRL 1.16.0, DPOConfig\\
        beta: float = field(default=0.1, ...\\
        precompute\_ref\_log\_probs: bool = ...\\
        \ind{2}"... the reference model does not need to be kept in memory."
      \end{logblock}
    \end{column}
  \end{columns}
  \mlsyscredit{Trajectory Fine-Tuning, \S16.8 and equation 7; Rafailov et al. 2023. Code: github.com/huggingface/trl, trl/trainer/dpo\_config.py, release 1.16.0 (Apache-2.0), condensed.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Starting with the training objective, suppose two continuations from the same diagnosis both fix the connection-pool leak, one running targeted tests once and the other running the full suite after every edit. Imitation alone cannot rank two passing paths. Earlier pipelines fit a separate learned reward model to comparisons and ran reinforcement learning; Direct Preference Optimization (DPO, Rafailov et al., NeurIPS 2023, equation 7) folds that into one logistic loss using sigmoid $\sigma$. Each path's score $z$ sums selected-token log-probability ratios against frozen starting checkpoint $\pi_{\text{ref}}$, while observations condition later turns without loss and identical shared prefixes cancel. Scale $\beta$ resists drift from $\pi_{\text{ref}}$ (TRL DPOConfig defaults to $\beta = 0.1$, and precomputing reference log-probabilities frees reference memory). A positive preferred-minus-dispreferred gap $z_w - z_l > 0$ indicates only a relative shift toward the preferred path against $\pi_{\text{ref}}$.

    \notecue{Watch for}{Refused e2 and fixed e4 cannot form a preference pair because e4 saw a refusal that e2 never observed. Valid pairs require identical available information.}

\begin{frame}{LoRA trains two thin matrices beside each frozen one}

  \note{%
    \mlsysnotemeta{2 min}{Core}%
    Segment 4's third choice is the parameter artifact. Rather than duplicating every weight per agent role or adding serial inference layers, Hu et al. (2021) introduced low-rank adaptation (LoRA, Napkin Math 16.5), freezing base weights $W_0$ and training two thin matrices scaled by $\alpha/r$. Matrix $B$ ($d_{\text{out}} \times r$) starts at zero while $A$ ($r \times d_{\text{in}}$) is initialized randomly, so training begins at the base model and the pair adds $r(d_{\text{in}} + d_{\text{out}})$ parameters per adapted matrix. Adapting two $4{,}096 \times 4{,}096$ matrices at $r = 16$ across 32 layers adds 8,388,608 parameters, or 0.10 percent of 8 billion. Running Hugging Face's Parameter-Efficient Fine-Tuning (PEFT) 0.21.2 library on Meta-Llama-3-8B's config.json from tensor shapes alone without loading weights, targeting attention query and output projections q\_proj and o\_proj, confirms 8,388,608 trainable parameters, or 0.1044 percent of 8.04 billion.

\begin{frame}{Open questions}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.3cm}
    \item Rationale tokens: train the model to write its own reasoning, or keep reasoning as context? What would you measure to decide?

  \end{itemize}

    \mlsysnotemeta{1 min}{Optional}%
    Three open design questions remain for any deployment. First, decide whether to select rationale tokens as targets, condition on them as context, or drop them (\S16.4.4), since each option alters serving latency and behavior. Second, price DAgger's online labeler against prevented failures inside $C_{\text{eff}}$, as in Exercise 5. Third, evaluate whether weekly schema churn limits tool-use fine-tuning strictly to schema-reading procedure.
