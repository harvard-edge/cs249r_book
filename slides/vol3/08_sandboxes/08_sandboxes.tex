  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Under ordinary OS permissions (descended from time-sharing systems like the IBM 360/67 and Lampson's 1974 access matrix), a process inherits ambient authority: everything its user account can reach, including home directories, SSH keys, and environment tokens. Launching \texttt{run\_shell} under a developer's account recreates Lecture 7's confused deputy one layer lower, spending the developer's reach on behalf of README text. Capabilities flip the default to empty (zero ambient authority from Lecture 1): a process accesses only resources named by unforgeable references explicitly granted to the task, ruling out confused-deputy escalations even inside separate child address spaces.

  \notecue{Watch for}{Spawning a child process with its own memory space removes memory sharing, not ambient authority, if it still runs with the developer's user identity.}

  \notecue{Next}{Formalize the four clauses that an enforcement point evaluates on every capability check.}}
\end{frame}

  Walk through the five-step evaluation of Equation 1 for a capability grant comprising rights, target objects, conditions, and expiry. \begin{frame}{Predict: which derived grant may be issued?}
  \mlsysactivity{Predict}{2 min}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=5.0cm,keepaspectratio]{attenuate_step}{3}\\[0.05cm]
  {\footnotesize Attenuation narrows a grant; revocation withdraws it. $G_{\text{child}} \sqsubseteq G_{\text{parent}}$ on rights, objects, conditions, expiry.}
  \mlsyscredit{Agent Sandboxes, \S8.4.2 and \S8.4.3.}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  When a repair task shifts from editing to testing or delegates to a helper, attenuation enforces monotonicity: a derived child grant must satisfy $G_{\text{child}} \sqsubseteq G_{\text{parent}}$ across rights, objects, conditions, and expiry. Step 2 rejects the proposed test grant because it requests \texttt{execute}, a right the parent edit grant never held, even though its expiry is shorter. \begin{frame}{Four envelopes differ in where a system call lands}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=5.4cm,keepaspectratio]{envelopes_step}{4}
  \mlsyscredit{Agent Sandboxes, \S8.5, figure 4. The landing point sets the trusted base and the per-call cost.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Walk through all four envelopes in order. First, a shared-kernel container filters system calls in-kernel (seccomp) and executes them on the host kernel, placing the entire host kernel inside the trusted base. Second, a user-space kernel (like gVisor's Sentry) intercepts and emulates Linux syscalls in a memory-safe user process, exposing only a slim syscall subset to the host. Third, a microVM (like Firecracker) boots a dedicated guest kernel behind hardware virtualization; normal syscalls run natively in the guest and only device I/O exits to the monitor, isolating host memory from guest-kernel exploits. Fourth, restricted bytecode (WebAssembly) lacks syscalls altogether, invoking only explicitly imported host functions.

  \notecue{Watch for}{An envelope's marketing label enforces nothing by itself: a microVM given a writable host mount leaks everything mounted into it.}

\begin{frame}{Takeaways}
  \thumbline{thumb_reach_step2.pdf}{A schema-valid command carries its whole process's authority; the kernel beneath it enforces the limit.}\\[0.15cm]
  \thumbline{thumb_attenuate_step3.pdf}{A capability names what a task may touch; a child grant only narrows it; revocation closes live handles.}\\[0.15cm]
  \thumbline{thumb_envelopes_step4.pdf}{Each envelope catches system calls at a different layer and pays its tax on different calls.}\\[0.15cm]
  \thumbline{thumb_egress_step3.pdf}{Copy-on-write storage tracks writes; the host path enforces egress.}\\[0.15cm]
  \thumbline{thumb_reset_step5.pdf}{A warm pool costs memory over the lease horizon; reuse requires a verified reset.}
  \note{%
  \mlsysnotemeta{1 min}{Core}%
  Five takeaways summarize execution containment (invariant closure beneath the model): schema-valid commands inherit process reach until the kernel bounds them; capabilities default to empty, attenuate monotonically, and close live handles on revocation; envelopes trade syscall landing points and per-call taxes; copy-on-write tracks writes while the host path governs egress; and warm pools cost memory over the lease horizon while demanding verified four-domain resets.

  \notecue{Next}{Three optional open questions examine shared GPUs, permitted-channel leaks, and covert DNS channels.}}
\end{frame}
