  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Recall from Lecture 1 that blast radius is the full set of resources and external effects that faulty or adversarial code can read, alter, disclose, or exhaust under the threat model. How much containment a task requires depends on its authority class. Read-only access ($A_0$) still carries disclosure risk through return values or sockets, the class of the credential read, so it requires read isolation and egress control. Sandboxed writes ($A_1$) confine workspace changes, cap compute, and prevent leftovers from reaching the next tenant (another user or task sharing the host). Compensable external effects ($A_2$) scope operations at mediation proxies because a local reset cannot undo remote state. Irreversible actions ($A_3$) require explicit approval at the effect boundary, right before the external action executes.

  \notecue{Watch for}{Do not equate read-only access ($A_0$) with zero blast radius. Silent exfiltration requires zero writes.}

\begin{frame}{Four envelopes differ in where a system call lands}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=5.4cm,keepaspectratio]{envelopes_step}{4}
  \mlsyscredit{Agent Sandboxes, \S8.5, figure 4. The landing point sets the trusted base and the per-call cost.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  An envelope's trusted base and per-call cost follow from where a guest system call lands across four options. A shared-kernel container filters calls with seccomp and runs them on the host kernel, placing the whole host kernel in the trusted base. A user-space kernel such as gVisor's Sentry (written in Go) intercepts and emulates Linux system calls in a memory-safe user process, exposing only a slim host subset. A lightweight virtual machine (microVM) such as Firecracker (Agache et al., NSDI 2020), a minimalist Rust monitor stripping legacy PC devices, boots a guest kernel behind CPU hardware virtualization (separate guest mode and hypervisor page tables); normal calls run natively and only device I/O exits to the monitor, isolating host memory from guest-kernel exploits. Restricted bytecode such as WebAssembly (portable bytecode in bounds-checked linear memory) has no system calls and invokes only imported host functions.

  \notecue{Watch for}{An envelope's marketing label enforces nothing by itself. A microVM given a writable host mount still leaks everything mounted into it.}

\begin{frame}{The reset contract clears four domains, then verifies them}

  Reusing an envelope safely starts with teardown. Wiping workspace files alone fails because commands can detach background daemons from the task's process group (via a double fork), bind abstract sockets with no filesystem path, store secrets in the kernel's in-memory keyring, or schedule cron jobs. Copy-on-write sharing holds one 512 MiB template plus 64 MB of dirty (modified private) memory per lease and two 8 MB standbys, cutting total memory to 39.0 GB, or 8.3$\times$ less. Doubling trajectory length doubles active-lease memory while leaving standby count unchanged.

  \notecue{Watch for}{Standby formulas assume steady arrivals. Correlated bursts still require hard admission caps.}

  \notecue{Next}{Next, test five common sandbox misconceptions in a short true-or-false check.}}
\end{frame}

\begin{frame}{Takeaways}
  \thumbline{thumb_reach_step2.pdf}{A schema-valid command carries its whole process's authority; the kernel beneath it enforces the limit.}\\[0.15cm]
  \thumbline{thumb_attenuate_step3.pdf}{A capability names what a task may touch; a child grant only narrows it; revocation closes live handles.}\\[0.15cm]
  \thumbline{thumb_envelopes_step4.pdf}{Each envelope catches system calls at a different layer and pays its tax on different calls.}\\[0.15cm]
  \thumbline{thumb_egress_step3.pdf}{Copy-on-write storage tracks writes; the host path enforces egress.}\\[0.15cm]
  \thumbline{thumb_reset_step5.pdf}{A warm pool costs memory over the lease horizon; reuse requires a verified reset.}
  \note{%
  \mlsysnotemeta{1 min}{Core}%
  Those two cases answer the driving question, showing that execution containment enforces invariant closure beneath the model and prices it in setup time, memory, and reset verification. Five takeaways summarize the architecture. First, schema-valid commands inherit their process's reach until the kernel bounds them. Second, capabilities default to empty, only narrow on attenuation, and close live handles on revocation. Third, isolation envelopes trade system-call landing points against per-call taxes and setup horizon. Fourth, copy-on-write storage tracks writes while the host path governs egress. Fifth, warm pools cost memory over the lease horizon and require verified four-domain resets.
