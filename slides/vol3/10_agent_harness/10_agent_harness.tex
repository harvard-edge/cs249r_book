\begin{frame}{A rule kept on 99\% of turns fails in 26\% of 30-turn runs}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=4.65cm,keepaspectratio]{compound_step}{2}\\[0.08cm]
  \uncover<2->{\small Five public repair agents ran 23 to 64 model calls per task at the median.}
  \mlsyscredit{Derived: $0.99^{H}$ (equation 1.1). Medians: 2,100 public SWE-bench Verified trajectories of five agent configurations.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Option B in the opening incident asked whether 99\% per-turn rule compliance is safe enough. Recall from Lecture 1 that unchecked per-step errors compound across $H$ turns as $(1-\epsilon)^H$ (Equation 1.1). With per-turn violation rate $\epsilon$, a model honoring a freeze or budget rule on 99\% of turns keeps it across 30 turns with probability $0.99^{30} = 74\%$, violating it in 26\% of runs. Across 2,100 public SWE-bench Verified runs from five configurations, median lengths span 23 to 64 model calls per task. At 64 calls, 99\% per-turn compliance holds across the run in only 53\% of cases. Reaching 99\% run-level compliance across 64 calls would require 99.98\% per turn, which prompts cannot guarantee. A deterministic runtime guard holds on every turn regardless of $H$.

  \notecue{Watch for}{The 99\% rate is illustrative, because War Story 10.1 reports no per-turn rate. Any per-turn compliance below 100\% decays exponentially with horizon.}

\begin{frame}{The harness decides what runs; the model only proposes}

  \note{%

  In a bare loop like \texttt{mini-SWE-agent}, all state lives in the message list, leaving an operator pause, spend ceiling, or required approval nowhere to register. \begin{frame}{The trajectory moves only along guarded edges}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=5.5cm,keepaspectratio]{states_step}{3}
  \mlsyscredit{After The Agent Harness, \S10.4, table 3 and fig.~2 (Explore: Trajectory State Machine on mlsysbook.ai).}
  \note{%
  \mlsysnotemeta{3 min}{Core}%
  Turning those guard predicates into a complete lifecycle starts with the normal loop, \texttt{READY} $\to$ \texttt{CALLING\_MODEL} $\to$ \texttt{WAITING\_TOOL} $\to$ \texttt{READY}. Controlled detours handle interruptions and review. A trajectory enters \texttt{PAUSED} only from \texttt{READY} and never directly from \texttt{CALLING\_MODEL}, because doing so would orphan active streams; the harness withdraws eligibility first. Replies with no admissible call return to \texttt{READY}, while policy-flagged proposals wait in \texttt{AWAITING\_APPROVAL} until signed and re-admitted. Every termination (completion, cancel, kill, budget stop, or deadline) passes through \texttt{FINALIZING}, which halts admission, runs completion checks, and settles or transfers obligations before entering absorbing terminal states that permit no further moves; retries start fresh trajectories.

  \notecue{Watch for}{A legal edge alone never authorizes a move. Every transition evaluates guards on control holds, valid grants, approvals, dependencies, remaining time before the deadline, capacity, and reserved budget, and a \texttt{COMPLETED} model call never ends the task.}

\begin{frame}{Escrow holds the exact proposal until dispatch rechecks it}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=6.3cm,keepaspectratio]{escrow_step}{3}
