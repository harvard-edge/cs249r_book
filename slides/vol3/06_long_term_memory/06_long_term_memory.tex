\begin{frame}{Each stored record plays one role in an evidence chain}
  \centering
  \mlsyssteps[width=\textwidth,height=6.0cm,keepaspectratio]{roles_step}{4}
  \mlsyscredit{Long-Term Memory, \S6.2.1, Table 1 (redrawn with the repair agent's records).}
  \note{%
  \mlsysnotemeta{3 min}{Core}%
  When the repair agent resumes in a fresh session, nothing remains in its context window, so it reconstructs state from four record roles (Table 1). First, source records such as \texttt{src/pool.py} at revision r18 or a user preference establish provenance (origin tracking from Lecture 4) without certifying bug-free truth. Second, observation logs record timestamped test outcomes, such as failure at r17 and passing at r18 under configuration \texttt{c18}, which remain permanently true as history. Third, agent-written memory such as resume notes states plans and claims rather than verified facts. Fourth, derived indexes only locate candidate records. Every derived artifact points back to its source, so a ``repair complete'' note must be checked against the observation log and the r18 source.

  \notecue{Watch for}{These four categories define epistemic roles, meaning roles of evidence, rather than fast or slow storage tiers. One database can hold all four, while the durable replicated trajectory log belongs to Lecture 11.}

  \notecue{Next}{See what happens when a deployed system blurs these roles in the Air Canada chatbot contradiction.}}

\section{Contract}

\begin{frame}{A read is a bounded request answered by an envelope}
  \centering
  \mlsyssteps[width=\textwidth,height=6.0cm,keepaspectratio]{contract_step}{3}
  \mlsyscredit{Long-Term Memory, Definition 6.1, \S6.3.1 (Table 2), \S6.3.2 (listing 1), redrawn.}
  \note{%
  \mlsysnotemeta{3 min}{Core}%
  To keep version and scope attached to every read, Definition 6.1 specifies the request, its bounds, and the provenance envelope returned. First, the runtime bounds scope, principal (the acting user or service), revision, item count, and token payload, because ten full files differ greatly from ten docstrings and scope strings never grant access. Next, the retrieval gateway (the service mediating every read) enforces access control inside those bounds and cancels backend scans upon timeout. Finally, it returns an envelope with completion status (\texttt{complete}, \texttt{partial} with a reason, or \texttt{unavailable}), searched snapshot, and each item's path, lines, revision, content hash (a byte fingerprint), role, and scoring method, where scores are not probabilities. Under the absence rule, zero hits prove absence only after a complete exact scan within that snapshot and scope, never after a timeout or approximate search.

  \notecue{Watch for}{A content hash verifies exact bytes without verifying whether a claim inside those bytes is true.}

  \notecue{Next}{See why capping retrieved tokens matters even when more tokens fit the window, using SWE-bench data.}}
\end{frame}

\begin{frame}{More retrieved context raised recall and lowered success}
  \centering
  \safeimg[width=0.96\textwidth,height=5.05cm,keepaspectratio]{swebench_context.pdf}\\[0.1cm]
  {\small SWE-bench with BM25 pre-staged files, one model, three context limits.}
  \mlsyscredit{Jimenez et al., ``SWE-bench,'' ICLR 2024, Table 2 (Claude 2, \% resolved) and Table 3 (BM25 recall of oracle files, ``Avg.'' row).}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  Payload limits are not only about avoiding overflow; staging more retrieved text can hurt task success. In the SWE-bench paper from Lecture 0 (Jimenez et al., ICLR 2024), the authors pre-staged repository files ranked by BM25, a standard keyword-ranking method, for Claude 2 at three limits of 13K, 27K, and 50K tokens. Recall of the true target files (oracle-file recall) climbed from 29.58\% at 13K to 44.41\% at 27K and 51.06\% at 50K, yet issue resolution rate fell from 1.96\% to 1.87\% and then to 1.22\%. Unrelated code distracted the model and triggered Lecture 4's Lost-in-the-Middle position drop. Retrieval policies should therefore optimize measured task acceptance and treat recall as an intermediate diagnostic.

  \notecue{Watch for}{Absolute resolution rates here are small because this baseline uses single-shot, non-interactive retrieval. Slide 12 compares interactive search tools on the same benchmark.}

  \notecue{Next}{Work through sizing a retrieval payload budget when provenance metadata shares the same token cap.}}
\end{frame}

\begin{frame}{An inverted index finds every notify, even in a stale log}
  \begin{columns}[c]
    \begin{column}{0.56\textwidth}
      \centering\safeimg[width=\textwidth,height=5.4cm,keepaspectratio]{inverted_index.pdf}
    \end{column}
    \begin{column}{0.40\textwidth}
      \centering\safeimg[width=\textwidth,height=3.6cm,keepaspectratio]{card-catalog.jpg}\\[0.1cm]
      {\footnotesize ``Our ineptitude in getting at the record is largely caused by the artificiality of systems of indexing.'' Vannevar Bush, 1945}
    \end{column}
  \end{columns}
  \mlsyscredit{Photo: TBurmeister (WMF), CC BY-SA 4.0, Wikimedia Commons (Indiana State Library card catalog). Bush, ``As We May Think,'' The Atlantic Monthly, July 1945, \S6. Diagram after Long-Term Memory, \S6.5.}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  Long before digital archives, Vannevar Bush's 1945 essay ``As We May Think'' imagined the memex, a desk-sized archive linked by associative trails, locating the hard problem of indexing in selection rather than storage capacity. Like a card catalog, an inverted index maps each term to a postings list of matching documents with counts and positions. Searching \texttt{notify} hits both \texttt{src/pool.py} and a stale r17 failure log because it tracks token occurrence without distinguishing definitions, comments, or revision currency. BM25 weights postings by term rarity, saturating frequency, and document length; in Example 6.1, a short file with one match scores 14.58 over a long file with six matches at 8.46. By contrast, a structural abstract syntax tree (AST) index resolves enclosing functions and caller chains such as ``all callers of return.''

  \notecue{Watch for}{Static structural indexes miss dynamic dispatch paths chosen at run time, so a missing call edge never proves reachability is absent.}

  \notecue{Next}{When a symptom avoids code terms altogether, compare dense search with literal search on CPython's \texttt{Condition} source code.}}
\end{frame}

\begin{frame}{Approximate indexes touch fewer bytes and promise no absence}
  \centering
  \mlsyssteps[width=0.98\textwidth,height=5.0cm,keepaspectratio]{prefilter_step}{3}\\[0.05cm]
  {\footnotesize IVF-PQ stores 64 one-byte codes (24$\times$ smaller); HNSW walks can strand under a scope filter.}
  \mlsyscredit{Long-Term Memory, \S6.6.2, Table 5 (Explore: Access Pre-Filter on mlsysbook.ai; 32 links/node, 64 subvectors, derived).}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  When a corpus exceeds the exact-scan ceiling, approximate indexes cut memory traffic by touching only a fraction of 10M vectors. A hierarchical navigable small-world (HNSW) graph keeps full vectors plus 32 8-byte links per node for greedy walks that always step to the closest neighbor, taking 17.92 GB. An inverted file with product quantization (IVF-PQ) clusters vectors and compresses each into 64 one-byte codes, taking 0.64 GB or 24$\times$ less memory. Scope filters complicate graph walks. Masking ineligible nodes during an HNSW walk can strand traversal at a local minimum where every unmasked neighbor is farther from the query, whereas post-filtering after search can return empty results despite valid matches. Three remedies address this, namely partitioning indexes by scope, seeding in-scope entry points, or scanning small filtered sets of 8,000 to 10,000 vectors exactly in 0.31 ms.

  \notecue{Watch for}{Zero hits from an approximate index never satisfy the absence rule, even when the query completes without timeout.}
