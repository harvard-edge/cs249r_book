\begin{frame}{A read is a bounded request answered by an envelope}
  \centering
  \mlsyssteps[width=\textwidth,height=6.0cm,keepaspectratio]{contract_step}{3}
  \mlsyscredit{Long-Term Memory, Definition 6.1, \S6.3.1 (Table 2), \S6.3.2 (listing 1), redrawn.}
  \note{%
  \mlsysnotemeta{3 min}{Core}%
  Definition 6.1 specifies what a read requests, its permitted bounds, and the provenance envelope returned. First, Step 1 shows the runtime setting explicit bounds on scope, principal, revision, item count, and token payload (ten full files differ vastly from ten docstrings; scope strings never grant access). Second, Step 2 enforces access control inside bounds and cancels backend scans upon timeout. Third, Step 3 returns an envelope carrying completion status (\texttt{complete}, \texttt{partial} with reason, or \texttt{unavailable}), searched snapshot, and per-item path, lines, revision, content hash, role, and scoring method (scores are not probabilities). The red absence rule holds: zero hits prove absence only after a complete exact scan within that snapshot and scope, never after a timeout or approximate search.

  \notecue{Watch for}{A content hash verifies exact bytes without verifying whether a claim inside those bytes is true.}
