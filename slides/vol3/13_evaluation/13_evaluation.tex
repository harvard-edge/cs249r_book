\begin{frame}{Pending and unknown trials stay in the denominator}
  \begin{columns}[c]
    \begin{column}{0.36\textwidth}
      \small
      \textbf{\textcolor{figgreen}{pass}}: evidence meets the criterion\\[0.08cm]
      \textbf{\textcolor{figred}{fail}}: evidence shows a violation\\[0.08cm]
      \textbf{pending}: check still running\\[0.08cm]
      \textbf{unknown}: no evidence at the cutoff\\[0.25cm]
      Accept only if every mandatory criterion passes. Any fail ends it.
    \end{column}
    \begin{column}{0.62\textwidth}
      \centering\mlsyssteps[width=\textwidth,height=3.6cm,keepaspectratio]{verdicts_step}{2}\\[0.05cm]
      {\footnotesize 100 trials: 60 accepted, 25 failed, 15 unresolved (illustrative)}
    \end{column}
  \end{columns}
  \mlsyscredit{Agent Evaluation, \S13.2.3, the four-verdict rule. Counts illustrative; rates (derived).}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Each mandatory criterion resolves to one of four verdicts (pass, fail, pending, unknown), kept separate from trajectory runtime states. Aggregation short-circuits: any mandatory fail rejects the trial, every mandatory pass accepts it, and otherwise the trial remains pending or unknown. First, Step 1 shows 100 illustrative trials with 60 accepted, 25 failed, and 15 unresolved: the default counts unresolved trials as not accepted (60 percent) and reports the interval $[60\%, 75\%]$. Then, Step 2 shows the survivorship error of dropping those 15, inflating the rate to 70.6 percent because hard tasks time out most often, while artificially lowering cost per accepted task.

    \notecue{Watch for}{Under Lecture 10's bounded-liability admission, outstanding reservations stay separate from settled charges because an evaluation cutoff does not cancel a running cloud job.}

    \notecue{Next}{Slide 11 inspects real SWE-bench grader code where missing test evidence once defaulted to pass.}
  }
\end{frame}

  \note{%

    The glovebox illustrates a hermetic boundary: work proceeds through sealed ports inside a declared, controlled atmosphere. Fixture pool\_fixture\_v1 pins the starting source revision, defect text, language toolchain, package versions, service emulators with their fault modes, and editable paths so a library upgrade between baseline\_v1 and candidate\_v2 cannot disguise itself as a model gain. Because serving nondeterminism persists (Lecture 11), hermetic execution records every remaining source of variation. A mock cloud API that always replies HTTP 200 immediately can never test recovery from timeouts or dropped acknowledgments.

\begin{frame}{Model judges change verdicts when two answers swap places}

  \safeimg[width=0.86\textwidth,height=4.2cm,keepaspectratio]{zheng.pdf}\\[0.1cm]

\begin{frame}{New tasks shrink both variance terms; repeats shrink one}
  \centering
  {\small $\operatorname{Var}(\hat{p}) = \dfrac{\sigma_{\text{task}}^2}{N} + \dfrac{\sigma_{\text{run}}^2}{N\,r}$\qquad
  {\footnotesize $N$ tasks, $r$ runs each; pilot: $\sigma_{\text{task}}^2 = 0.08$, $\sigma_{\text{run}}^2 = 0.16$; budget 600 runs}}\\[0.2cm]
  \only<1|handout:0>{\safeimg[width=0.82\textwidth,height=3.9cm,keepaspectratio]{designs_step1.pdf}\\[0.1cm]{\small New tasks free: one run each wins}}%
  \only<2->{\safeimg[width=0.82\textwidth,height=3.9cm,keepaspectratio]{designs_step2.pdf}\\[0.1cm]{\small A new fixture costs 10 runs: 5 runs each wins}}
  \mlsyscredit{Agent Evaluation, \S13.5.1, equation 1; numbers from exercise 1 (hypothetical). Standard errors (derived).}
  \note{%
    \mlsysnotemeta{2.5 min}{Optional}%
    Equation 1 splits acceptance-rate variance across $N$ tasks and $r$ runs per task into a task term ($\sigma_{\text{task}}^2/N$) and a run term ($\sigma_{\text{run}}^2/(Nr)$): extra repeats shrink only run variance, whereas new tasks shrink both. In Exercise 1's pilot (mean 0.6, $\sigma_{\text{task}}^2 = 0.08$, giving $\sigma_{\text{run}}^2 = 0.6 \times 0.4 - 0.08 = 0.16$) with a 600-run budget, Step 1 shows free fixtures favor 600 tasks $\times$ 1 run (SE 2.00 points) over 200$\times$3 (2.58) or 100$\times$6 (3.27). Step 2 prices each new fixture at 10 runs: now 40 tasks $\times$ 5 runs wins at 5.29 points versus 54$\times$1 at 6.67, because repeats pay off once fixtures are costly ($\sigma_{\text{run}}^2/\sigma_{\text{task}}^2 = 2$ marks where run variance stops dominating).

LATS with GPT-4 (tree search) reached 88.0 percent at \$134.50, whereas simple baselines on the same model that retry or warm temperature on failed tests reached 92.0 to 93.2 percent for \$2.45 to \$2.51, 55 times cheaper and more accurate (single-call GPT-4 scored 89.6 percent for \$1.93). Accuracy-only leaderboards reward unbounded retries, refuting the fallacy that higher accuracy alone picks the better agent; matched-budget evaluation fixes tasks, criteria, and envelope first.

    \notecue{Watch for}{While 2024 API prices change over time, the structural cost gap between policies remains.}
