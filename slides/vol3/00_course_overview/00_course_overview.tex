\begin{frame}{A steam-engine governor closes its loop on measured speed}
  \begin{columns}[c]
    \begin{column}{0.46\textwidth}
      \centering\safeimg[width=\textwidth,height=5.4cm,keepaspectratio]{steam-engine-governor.jpg}
    \end{column}
    \begin{column}{0.50\textwidth}
      \normalsize
      The spinning balls measure the engine's speed and move the steam valve.\\[0.4cm]
      \uncover<2->{An agent is a model inside a loop that software closes. The loop runs commands and reads back what happened.}
    \end{column}
  \end{columns}
  \mlsyscredit{Photo: centrifugal governor on an Allis-Chalmers steam engine, brewbooks (CC BY-SA 2.0), Wikimedia Commons.}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  Closed-loop control is far older than language models, and the steam-engine centrifugal governor shows its mechanism directly. As shaft speed rises, the spinning weights swing outward and throttle the steam valve. As speed drops, they fall and open the valve. Because the mechanism senses actual shaft speed rather than the throttle setting, it corrects real disturbances, the organizing principle of feedback control that Norbert Wiener formalized in founding cybernetics (Wiener, 1948). A software agent closes the same loop. The language model proposes an action, software runs the command, and the measured output returns as the next observation, just as in the 22 Django calls.

  \notecue{Watch for}{Unlike a physical governor reading shaft speed, a model emits untrusted text proposals that can be fluent and wrong. Software must validate and bound every action before executing it.}

  \notecue{Next}{Compare the exact same models with and without a loop to measure how much feedback matters in practice.}}
\end{frame}

\begin{frame}{An agentic system is six layers serving one task}
  \begin{columns}[c]
    \begin{column}{0.60\textwidth}
      \centering
      \only<1|handout:0>{\mlsyskitfig[width=\textwidth,height=5.5cm,keepaspectratio]{stack_build2}}%
      \only<2|handout:0>{\mlsyskitfig[width=\textwidth,height=5.5cm,keepaspectratio]{stack_build4}}%
      \only<3|handout:0>{\mlsyskitfig[width=\textwidth,height=5.5cm,keepaspectratio]{stack_build6}}%
      \only<4-|handout:1>{\mlsyskitfig[width=\textwidth,height=5.5cm,keepaspectratio]{stack_build7}}%
    \end{column}
    \begin{column}{0.37\textwidth}
      \normalsize
      \only<1|handout:0>{\textbf{Model and Memory}\\[0.15cm]\small One call returns a proposal, its tokens, and its price; memory chooses what each call reads and keeps.}%
      \only<2|handout:0>{\textbf{Tools and Runtime}\\[0.15cm]\small Tools bound allowed actions in sandboxes; the runtime runs the loop, enforces limits, recovers, and evaluates.}%
      \only<3|handout:0>{\textbf{Learning and Scale}\\[0.15cm]\small Learning trains on recorded runs; scale splits work across agents and prices each accepted task.}%
      \only<4-|handout:1>{\textbf{Trajectory}\\[0.1cm]\small Every layer serves the record of one task, from first request to finish.\\[0.25cm]Django run: 22 calls (Model), growing prompts (Memory), container commands (Tools), loop and stop rule (Runtime).}%
    \end{column}
  \end{columns}
  \note{%
  \mlsysnotemeta{4 min}{Core}%
  This six-layer stack, repeated on every lecture divider, arranges an agentic system from bottom to top in four steps. Model handles each call, priced by its tokens (the text chunks a model reads and writes), while Memory selects what context, the text and history sent into each call, enters the prompt and what persists across tasks. Tools bound permitted actions inside sandboxes, isolated execution spaces, while Runtime runs the loop, enforces limits and stop rules that end execution, recovers from crashes, and evaluates outcomes. Learning and Scale train on recorded runs, coordinate multiple agents, and price each accepted task. Spanning all six layers, the Trajectory bar marks one task's complete record as our unit of engineering, uniting the Django run's calls, growing prompts, container commands, and loop control.

  \notecue{Watch for}{These layers are tightly coupled rather than independent silos. A memory decision immediately alters serving cost, the expense of running the model on requests, as well as latency and runtime reliability.}

  \notecue{Next}{Put this six-layer map to work by diagnosing which layer failed in six real production and benchmark incidents.}}
\end{frame}
