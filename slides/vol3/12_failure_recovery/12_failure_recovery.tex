  \uncover<2->{\safeimg[width=0.92\textwidth,height=3.35cm,keepaspectratio]{comp_states.pdf}}\\[0.1cm]
  \uncover<3->{\footnotesize Restoring the snapshot \op{ws\_r18} resets local files; it never releases the remote environment.}
  \mlsyscredit{Failure Recovery, \S12.3.2, equation 2 and Definition 12.2.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    First, Step 1 defines compensation (Definition 12.2, equation 2): because no distributed transaction spans the runtime log and external services, compensation is a separately committed forward operation that restores declared predicates $P$, so $S_{\text{comp}} \equiv_P S_{\text{pre}}$. Next, Step 2 shows two predicates for env\_r18\_01 (allocated, depended on by an admitted test) toggling false, true, false while billing charges and audit records stay outside $P$. \begin{frame}{Recovery chooses by evidence, then admission, then cost}

  \note{%
    \mlsysnotemeta{3 min}{Core}%
    Lecture 2 showed self-review without new evidence lowering accuracy while external checks raise it, so repair success rate $p$ is a measured property of one failure class and feedback source (Olausson et al. found modest, variable code-repair gains under matched budgets). First, Step 1 inspects evidence class: an unknown outcome raises an effect-status problem requiring settlement or a verified repeat contract (Lecture 7) before any repair.
