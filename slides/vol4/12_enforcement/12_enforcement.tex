  \note{
  \mlsysnotemeta{2.5 min}{Core}%

\begin{frame}{A barrier on distance alone gives the motor no say}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=3.6cm,keepaspectratio]{reldeg_step}{2}\\[0.15cm]
  \uncover<2->{\normalsize $h(\theta,\omega)=\theta-\dfrac{\omega^2}{2\,\alpha_{\text{net}}}\ \ge 0$}\\[0.1cm]
  \uncover<2->{\footnotesize $h$: margin; $\theta$: clearance; $\omega$: speed; $\alpha_{\text{net}}$: net braking.\enspace Relative degree: integrators from torque to $h$.}
  \mlsyscredit{Safety Enforcement, \S12.5, Definition 12.2, \S12.5.1, and equation 5.}
  \note{
  \mlsysnotemeta{2.5 min}{Core}%
  To enforce that 79.45~mm descending stopping margin on every millisecond tick, a control barrier function defines a safety margin $h \ge 0$ and requires every admitted command to keep $h$ from decreasing faster than $\gamma h$, where $\gamma$ is a positive decay-rate constant, preserving safety forward in time (Definition 12.2). Setting $h$ to raw clearance $\theta$ fails because torque must integrate twice, through acceleration and velocity, to reach position, giving relative degree two. Consequently, $\dot{h} = -\omega$ contains no torque and demands infinite torque at contact. Subtracting stopping distance instead forms the kinetic barrier $h(\theta,\omega) = \theta - \omega^2 / (2\alpha_{\text{net}}) \ge 0$ (eq.~5). Now $\dot{h}$ contains torque directly, giving relative degree one, and turns the barrier rule into a bound on the next torque whose $h=0$ boundary at 79.45~mm and 1.2~rad/s matches the descending stopping budget.

  \notecue{Watch for}{Relative degree counts integrators from control input to margin, not physical degrees of freedom. If your background is in machine learning, review the control appendix for details.}

  \notecue{Next}{Next, plot equation 6 to see how braking torque demand climbs as clearance shrinks toward 79.45~mm.}
}
\end{frame}

\begin{frame}{Inside 79.45 mm the barrier asks for more than the joint has}

\begin{frame}{Every barrier rests on five premises, each with a detector}
  \centering
  \safeimg[width=0.92\textwidth,height=5.0cm,keepaspectratio]{premises.pdf}\\[0.05cm]
  {\small A premise no detector watches is an assumption.}
  \mlsyscredit{Safety Enforcement, \S12.7.3 (conditions of forward invariance) and \S12.7.4.}
  \note{
  \mlsysnotemeta{2 min}{Core}%
  Forward invariance of a control barrier function, the guarantee that states starting safe stay safe, holds in continuous time only under five premises. They are bounded model error, bounded external disturbances, qualified actuator authority and delay, solver completion inside its cycle budget, and a sample period short enough to bound inter-sample drift between ticks. Because an unwatched premise is only an assumption, each premise carries a per-tick detector. When any detector trips, the enforcer never assumes better numbers and instead switches to a fallback whose premises still survive. Because this machine does not measure floor friction, slippery floors violate disturbance and actuation premises without a detector and must become an operating restriction.

  \notecue{Watch for}{Matching joint encoders, which measure joint angles, to a reference trajectory is only a proxy for true physical body pose in the aisle.}

State latching takes 30~$\mu$s, proposal and lease checks 15~$\mu$s, tracking 10~$\mu$s, QP solve 150~$\mu$s, output staging 15~$\mu$s, and reserve 30~$\mu$s. An unloaded 135~$\mu$s run bounds nothing. Between ticks, zero-order hold (holding the last command constant) drifts $v\Delta t + \tfrac{1}{2}a\Delta t^2 = 1.500 + 0.001 = 1.501\text{ mm}$ at 1.5~m/s and 2~m/s$^2$, well under 100~mm protective margin. An overrunning timer interrupt, the clock-triggered check routine, cannot catch itself and needs an independent timer, linking Lecture 4's WCET to Lecture 13's loaded test.

  \notecue{Watch for}{Naming a real-time operating system never bounds interference from shared memory or peripherals.}

  \notecue{Teach}{In a 50-minute class, skip this slide, note that the enforcer must finish inside a 250~$\mu$s budget watched by an independent timer, and move to the four-rung fallback ladder.}

  \mlsyscredit{Safety Enforcement, \S12.9.1, \S12.9.2, table 3, and Pitfall in \S12.12 (derived S-curve; brake set time illustrative).}
  \note{
  \mlsysnotemeta{2.5 min}{Core}%
  Test the difference between STOP and INHIBIT. Suppose the proposer's host crashes while the base cruises at 1.3~m/s. Before reading on, decide between cutting torque immediately (A) and running the resident STOP first (B).

  \notecue{Check}{The answer is B. Safe torque off (STO, Category 0 under IEC 60204-1, the machinery electrical-safety standard) disables inverter power so the motor cannot generate torque, yet it applies no braking. The base coasts unbraked while spring brakes take 30 to 80~ms to close with no credited stopping capacity. Instead, the MCU detects the silent host heartbeat signal within 30~ms and runs the resident Category 1 S-curve stop, taking 931.25~ms over 605.31~mm from 1.3~m/s, removing torque only after confirmed standstill. A tempting answer is A, which mistakes STO for maximum braking. Cutting torque lets a moving base coast, drops a gravity-loaded arm, and topples a walking humanoid.}
