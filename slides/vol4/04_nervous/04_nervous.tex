\section{Mailbox}

\begin{frame}{A queue hands the tick old plans; a mailbox the newest}
  \centering
  \mlsyssteps[width=14.6cm]{queue_step}{2}\\[0.1cm]
  \uncover<2->{\small A \textbf{state message} replaces the old value in place. Backpressure cannot pause moving mass.}
  \mlsyscredit{The Nervous System, \S4.3.2 (event and state messages, after Kopetz 2011).}
  \note{%
  \mlsysnotemeta{2.5 min}{Core}%
  First, a conventional FIFO queue preserves every message in order, which fails under physical motion: if the reader lags or the writer bursts after a stall, the tick consumes obsolete proposal 5 while proposal 9 already reflects newer sensors, and backpressure cannot pause moving mass. Second, a one-slot mailbox overwrites the old proposal in place so the tick always inspects the freshest complete plan. Following Kopetz (2011), real-time control separates overwrite state messages (live commands and sensor state) from queued event messages (diagnostic logs and fault records stored in ordered audit buffers).

  \notecue{Watch for}{Overwriting unread proposals does not discard future waypoints of an already admitted chunk; those execute on schedule under the active lease until a valid newer chunk replaces them.}

  \notecue{Next}{Predict how long a 1 kHz reader actually waits under a blocking mutex, a try-lock, and a one-attempt seqlock.}
}
\end{frame}

\begin{frame}{The seqlock reader makes one bounded attempt per tick}
  \centering
  \mlsyssteps[width=14.6cm]{seqlock_step}{3}\\[0.05cm]
  {\small Odd counter: a write is open. Changed counter: a torn copy. Either way, keep the active chunk.}
  \mlsyscredit{The Nervous System, \S4.3.2 (figure 4 panel b, redrawn); Lamport 1977; Kopetz and Reisinger 1993.}
  \note{%
  \mlsysnotemeta{3 min}{Core}%
  On the safety microcontroller, the receive interrupt writes each validated frame into the mailbox slot by incrementing a sequence counter to odd, copying payload bytes, and incrementing to even; the higher-priority 1 kHz tick reads counter, payload, and counter once without retrying. First, clean read: counter reads 8 before and 8 after, so the tick validates freshness, lease, and limits. Second, mid-write collision: counter reads odd (9), so the tick discards the partial copy in constant time, keeps the active chunk, and picks up 10 on the next tick. Third, host stall: no frame arrives, counter stays at 10, the tick never blocks, and the lease keeps counting down; a crashed host cannot leave the counter odd because it never touches microcontroller SRAM.

  \notecue{Watch for}{Retrying in a loop has no execution-time bound if writes keep colliding. Out-of-order cores require memory barriers (such as Arm Cortex-M \texttt{DMB}) so payload reads never reorder ahead of counter checks; triple- or quadruple-buffered slots avoid collisions at higher memory cost.}

  \notecue{Next}{Compare real retry-loop seqlock code from the Linux kernel with single-attempt try-lock code from \texttt{ros2\_control}.}
}
\end{frame}

  \mlsyscredit{Jones 1997 (after Wilner, RTSS 1997 keynote), as archived at cs.cornell.edu/courses/cs614; Reeves 1997; The Nervous System, War Story 4.1.}
  \note{%
  \mlsysnotemeta{2 min}{Core}%
  Resolve the opening case using the response-time equation. First, trace the schematic timeline: the bus task's execution time $C$ and preemption $I$ were bounded, yet its blocking term $B$ had no upper bound because a medium-priority communications task indefinitely preempted the low-priority weather task while it held the bus mutex, firing the total-reset watchdog. Second, reveal the fix (Sha et al. 1990): priority inheritance elevates the lock holder to the blocked high-priority task's priority so medium-priority work cannot preempt it, bounding $B$ to one critical section. JPL reproduced the bug on a ground testbed with full tracing and uplinked a patch toggling the mutex's inheritance flag on.

  \notecue{Watch for}{Engineers had left priority inheritance disabled to avoid minor mutex overhead and dismissed one or two pre-flight resets as hardware glitches; our permission tick eliminates mutexes entirely via the seqlock.}

  \notecue{Next}{Extend timing bounds onto the physical drive bus by comparing CAN FD and EtherCAT across all nine axes.}
}
\end{frame}
