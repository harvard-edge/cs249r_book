  \note{[2.5 min] [CORE] The I/O wall. Hold the input path fixed and make the accelerator faster. Step 1: the chapter's normalized example. \begin{frame}{Required bandwidth is consumers $\times$ batch bytes $\div$ compute time}
  \centering
  \vspace{0.3cm}
  {\Large $\text{BW}_{\text{required}} =
    \underbrace{N_{\text{GPU}}}_{\text{\normalsize\uncover<2->{consumers}}} \times
    \underbrace{\eta_{\text{target}}}_{\text{\normalsize\uncover<3->{busy fraction}}} \times
    \dfrac{\overbrace{D_{\text{vol,batch}}}^{\text{\normalsize\uncover<4->{bytes per batch}}}}
          {\underbrace{T_{\text{iteration}}}_{\text{\normalsize\uncover<4->{compute time}}}}$}\\[0.6cm]
  {\normalsize\uncover<5->{Delivered rate $=$ the slowest stage: read, network, decode, host copy, PCIe.}}
  \mlsyscredit{Data Storage, \S4.4, equations 2 and 3.}
  \note{[2.5 min] [CORE] The input delivery budget. Step 1: the equation. Step 2: $N_{\text{GPU}}$ counts accelerators that consume distinct batches; GPUs that split one batch share one read. Step 3: $\eta_{\text{target}}$ is the fraction of wall-clock time spent computing, typically 0.8 to 0.95; it is an active-time fraction and differs from model FLOPs utilization. Step 4: bytes in one local batch over its uninterrupted compute time. A faster accelerator shrinks the denominator, which is exactly why it raises demand. Step 5: every stage between storage and HBM must sustain this rate, measured in the same output-equivalent bytes, because the delivered rate is the minimum over stages. Compression may speed the read and slow the decode. ENGAGE: double the GPUs at the same batch and step time; what happens to the requirement? (Expected: it doubles.) WARN: if the measured iteration time already includes stalls, multiplying by $\eta$ again counts the slowdown twice.}
\end{frame}

\begin{frame}{Overlap turns read plus compute into the longer of the two}
  \centering
  \mlsyssteps[width=\textwidth,height=5.0cm,keepaspectratio]{stall_step}{2}\\[0.05cm]
  {\small Data stall $= (T_{\text{step}} - T_{\text{compute}}) / T_{\text{step}}$: the share of each step spent waiting for input.}
  \mlsyscredit{Data Storage, Napkin Math 4.5 and equation 4.}
  \note{[2 min] [CORE] The data stall ratio. Compute takes \val{step_ms} ms per batch; storage takes \val{io_ms} ms to deliver one. Step 1: without overlap, the GPU waits for each read, then computes, \val{seq_ms} ms per step, \val{io_ms} of them stalled, \val{seq_stall_pct} percent. Step 2: overlapped, the loader reads batch $i+1$ while the GPU computes batch $i$, so a step costs the longer of the two, \val{ovl_ms} ms, and the stall falls to \val{ovl_wait_ms} of \val{ovl_ms} ms, \val{ovl_stall_pct} percent. \begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.18cm}
    \item Tiers quote bandwidth at different scopes; \val{hot_miss_pct}\% misses at \val{hot_penalty}$\times$ cost \val{hot_lost_pct}\% of the rate.
    \item Required bandwidth is consumers $\times$ batch bytes $\div$ compute time, at the slowest stage.
    \item Shards amortize file opens; the metadata server binds before the bytes do.
    \item A checkpoint writes each byte once, pauses for the local write, and counts at its manifest.
    \item Versioned, keyed writes make replay safe; price placement by the whole delivery bill.
  \end{itemize}
  \note{[1 min] [CORE] One line per segment. Ask students to star the one they would have gotten wrong before today; most star the second or the third.}
\end{frame}
