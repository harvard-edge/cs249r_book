\mlsysnote{%
  \mlsysnotemeta{1 min}{Core}%
  That 48\% shortfall is one case of a general feeding limit. Equations 4 and 5 express Lecture 1's overlapped iron law for input pipelines. Training throughput cannot exceed the minimum of the accelerator compute rate $R_{\text{compute}}$ and the data supply rate $BW_{\text{storage}}(1 - \text{overhead}) / (\text{bytes per sample})$, where overhead captures bandwidth lost to seeks, headers, and protocol work that the previous estimate folded into usable supply. Whenever data supply is smaller, buying a faster accelerator yields zero speedup. Raising throughput then requires either more effective storage bandwidth or fewer bytes per sample, which Segment 3 addresses.

  \notecue{Next}{Test this feeding law on a common optimization that caches pre-decoded tensors instead of compressed JPEGs.}
}

   \underbrace{\frac{BW_{\text{storage}}\,(1-\text{overhead})}{\text{bytes per sample}}}_{\text{data supply}}\Big)$\\[0.6cm]
  {\small\textcolor{white!75}{Samples per second on both sides; equations 4 and 5 of the chapter.}}%

\begin{frame}{Columnar files read one fifth of the bytes; dictionaries cut more}

  \note{%
    \mlsysnotemeta{1.5 min}{Optional}%
    Consider a fraud model reading 20 of 100 equal-size columns. Row-oriented files such as comma-separated values (CSV) pull all 100 columns off disk.     \notecue{Check}{Why does columnar projection buy nothing when a model reads all 100 columns? Every column must still be fetched from disk, leaving only per-column compression gains.}

\begin{frame}{Drift is a change in $p(x)$, $p(y)$, or $p(y \mid x)$}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=5.6cm,keepaspectratio]{drift_step}{3}
  \mlsyscredit{Data Engineering, \S4.12.1.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Monitoring decomposes distribution shift into three probability terms, input prevalence $p(x)$, outcome prevalence $p(y)$, and the true relationship from inputs to labels $p(y \mid x)$. First, recall Lecture 1's covariate shift, where $p(x)$ moves while $p(y \mid x)$ holds, such as a new KWS microphone changing its frequency response (how strongly it captures low versus high sound pitches); input feature monitors catch it. Second, label shift moves $p(y)$, as in winter flu spikes, which shifts in the prediction mix reveal. Third, concept drift changes $p(y \mid x)$ as fraudsters adapt, which only delayed fresh labels expose.

    \notecue{Check}{Which shift describes Lecture 1's ImageNetV2, and which shift is hardest to catch? ImageNetV2 is covariate shift, detectable in inputs before labels arrive. Concept drift is hardest to catch, because input statistics can look unchanged until outcomes arrive.}

    \notecue{Watch for}{Keep external world drift separate from Part 1's internal training-serving skew, where serving preprocessing logic or fitted state diverges from training.}

\begin{frame}{The K-S test flags drift when the CDFs separate}
  \begin{columns}[c]
    \begin{column}{0.60\textwidth}

      \uncover<3->{$D = \max_x \lvert F_{\text{train}}(x) - F_{\text{recent}}(x)\rvert$\\[0.3cm]

    To test covariate shift on a continuous feature, return to Part 1's quiet batch, where 15\% of clips had microphone gain halved yet passed every schema check. First compute the empirical cumulative distribution function (CDF), the fraction of samples at or below each loudness value in dBFS (decibels relative to full scale, where values closer to 0 are louder), for the training baseline and 1,000 recent quieter clips. \begin{frame}{PSI adds every bin that moved, 0.135 here}
  \centering
  {\small $\text{PSI} = \sum_{\text{bins}} \big(\text{recent} - \text{training}\big)\,\ln\dfrac{\text{recent}}{\text{training}}$}\\[0.1cm]
  \mlsyssteps[width=0.84\textwidth,height=4.7cm,keepaspectratio]{psi_bins_step}{3}
  \mlsyscredit{Data Engineering, \S4.12.1 (formula and bands). Bin shares are illustrative.}
  \note{%
    \mlsysnotemeta{3 min}{Core}%
    To score shift magnitude independent of sample size, the Population Stability Index (PSI) bins training loudness into equal 20\% quintiles against recent bin shares of 30, 25, 20, 15, and 10\%. Each bin weights its share change by the natural log ratio; when a bin shrinks, both factors turn negative and their minus signs cancel, so every moved bin contributes positively. The quietest bin adds $0.10 \ln(1.5) = 0.041$, the loudest shrinks by half yet still adds $0.10 \ln(2) = 0.069$ after sign cancellation, and summing all bins yields 0.135. Heuristics treat values under 0.1 as stable, 0.1 to 0.25 as moderate, and above 0.25 as requiring action. Like the asymmetric Kullback-Leibler (KL) divergence, another log-ratio measure, PSI diverges on empty bins, so monitors smooth zero counts and fix KL's direction.

    \notecue{Check}{What does PSI equal when recent bin shares match training identically? It equals zero, because every share difference is zero and every log ratio is zero.}

    \notecue{Watch for}{The 0.1 and 0.25 thresholds are conventions to calibrate per application rather than physical laws.}

    \notecue{Next}{Inspect how Evidently's source code switches automatically from K-S to an effect-size distance above 1,000 rows.}
  }
\end{frame}

\begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.3cm}
    \item Moving a petabyte costs about a day and \$20,000, so large datasets pull the computation to them.
    \item Training runs at the slower of compute and data supply.
    \item Bytes per sample is a lever as strong as bandwidth; which wins depends on the limiting stage.
    \item Drift statistics flag; controlled comparisons against a release diagnose.
  \end{itemize}
  \note{%
    \mlsysnotemeta{1.5 min}{Core}%
    Four engineering principles summarize how a pipeline keeps pace with both hardware and the world across the five segments. Moving a petabyte quantifies data gravity. Feeding an accelerator obeys the min-of-rates ceiling. Reducing bytes per sample must relieve the limiting stage. Finally, drift statistics flag changes while fixed-version release comparisons diagnose the cause.
