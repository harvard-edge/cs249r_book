\section{Time}

\begin{frame}{A training token costs $6P$ FLOPs; an inference token, $2P$}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=4.9cm,keepaspectratio]{flops_per_token_step}{2}\\[0.35cm]
  \uncover<2->{\normalsize Backward: one product for the activation gradient, one for the weight gradient.}
  \mlsyscredit{Model Training, Lighthouse 8.1.}
  \note{[2 min] [CORE] $P$ is the number of parameters. Step 1: in the forward pass every weight takes part in one multiply-add per token, two FLOPs, so a token costs $2P$. That is all inference pays. Step 2: the backward pass computes two matrix products per weight: one carries the error signal to the previous layer (the activation gradient), and one produces the gradient the optimizer needs (the weight gradient). That is $4P$, and a training token costs $6P$. Over a dataset of $D$ tokens, the work is $O \approx 6PD$. For GPT-2 XL that is $1.5\times10^{21}$ FLOPs. LINK: Lecture 5 derived both backward products for one layer. WARN: the $6P$ rule leaves out the attention-score products, which grow with sequence length squared; for GPT-2 XL at 1,024 tokens they add about 10 percent (320.8 against 295 TFLOP per step in the chapter's per-layer count).}
\end{frame}

\mlsysnote{[2 min] [CORE] The training-time law, the iron law of Lecture 1 specialized to training. The numerator is the work, $6PD$: data times algorithm. The denominator is what the machine delivers: the peak rate at the chosen number format times the utilization, the fraction of that peak spent on useful model arithmetic. Every stall, data wait, synchronization, and slow kernel (a kernel is one operation's program on the accelerator) lowers the utilization. Three levers: do less work, buy a higher peak, or waste less of it. Then point to the last line: memory appears nowhere in the law. A step that does not fit in memory runs at no speed, so memory is a gate, checked before the law applies. LINK: Lecture 1's iron law has the same three factors.}
\mlsysfocus{The Training-Time Law}{%
  $\displaystyle T_{\text{train}} = \frac{\overbrace{6PD}^{\text{work, } O}}{\underbrace{R_{\text{peak}}}_{\text{peak rate}} \times \underbrace{\eta_{\text{hw}}}_{\text{utilization}}}$\\[0.6cm]
  {\small\textcolor{white!75}{Memory is not in the law. It decides whether the step runs at all.}}%
}

\mlsysnote{[0.5 min] [CORE] The law said nothing about memory. Now the gate: what must the step hold?}
\mlsysdivider{What does a training step have to hold in memory?}{Model Training, \S8.3.2 and \S8.3.3}
\section{Memory}

\begin{frame}{Training holds four kinds of state; inference holds one}
  \centering
  \mlsyssteps[width=0.98\textwidth,height=5.0cm,keepaspectratio]{train_state_step}{4}
  \mlsyscredit{Model Training, \S8.3.2 (simplified static view: parameters, gradients, and Adam's two moments, 1:1:2).}
  \note{[2.5 min] [CORE] Build the memory bar one term at a time. Step 1: the weights. Inference keeps these (plus a small working set) and nothing else. Step 2: gradients, one per weight, the same size again. Step 3: the optimizer's state. Adam, the default optimizer for language models, keeps two running averages per weight: the first moment $m$ (a smoothed gradient, momentum) and the second moment $v$ (a smoothed squared gradient, which scales each weight's step size). Weights, gradients, and moments sit in a 1:1:2 ratio. Step 4: the activations, the forward values autodiff saves for the backward pass (Lecture 7). They are the only term that grows with batch size and sequence length. WARN: the width of the activation block is drawn for illustration; the next slides put numbers on every term, starting with the optimizer.}
\end{frame}

\begin{frame}{SGD keeps no extra state; momentum keeps one copy; Adam two}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=4.6cm,keepaspectratio]{optimizer_bytes_step}{3}
  \mlsyscredit{Model Training, \S8.3.2 and table 3 (FP32 throughout).}
  \note{[2 min] [OPTIONAL] Every optimizer stores the weights (W) and their gradients (G); in FP32 that is 8 bytes per parameter. Step 1: plain stochastic gradient descent (SGD) keeps nothing else. Step 2: momentum keeps one running velocity per weight, $v$, a smoothed gradient: 12 bytes. Step 3: Adam keeps two running averages, the first moment $m$ and the second moment $v$ (a smoothed squared gradient that scales each weight's step): 16 bytes, twice the weights and gradients. ENGAGE: why pay for Adam's extra 4 bytes? (Expected: it often reaches the target loss in fewer steps; whether it saves time must be measured.) LINK: memory-efficient optimizers such as Adafactor and 8-bit Adam attack exactly the orange blocks.}
\end{frame}


\begin{frame}{Mixed-precision Adam holds 16 bytes per parameter}
  \centering
  \safeimg[width=0.95\textwidth,height=5.0cm,keepaspectratio]{static_bytes.pdf}\\[0.3cm]
  {\normalsize Eight times the 16-bit weights an inference server stores.}
  \mlsyscredit{Model Training, \S8.3.2.}
  \note{[1.5 min] [CORE] The common recipe, mixed precision (16-bit arithmetic with 32-bit bookkeeping, taken apart next lecture): 2 bytes for the 16-bit weights, 2 for the 16-bit gradients, 4 for a 32-bit master copy of the weights that the optimizer updates, and 8 for Adam's two 32-bit moments. Sixteen bytes per parameter, against the 2 bytes an inference server holds: eight times. WARN: this is before a single activation is stored. A 7B model that serves from 14 GB needs 112 GB to train this way.}
\end{frame}

\begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item Run time is $6PD$ over peak times utilization; utilization moves time and energy together.
    \item Mixed-precision Adam holds 16 bytes per parameter before any activation.
    \item A step holds weights, gradients, optimizer state, and activations; only activations grow with batch and sequence.
    \item Busy time bounds MFU; profile before fixing, and fit before profiling.
  \end{itemize}
  \note{[1 min] [CORE] One line per segment, plus the order of work. Ask students to star the one they would have gotten wrong before today.}
\end{frame}
