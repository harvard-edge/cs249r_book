\begin{frame}{A training token costs $6P$ FLOPs; an inference token, $2P$}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=4.9cm,keepaspectratio]{flops_per_token_step}{2}\\[0.35cm]
  \uncover<2->{\normalsize Backward: one product for the activation gradient, one for the weight gradient.}
  \mlsyscredit{Model Training, Lighthouse 8.1.}
  \note{[2 min] [CORE] $P$ is the number of parameters. Step 1: in the forward pass every weight takes part in one multiply-add per token, two FLOPs, so a token costs $2P$. That is all inference pays. Step 2: the backward pass computes two matrix products per weight: one carries the error signal to the previous layer (the activation gradient), and one produces the gradient the optimizer needs (the weight gradient). That is $4P$, and a training token costs $6P$. Over a dataset of $D$ tokens, the work is $O \approx 6PD$. For GPT-2 XL that is $1.5\times10^{21}$ FLOPs. LINK: Lecture 5 derived both backward products for one layer. WARN: the $6P$ rule leaves out the attention-score products, which grow with sequence length squared; for GPT-2 XL at 1,024 tokens they add about 9 percent (320.8 against 295 TFLOP per step in the chapter's per-layer count).}
\end{frame}

\mlsysnote{[2 min] [CORE] The training-time law, the iron law of Lecture 1 specialized to training. The numerator is the work, $6PD$: data times algorithm. The denominator is what the machine delivers: the peak rate at the chosen number format times the utilization, the fraction of that peak spent on useful model arithmetic. Every stall, data wait, synchronization, and slow kernel (a kernel is one operation's program on the accelerator) lowers the utilization. Three levers: do less work, buy a higher peak, or waste less of it. Then point to the last line: memory appears nowhere in the law. A step that does not fit in memory runs at no speed, so memory is a gate, checked before the law applies. LINK: Lecture 1's iron law has the same three factors.}
\mlsysfocus{The Training-Time Law}{%
  $\displaystyle T_{\text{train}} = \frac{\overbrace{6PD}^{\text{work, } O}}{\underbrace{R_{\text{peak}}}_{\text{peak rate}} \times \underbrace{\eta_{\text{hw}}}_{\text{utilization}}}$\\[0.6cm]
  {\small\textcolor{white!75}{Memory is not in the law. It decides whether the step runs at all.}}%
}

\begin{frame}{SGD keeps no extra state; momentum keeps one copy; Adam two}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=4.6cm,keepaspectratio]{optimizer_bytes_step}{3}
  \mlsyscredit{Model Training, \S8.3.2 and table 3 (FP32 throughout).}
  \note{[1.5 min] [OPTIONAL] Every optimizer stores the weights (W) and their gradients (G); in FP32 that is 8 bytes per parameter. Step 1: plain stochastic gradient descent (SGD) keeps nothing else. Step 2: momentum keeps one running velocity per weight, $v$, a smoothed gradient: 12 bytes. \begin{frame}{Mixed-precision Adam holds 16 bytes per parameter}
  \centering
  \safeimg[width=0.95\textwidth,height=5.0cm,keepaspectratio]{static_bytes.pdf}\\[0.3cm]
  {\normalsize Eight times the 16-bit weights an inference server stores.}
  \mlsyscredit{Model Training, \S8.3.2.}
  \note{[2.5 min] [CORE] The common recipe, mixed precision (16-bit arithmetic with 32-bit bookkeeping, taken apart next lecture): 2 bytes for the 16-bit weights, 2 for the 16-bit gradients, 4 for a 32-bit master copy of the weights that the optimizer updates, and 8 for Adam's two 32-bit moments. Sixteen bytes per parameter, against the 2 bytes an inference server holds: eight times.   \note{[2 min] [CORE] Three of the chapter's fallacies. ENGAGE: students write T or F for each, then compare with a neighbor. Step 2: all three are false.   \note{[2 min] [CORE] Answer the hook with today's tools. Step 1: at 16 bytes per parameter, PaLM's 540 billion parameters carry about 8.6 TB of weights, gradients, master weights, and moments, about 100 H100s of memory before a single activation. Memory, not arithmetic, is the first reason a model this size needs thousands of chips. Step 2: what the rewind needed. A training checkpoint saves the 16-bit weights, the master copy, and both moments, 14 bytes per parameter (gradients are recomputed), about 7.6 TB each time. Step 3: what each spike cost. Every rewind repeats about 100 steps on 6,144 chips; in the training-time law that is lost utilization, which is why checkpoint frequency is a throughput decision as well as a reliability one. \begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item Run time is $6PD$ over peak times utilization; utilization moves time and energy together.
    \item Mixed-precision Adam holds 16 bytes per parameter before any activation.
    \item A step holds weights, gradients, optimizer state, and activations; only activations grow with batch and sequence.
    \item Busy time bounds MFU; profile before fixing, and fit before profiling.
  \end{itemize}
  \note{[1 min] [CORE] One line per segment, plus the order of work. Ask students to star the one they would have gotten wrong before today.}
\end{frame}
