\begin{frame}{A sigmoid needs an exponential; a ReLU needs a comparison}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=3.6cm,keepaspectratio]{transistor_tax_step}{2}\\[0.3cm]

  \note{[1 min] [OPTIONAL] Step 1: a ReLU in hardware is a comparator on the sign bit (is the number negative?) and a multiplexer (a switch that passes either the input or zero), about 50 transistor equivalents. FP32 and BF16 (a 16-bit format that keeps FP32's exponent range) span about 10 to the minus 38 to 10 to the 38. FP16, the 2-byte half-precision format that halves memory and traffic, holds only about 6.1e-5 to 65,504. INT16, the format of Ariane's failed conversion, tops out at 32,767. Step 2: the gradient lands far left of FP16's range. ENGAGE: vote. Step 3: C, zero. It is below the smallest normal FP16 value and below FP16's subnormals, the hatched extension that holds values down to 6.0e-8 with fewer significant bits, so it underflows (numpy's float16 of 9.1e-13 is 0.0, printed by calcs.py), and a weight whose gradient is zero stops learning. If students chose B, they think values are clamped to the smallest representable number; they are not. LINK: Lecture 8b (mixed-precision training with loss scaling) and Lecture 10b (quantization). FLEX: cut with the sigmoid predict; the closing slide names range failures.}
\end{frame}

\begin{frame}{Training holds 3.4 times the memory of inference}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=4.4cm,keepaspectratio]{memory_step}{3}\\[0.2cm]
  {\normalsize Training $\approx$ weights $+$ gradients $+$ optimizer state $+$ saved activations}
  \mlsyscredit{Neural Computation, Table 9 (MNIST network, batch 32, FP32; Adam optimizer).}
  \note{[2 min] [CORE] Table 9, the chapter's central result. Bottom bar, inference: the 437.5 KB of weights plus a rolling pair of activation buffers, about 117 KB, because each layer's output can be overwritten once the next layer has read it; about 554 KB. Step 1, training: the same weights, plus every layer's activations kept for the backward pass, 126 KB. Step 2: a gradient for every parameter, another 437.5 KB. Step 3: the Adam optimizer keeps two running averages per parameter (of its recent gradients and of their squares), 875.1 KB. Total about 1.9 MB, 3.4 times inference, for the same weights and the same forward arithmetic. ENGAGE: which bars grow if the batch doubles? Expected: only the activations. WARN: the ratio depends on batch size, precision, optimizer, and whether activations are recomputed. At batch 1,024 the saved activations grow 32 times and dominate (chapter Figure 17); Lecture 8b trades that memory for recomputation.}
\end{frame}

\begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item A dense layer costs one MAC per weight per example; widths fix it.
    \item Matrix multiply is over 99\% of the work; batching reuses each weight.
    \item Backpropagation reads saved forward values; a step is 2 to 3 forward passes.
    \item Training holds weights, gradients, optimizer state, and activations: 3.4$\times$ inference here.
    \item Without branches, a network's common failures are numerical range and memory.
  \end{itemize}
  \note{[1 min] [CORE] One line per section. Ask students to star the one they would least be able to explain tomorrow and reread that section of the chapter first.}
\end{frame}
