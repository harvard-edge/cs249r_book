  \begin{columns}[T]
    \begin{column}{0.40\textwidth}
      \begin{mlsyscard}{mlsysaccent}
        \textbf{Given}\\[0.1cm]
        $d_{\text{in}} \times d_{\text{out}}$ weights in FP32\\
        (4 bytes each)\\
        One example (batch one)\\
        Each weight: one multiply-add,\\
        2 FLOPs
      \end{mlsyscard}
    \end{column}
    \begin{column}{0.56\textwidth}
      \normalsize
      \uncover<2->{FLOPs $= 2\,d_{\text{in}}\,d_{\text{out}}$\\[0.3cm]}
      \uncover<3->{Bytes read $= 4\,d_{\text{in}}\,d_{\text{out}}$\\[0.3cm]}
      \uncover<4->{$I = \dfrac{2\,d_{\text{in}}\,d_{\text{out}}}{4\,d_{\text{in}}\,d_{\text{out}}} = $ {\Large\textbf{\textcolor{mlsysaccent}{0.5 FLOP/byte}}}\\[0.35cm]}
      \uncover<5->{Accelerators need tens to hundreds of FLOPs per byte to stay busy.\\[0.2cm]}
      \uncover<6->{Batch $B$: each weight read serves $B$ examples.}
    \end{column}
  \end{columns}
  \mlsyscredit{Network Architectures, equation 2 (weight-only model; ignores inputs, outputs, and caches).}
  \note{[3 min] Worked example 1. Step 1: the given. Step 2: each weight takes part in one multiply-add, two FLOPs. Step 3: each weight is read once, four bytes in FP32. Step 4: the ratio, arithmetic intensity, is half a FLOP per byte, whatever the widths, because both counts grow with the same product. Step 5: an accelerator's arithmetic can consume tens to hundreds of FLOPs for every byte its memory delivers, so this layer leaves most of the arithmetic idle, waiting for weights. Step 6: the one change that raises the ratio. With a batch of B examples each weight read serves B multiply-adds, so intensity grows to about 0.5 times B until activation traffic takes over (Lecture 5). ENGAGE: ``At what batch does this layer reach 100 FLOP per byte?'' Expected: about 200. WARN: this is a weight-only model; a small layer such as 784 by 128 can stay in on-chip cache, and then dispatch overhead, not memory bandwidth, dominates. FLEX: [CORE].}
\end{frame}

\mlsysnote{[1 min] The one ratio to remember today. Arithmetic intensity is the work done per byte moved. Compare it with the machine's balance, its peak FLOP/s divided by its memory bandwidth: above the balance the arithmetic limits (the compute term of the iron law), below it the memory limits (the data term). Each family today lands at a different intensity, and recurrence escapes this axis entirely: its limit is a chain of steps. LINK: Lecture 11 draws the full roofline.}
\mlsysfocus{Arithmetic intensity decides which term binds}{%
  $\displaystyle I = \frac{\text{operations}}{\text{bytes moved}}\quad\text{(FLOP/byte)}$\\[0.7cm]
  {\normalsize\textcolor{white!80}{Above the machine's balance: compute bound.\quad Below it: memory bound.}}%
}

  \note{[2 min] Step 1: a plain recurrent step has one affine map. An LSTM adds gates, elementwise valves between zero and one: input, forget, and output gates plus a candidate update, four affine maps, so four times the weights and four times the multiply-adds per step. It also carries a cell state beside the hidden state, twice the state. The forget gate lets the cell state pass forward almost unchanged, which is what lets gradients cross many steps. Runtimes fuse the four maps into one matrix multiply four times as wide; that raises intensity but does not shorten the chain. Step 2: memory. At inference a recurrent network keeps only its current state, 2 KB for a 512-wide FP32 vector, whether the stream is 10 tokens or 10,000. Training by backpropagation through time keeps a state for every step, so training memory grows with sequence length. Step 3: say the bridge aloud. \begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item Each architecture bets on the data's structure; a matching bet saves weights and data.
    \item Dense layers at batch one do 0.5 FLOP per byte; convolution reuses each weight at every position.
    \item A convolution becomes a matrix multiply by unfolding its patches, at up to $K^2$ times the input memory.
    \item Skip connections and normalization make depth trainable; each adds memory traffic.
    \item Recurrence holds state fixed and pays in serial steps.
  \end{itemize}
  \note{[1.5 min] One line per idea. Ask students to circle the one they could not have explained an hour ago. FLEX: [CORE].}
\end{frame}
