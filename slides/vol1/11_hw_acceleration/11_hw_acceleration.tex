  \note{[2.5 min] A systolic array is a grid of multiply-add cells that pass data to their neighbors on every clock tick; this one is weight stationary, the design inside the TPU. Step 1: each cell holds one weight and does one multiply-add per cycle. Step 2: activations enter at the left edge and pass from cell to neighbor; each one loaded once is used by every cell in its row. Step 3: partial sums flow down each column, adding one product per cell, and leave at the bottom as outputs. No value returns to a register file or memory between cells; a neighbor wire replaces a memory read. A 128 by 128 array does 16,384 multiply-accumulates (MACs) per cycle; the first TPU's array was 256 by 256. ENGAGE: in an N by N array, how many times is each activation used after one load? Expected: N times. WARN: the diagram omits timing: each row's inputs enter one cycle later than the row above, so the array takes a few cycles to fill and drain, and it is efficient only when the matrix fills it (segment 4). FLEX: [CORE].}
\end{frame}

\mlsysdivider{Which ceiling binds: arithmetic or bytes?}{Hardware Acceleration, \S11.6}
\section{Roofline}

\mlsysnote{[2 min] The roofline (Williams et al. 2009). Arithmetic intensity I is operations per byte moved from memory. Attainable rate is the smaller of two ceilings: the chip's peak, or bandwidth times intensity. The ridge point is where they meet, peak divided by bandwidth. Below the ridge a kernel waits for bytes, and only fewer bytes or more reuse help; above it, only a faster datapath helps. LINK: Lecture 2 drew this for the A100: 312 TFLOP/s over 2.04 TB/s, a ridge of 153 FLOP/byte. Today puts numbers on both axes for the H100. WARN: the roofline gives an upper bound; a kernel below both lines may be limited by something else, such as launch overhead, which profiling finds (Lecture 12).}
\mlsysfocus{The Roofline}{%
  $\displaystyle \text{Attainable} = \min\left(\Rpeak,\ \text{BW} \times I\right)$\\[0.6cm]
  $\displaystyle I_{\text{ridge}} = \frac{\Rpeak}{\text{BW}}$\\[0.5cm]
  {\small\textcolor{white!75}{One ridge per number format: each path has its own $\Rpeak$.}}%
}
