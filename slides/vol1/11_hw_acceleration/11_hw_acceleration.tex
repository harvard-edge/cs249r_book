\begin{frame}{A systolic array reuses each operand across a whole row}
  \begin{columns}[c]
    \begin{column}{0.55\textwidth}
      \centering\mlsyssteps[width=\textwidth,height=5.6cm,keepaspectratio]{systolic_step}{3}
    \end{column}
    \begin{column}{0.43\textwidth}
      \normalsize
      \only<1|handout:0>{\textbf{Weights} stay in the cells.}%
      \only<2|handout:0>{\textbf{Activations} enter at the edge and move right, one cell per cycle.}%
      \only<3-|handout:1>{\textbf{Weights} stay in the cells.\\[0.2cm]
        \textbf{\textcolor{BlueLine}{Activations}} move right.\\[0.2cm]
        \textbf{\textcolor{GreenLine}{Partial sums}} move down.\\[0.4cm]
        {\small $128{\times}128$ cells: 16,384 MACs per cycle (TPU v4)}}
    \end{column}
  \end{columns}
  \mlsyscredit{After Hardware Acceleration, figure 6 and \S11.4.4; Kung 1982; Jouppi et al. 2023.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    Explain a weight-stationary systolic array (the TPU's matrix core) in three steps. First, each cell holds one weight and performs one multiply-accumulate per clock tick. Second, activations enter along the left edge and march rightward one cell per cycle, so one operand loaded into an $N\times N$ array is reused $N$ times across its row. Third, partial sums flow downward one cell per cycle, accumulating products and exiting the bottom as finished outputs. Neighbor-to-neighbor wires replace register-file and memory reads; TPU v4's 128 by 128 array completes 16,384 MACs per cycle (TPU v1 used 256 by 256).

    \notecue{Watch for}{This schematic omits temporal skew: each row enters one cycle after the row above, creating fill and drain phases that Lecture 11b traces cycle by cycle.}

    \notecue{Next}{Quantify how much energy systolic reuse saves per multiply-accumulate compared with naive DRAM fetches.}
  }
\end{frame}

\mlsysdivider{Which ceiling sets the limit: arithmetic or bytes?}{Hardware Acceleration, \S11.6}
\section{Roofline}

\mlsysnote{%
  \mlsysnotemeta{2 min}{Core}%
  State Williams et al.'s (2009) roofline model: attainable performance equals $\min(R_{\text{peak}}, \text{BW} \times I)$, where arithmetic intensity $I$ is FLOPs per byte moved from memory. The two lines meet at the ridge point $I_{\text{ridge}} = R_{\text{peak}} / \text{BW}$ (Lecture 2 introduced this for the A100 at 312 TFLOP/s over 2.04 TB/s = 153 FLOP/byte; today quantifies the H100). Below the ridge, kernels are bandwidth bound and improve only via fewer bytes or higher reuse; above the ridge, kernels are compute bound and improve only via faster arithmetic datapaths. Importantly, each precision has its own peak and therefore its own ridge.

  \notecue{Watch for}{The roofline sets an upper bound; a kernel sitting well below both lines is stalled by launch overhead, latency, or poor parallelism, which profiling diagnoses (Lecture 12).}

  \notecue{Next}{Plot all three H100 precision roofs and ridges on one log-log chart.}
}
\mlsysfocus{The Roofline}{%
  $\displaystyle \text{Attainable} = \min\left(\Rpeak,\ \text{BW} \times I\right)$\\[0.6cm]
  $\displaystyle I_{\text{ridge}} = \frac{\Rpeak}{\text{BW}}$\\[0.5cm]
  {\small\textcolor{white!75}{One ridge per number format: each path has its own $\Rpeak$.}}%
}

Second, after INT8 conversion the profiler flags stage-3 conv as bandwidth bound because doubling peak compute doubled the ridge to 591 without adding HBM bandwidth. Third, reveal the mechanism and fix: if weights become INT8 while activations remain FP16 between layers, intensity rises only to about 569 (falling below 591); keeping activations in INT8 halves every byte and pushes intensity to 1,126, staying compute bound (meanwhile stage-2 3x3 stays just under both ridges at 287 and 574, and 1x1 expansion stays bandwidth bound at 51 and 102, gaining only from halved bytes). Close Section 3: always match a kernel's intensity to the ridge of the exact precision path it runs on (part of Lecture 10b's 5.9x gain).

    Shift from 700 W datacenter GPUs to edge silicon on the Apple A12 SoC, where CPU, GPU, NPU, and ISP share one die and one LPDDR bus inside a fanless 3 to 5 W sustained envelope (10 to 15 W burst only). First, state CMOS dynamic power $P_{\text{dyn}} = \alpha C V^2 f \propto f^3$ whenever raising clock $f$ requires raising voltage $V$. Second, explain the architectural payoff: doubling frequency costs roughly 8 times the power (and cutting clock 20 percent saves far more than 20 percent power because voltage drops too), so accelerators run wide parallel arrays at moderate clocks like TPU v1's 700 MHz. Third, explain sustained mobile behavior: thermal governors apply DVFS to throttle $V$ and $f$ under load (measured on phones in Lecture 12), while unsupported ops falling back to CPU incur cache flushes, layout transposes, and shared-bus contention.
