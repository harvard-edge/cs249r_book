\begin{frame}{Each format spends its bits on range, on precision, or on neither}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=5.4cm,keepaspectratio]{formats_step}{3}
  \mlsyscredit{Model Compression, \S10.3.1 and table 7; FP8 limits: Micikevicius et al. 2022, Table 1. Bit fields drawn to scale.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    To see what shrinking bit width gives up, recall from Lecture 8b that FP32 spends 1 sign bit, 8 exponent bits on range, and 23 mantissa bits on precision within each power of two, while BF16 keeps that 8-bit exponent range and FP16 keeps a wider mantissa than BF16 at a 65,504 cap. Moving to 8 bits, Micikevicius et al. (2022) defined two 8-bit floating-point (FP8) formats that still keep an exponent. E4M3 trades range for finer steps up to 448 for weights and activations, while E5M2 reaches 57,344 for wider-range gradients. Below them, integers drop the exponent altogether. INT8 holds 256 evenly spaced levels at 4 times smaller storage than FP32, and 4-bit integer (INT4) holds 16 levels at 8 times smaller storage. Without an exponent, integers require a shared scale alongside the codes to span both 0.003 weights and 40 activations. Microscaling formats (one exponent per 32-value block) are left to reading, and Lecture 13 owns runtime precision selection.

    \notecue{Next}{Examine a real 4-bit model file to see how many bits those shared scales actually add.}

\end{frame}

\mlsysdivider{How does a quantizer map real numbers onto integers?}{Model Compression, \S10.3.3, Napkin Math 10.1}
\section{Mapping}

\mlsysnote{%
  \mlsysnotemeta{1 min}{Core}%
  Affine quantization maps a real clipping range $[\alpha, \beta]$ onto unsigned $b$-bit integer codes $[0, 2^b - 1]$ using two parameters. The scale $s = (\beta - \alpha)/(2^b - 1)$ is the real spacing between adjacent codes, and the zero-point $z = \operatorname{round}(-\alpha/s)$ is the integer representing real zero. Forward quantization divides by $s$, adds $z$, rounds, and clamps, $x_q = \operatorname{clamp}(\operatorname{round}(x/s) + z, 0, 2^b - 1)$; dequantization inverts it via $x \approx s(x_q - z)$. Signed grids shift those codes down by $2^{b-1}$ onto $[-2^{b-1}, 2^{b-1} - 1]$ (or symmetric $[-2^{b-1} + 1, 2^{b-1} - 1]$ with zero-point zero, dividing peak magnitude by $2^{b-1} - 1$). Every calibration and granularity choice that follows comes down to choosing $\alpha$ and $\beta$ well.

  \notecue{Next}{Visualize this mapping on a 3-bit toy grid.}
}
\mlsysfocus{Affine Quantization}{%
  $\displaystyle x \approx s\,(x_q - z)$\\[0.5cm]
  {\normalsize $\displaystyle s = \frac{\beta - \alpha}{2^{b} - 1} \qquad z = \operatorname{round}\!\left(\frac{-\alpha}{s}\right)$}\\[0.4cm]
  {\small\textcolor{white!75}{$[\alpha, \beta]$: the clipping range \quad $b$: bits \quad $s$: scale \quad $z$: zero-point}}%
}

\begin{frame}{A scale and a zero-point lay an integer grid over the range}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=4.5cm,keepaspectratio]{affgrid_step}{3}\\[0.05cm]
  \only<2|handout:0>{\small $b = 3$: \ $s = \dfrac{2.5 - (-1)}{2^{3} - 1} = 0.5$, \quad $z = \operatorname{round}(1 / 0.5) = 2$}%
  \only<3-|handout:1>{\small Inside the range: nearest level. Outside: clamped to code 0 or 7.}
  \mlsyscredit{3-bit toy, derived from Model Compression, equations 1 to 3. INT8 draws 256 levels the same way.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    To see those equations in action, place a 3-bit grid with 8 codes from 0 to 7 over real values; INT8 works identically with 256 codes. First, five real values appear against the blue clipping range $\alpha = -1$ and $\beta = 2.5$, with two outliers outside. Next, the formulas give $s = 3.5/7 = 0.5$ and $z = \operatorname{round}(1/0.5) = 2$. Code 0 therefore equals $-1$, code 2 equals 0, and code 7 equals 2.5. Finally, the three plotted interior values snap to the nearest level, sending $-0.3 \to$ code 1 at $-0.5$, $0.8 \to$ code 4 at 1.0, and $1.6 \to$ code 5 at 1.5, while the two plotted outliers clamp to the endpoints ($-1.4 \to$ code 0 and $2.9 \to$ code 7). An extra off-slide value such as 2.2 would snap to code 6 at 2.0 with an error of 0.2.

    \notecue{Watch for}{Do not mistake the zero-point for the code of the smallest real value. Code 0 represents $\alpha$, whereas $z$ is the integer code representing real zero.}

Inputs $w$ and $x$ quantize to INT8 with symmetric scales $s_w = 0.75/127$ and $s_x = 2/127$, giving $w_q = [85, -42, 127]$ and $x_q = [64, 127, 32]$.   \mlsyssteps[width=0.95\textwidth,height=4.8cm,keepaspectratio]{cliff_step}{3}\\[0.05cm]
  \uncover<3->{\small With the same networks and 4-bit weights, quantization-aware training recovers most of it.}
  \mlsyscredit{Krishnamoorthi 2018, Tables 3 (8-bit weights and activations) and 5 (4-bit weights).}
  \note{%
    \mlsysnotemeta{3 min}{Core}%
    How abruptly does accuracy break when weights drop from INT8 to 4-bit? Krishnamoorthi's Tables 3 and 5 test both vision models across the plateau and cliff. With per-channel INT8 PTQ, ResNet-50 and MobileNetV2 stay within about 2 points of float. Dropping to 4-bit weights (16 levels) collapses per-tensor PTQ to chance, 0.2 percent for ResNet-50 and 0.1 percent for MobileNetV2. Per-channel PTQ rescues ResNet-50 only to 54.0 percent and fails on MobileNetV2, defining the accuracy cliff. Quantization-aware training (QAT) simulates rounding during fine-tuning so weights adapt to the grid, lifting ResNet-50 to 73.2 percent (within 2 points of float) and MobileNetV2 to 62.0 percent, still 10 points short. Binary and ternary networks (1 to 2 bits using bitwise logic) are left to reading (\S10.3.4).

    \notecue{Watch for}{The exact bit width of the cliff depends on the model and the method, so never extrapolate one network's cliff to another.}

\begin{frame}{QAT rounds in the forward pass, passes gradients straight back}
  \centering
  \begin{tikzpicture}[node distance=0.5cm]
    \node[blk=BlueLine, minimum width=2.9cm] (p) {Pretrained\\model};
    \node[blk=OrangeLine, minimum width=2.9cm, right=of p] (f) {Insert fake\\quantization};
    \node[blk=RedLine, minimum width=2.9cm, right=of f] (t) {Fine-tune on\\training data};
    \node[blk=GreenLine, minimum width=2.9cm, right=of t] (q) {Quantized\\model};
    \draw[arr] (p) -- (f); \draw[arr] (f) -- (t); \draw[arr] (t) -- (q);
  \end{tikzpicture}\\[0.45cm]
  \begin{minipage}{0.92\textwidth}
    \small
    \textbf{Forward:} \ $\hat{x} = \operatorname{round}(x / s)\cdot s$\\[0.05cm]
    {\footnotesize The loss sees the rounding error deployment will see.}\\[0.25cm]
    \uncover<2->{\textbf{Backward:} \ $\dfrac{\partial \hat{x}}{\partial x} = 1$ inside $[\alpha, \beta]$, \ 0 outside\\[0.05cm]
    {\footnotesize Straight-through estimator: rounding's true gradient is 0 almost everywhere.}\\[0.3cm]}
    \centering\uncover<3->{\normalsize Try post-training first; pay for QAT only when it misses.}
  \end{minipage}
  \mlsyscredit{Pipeline after Model Compression, \S10.3.3 (figure 25 and training mathematics); straight-through estimator: Bengio et al. 2013.}
  \note{%
    \mlsysnotemeta{1.5 min}{Optional}%
    Training through rounding hits a calculus obstacle, so QAT inserts fake quantization (simulated rounding in floating point) into a pretrained model. In the forward pass, $\hat{x} = \operatorname{round}(x/s)\cdot s$ exposes the loss to deployment rounding error. In the backward pass, rounding is a staircase whose true derivative is zero almost everywhere. The straight-through estimator, proposed by Bengio et al. in 2013 to copy upstream gradients across discrete operations, resolves this by setting $\partial\hat{x}/\partial x = 1$ inside $[\alpha, \beta]$ and 0 outside, letting full-precision weights accumulate updates until they cross rounding thresholds. In practice, try unlabeled PTQ first, and pay for QAT (needing labeled training data and fine-tuning) only when PTQ misses. Without training data, only PTQ is available.

    \notecue{Watch for}{The straight-through estimator is biased, so QAT optimizes an approximation of the quantized loss.}

    \notecue{Teach}{In a 50-minute class, skip QAT internals; the previous cliff slide already introduced QAT's role.}

    \notecue{Next}{See how GPTQ pushes frontier LLMs to 4 and 3 bits without retraining.}
  }
\end{frame}

\begin{frame}{GPTQ corrects rounding error as it goes}
  \centering
  \includegraphics[width=0.90\textwidth,height=4.8cm,keepaspectratio]{gptq}\\[0.05cm]
  {\small GPTQ rounds each weight while correcting the error it leaves on the next ones.}
  \mlsyscredit{Frantar et al. 2023 (GPTQ), Table 5 (OPT-175B, WikiText2, weights only).}

\begin{frame}{Unpacked in a separate pass, 4-bit weights move more than FP16}

\begin{frame}{Takeaways}
  \vspace{-0.15cm}
  \thumbline{thumb_formats_step3}{An integer format keeps evenly spaced levels; a scale and a zero-point place them over a range.}\\[0.2cm]
  \thumbline{thumb_rounderr_step2}{Inside the range, error is at most half a step; clipping error is unbounded.}\\[0.2cm]
  \thumbline{thumb_perchannel_step2}{The widest values set the scale, so clip rare outliers and give channels their own scales.}\\[0.2cm]
  \thumbline{thumb_cliff_step3}{Eight bits sit on a plateau; below it, try post-training first, then QAT or activation-aware rounding.}\\[0.2cm]
  \thumbline{thumb_dequant_step2}{Fewer bits help a memory-bound layer by the bytes removed, if unpacking stays in the kernel.}
  \note{%
    \mlsysnotemeta{1 min}{Core}%

\begin{frame}{Open questions}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.35cm}
    \item FP8 keeps an exponent and needs little calibration; INT8 needs careful ranges but smaller multipliers. If a phone accelerator could support only one, which should it be?
    \item Outlier features appear near 6.7B parameters. Should models be trained to be easy to quantize, or should quantizers adapt to whatever training produces?
    \item A small set of calibration images now decides how a deployed model behaves on inputs it never saw. Who should own that data, and how should it be versioned?
  \end{itemize}

The third examines how to own and version the small calibration sets that govern deployment accuracy, connecting to Lecture 14 operations.
