\begin{frame}{Each format spends its bits on range, on precision, or on neither}

  \mlsyssteps[width=0.94\textwidth,height=5.4cm,keepaspectratio]{formats_step}{3}
  \mlsyscredit{Model Compression, \S10.3.1 and table 7; FP8 limits: Micikevicius et al. 2022, Table 1. Bit fields drawn to scale.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    Read the bit-field diagram top to bottom. First, recalling Lecture 8b, FP32 devotes 1 sign bit, 8 exponent bits (range), and 23 mantissa bits (precision within each power of two); BF16 preserves FP32's 8-bit exponent and dynamic range, whereas FP16 keeps a wider mantissa and caps out at 65,504. Second, FP8 splits into two variants: E4M3 (max 448) for weights and activations, and E5M2 (max 57,344) for wider-range gradients. Third, integers drop the exponent altogether: INT8 gives 256 evenly spaced levels (4 times smaller than FP32) and INT4 gives 16 levels (8 times smaller), requiring a shared scale alongside the codes to represent both 0.003 weights and 40 activations. Microscaling formats (one exponent per 32-value block) are left to reading, and Lecture 13 owns runtime precision selection.

\mlsysdivider{How does a quantizer map real numbers onto integers?}{Model Compression, \S10.3.3, Napkin Math 10.1}
\section{Mapping}

\mlsysnote{%
  \mlsysnotemeta{1 min}{Core}%
  Present the lecture's central equation: $x \approx s(x_q - z)$. Each clipping range $[\alpha, \beta]$ stores a scale $s = (\beta - \alpha)/(2^b - 1)$ (the real spacing between adjacent codes) and a zero-point $z = \operatorname{round}(-\alpha/s)$ (the integer representing real zero). Say the inverse in plain words: subtract the zero-point, then multiply by the step. Every calibration and granularity choice that follows is simply choosing $\alpha$ and $\beta$ well.

  \notecue{Next}{Visualize this mapping step by step on a 3-bit toy grid.}
}
\mlsysfocus{Affine Quantization}{%
  $\displaystyle x \approx s\,(x_q - z)$\\[0.5cm]
  {\normalsize $\displaystyle s = \frac{\beta - \alpha}{2^{b} - 1} \qquad z = \operatorname{round}\!\left(\frac{-\alpha}{s}\right)$}\\[0.4cm]
  {\small\textcolor{white!75}{$[\alpha, \beta]$: the clipping range \quad $b$: bits \quad $s$: scale \quad $z$: zero-point}}%
}

\begin{frame}{A scale and a zero-point lay an integer grid over the range}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=4.5cm,keepaspectratio]{affgrid_step}{3}\\[0.05cm]
  \only<2|handout:0>{\small $b = 3$: \ $s = \dfrac{2.5 - (-1)}{2^{3} - 1} = 0.5$, \quad $z = \operatorname{round}(1 / 0.5) = 2$}%
  \only<3-|handout:1>{\small Inside the range: nearest level. Outside: clamped to code 0 or 7.}
  \mlsyscredit{3-bit toy, derived from Model Compression, equations 1 to 3. INT8 draws 256 levels the same way.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    Trace affine quantization on a visible 3-bit grid (8 codes, 0 to 7; INT8 works identically with 256 codes). First, place five real values against clipping range $\alpha = -1$, $\beta = 2.5$ (blue), with two outliers outside. Second, compute $s = 3.5/7 = 0.5$ and $z = \operatorname{round}(1/0.5) = 2$, so code 0 equals $-1$, code 2 equals 0, and code 7 equals 2.5. Third, snap interior values to nearest levels ($0.8 \to$ code 4 at 1.0, $-0.3 \to$ code 1 at $-0.5$, $1.6 \to$ code 5 at 1.5; similarly $2.2 \to$ code 6 at 2.0, error 0.2) and clamp outliers to endpoints ($2.9 \to$ code 7, $-1.4 \to$ code 0).

    \notecue{Watch for}{Students often mistake the zero-point for the code of the smallest real value; code 0 represents $\alpha$, whereas $z$ is the integer code representing real zero.}

    \notecue{Next}{Have students apply the exact same equations at full 8-bit precision by hand.}
  }

  \mlsyscredit{Pipeline after Model Compression, \S10.3.3 (figure 25 and training mathematics); straight-through estimator: Bengio et al. 2013.}
  \note{%
    \mlsysnotemeta{1.5 min}{Optional}%
    Walk through the QAT pipeline from top to bottom. First, insert fake quantization into a pretrained model so the forward pass computes $\hat{x} = \operatorname{round}(x/s)\cdot s$, exposing the loss to deployment rounding error. Second, solve the backward pass: because rounding is a staircase whose true derivative is zero almost everywhere, the straight-through estimator (Bengio et al. 2013) sets $\partial\hat{x}/\partial x = 1$ inside $[\alpha, \beta]$ and 0 outside, allowing full-precision weights to accumulate small updates until they cross rounding thresholds. Third, state the operational rule: try unlabeled PTQ first, and pay for QAT (which requires the labeled training set and a full fine-tune) only when PTQ misses; without training data, only PTQ is available.

    \notecue{Watch for}{The straight-through estimator is biased, so QAT optimizes an approximation of the quantized loss.}

    \notecue{Optional}{For a 50-minute class, skip QAT internals; the previous cliff slide already introduced QAT's role.}

    \notecue{Next}{See how GPTQ pushes frontier LLMs to 4 and 3 bits without retraining.}

\begin{frame}{Takeaways}
  \vspace{-0.15cm}
  \thumbline{thumb_formats_step3}{An integer format keeps evenly spaced levels; a scale and a zero-point place them over a range.}\\[0.2cm]
  \thumbline{thumb_rounderr_step2}{Inside the range, error is at most half a step; clipping error is unbounded.}\\[0.2cm]
  \thumbline{thumb_perchannel_step2}{The widest values set the scale, so clip rare outliers and give channels their own scales.}\\[0.2cm]

\begin{frame}{Open questions}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.35cm}
    \item FP8 keeps an exponent and needs little calibration; INT8 needs careful ranges but smaller multipliers. If a phone accelerator could support only one, which should it be?
    \item Outlier features appear near 6.7B parameters. Should models be trained to be easy to quantize, or should quantizers adapt to whatever training produces?
    \item A small set of calibration images now decides how a deployed model behaves on inputs it never saw. Who should own that data, and how should it be versioned?
  \end{itemize}
  \note{%
