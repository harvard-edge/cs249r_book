\begin{frame}{Attention is two matrix multiplies around a softmax}
  \centering
  \vspace{0.3cm}
  {\Large $\text{Attention}(Q,K,V) = \text{softmax}\!\left(\dfrac{\alt<2|handout:0>{\textcolor{OrangeLine}{QK^{T}}}{QK^{T}}}{\sqrt{d}}\right)\alt<4|handout:0>{\textcolor{OrangeLine}{V}}{V}$}\\[0.7cm]
  \begin{tikzpicture}[font=\normalsize]
    \uncover<2->{\node[text width=4.2cm, align=center] at (0,0) {\textbf{\textcolor{OrangeLine}{Scores}}\\$S \times S$, every pair\\$S^2 d$ multiply-adds};}
    \uncover<3->{\node[text width=4.2cm, align=center] at (4.7,0) {\textbf{\textcolor{midgray}{Softmax}}\\each row sums to 1};}
    \uncover<4->{\node[text width=4.2cm, align=center] at (9.4,0) {\textbf{\textcolor{OrangeLine}{Mix values}}\\$S^2 d$ multiply-adds\\again};}
  \end{tikzpicture}\\[0.5cm]
  \uncover<5->{\normalsize $Q$, $K$, $V$ are three learned projections of the same $S$ tokens.}
  \mlsyscredit{Network Architectures, \S6.6.2 and \S6.6.3 (Vaswani et al. 2017). $S$: sequence length; $d$: head width.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    To compute content-based routing in parallel, the transformer paper from Lecture 6 (Vaswani et al., 2017) defines scaled dot-product attention as $\text{Attention}(Q, K, V) = \text{softmax}(Q K^T / \sqrt{d}) V$. For $S$ tokens in one attention head of width $d$ (which equals block width when a layer uses one head), three dense projections form $Q$ (queries, what a token seeks), $K$ (keys, what it advertises), and $V$ (values, what it passes on). First, $Q K^T$ computes all $S \times S$ pairwise scores in $S^2 d$ MACs. Recall from Lecture 5 that softmax normalizes each score row into positive weights summing to 1, which requires reading the entire row. Multiplying by $V$ mixes the value rows in another $S^2 d$ MACs.

    \notecue{Check}{Which terms scale quadratically with sequence length $S$, and which scale linearly? The two matrix products around softmax scale as $S^2$ because every token pairs with every other token. The three dense projections scale linearly in $S$. A tempting mistake is treating the entire layer as quadratic.}

    \notecue{Next}{Work through a four-token head by hand to see every matrix dimension in action.}
  }
\end{frame}

    Once tables cross the 80 GB wall, engineers have three escapes, each with a trade-off. Teams can shrink tables by compression or by mapping multiple IDs to shared rows (hashing), risking collisions on rare tail items; move tables to host DRAM and pay the $52\times$ bandwidth penalty of the PCIe host-to-GPU bus (3.35 TB/s HBM versus 64 GB/s PCIe); or partition tables across accelerators. \begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.3cm}
    \item Attention scores every pair: score work grows with $S^2$.
    \item A block holds $12d^2$ weights; attention's work dominates only past $6d$ tokens.
    \item Decode reads every weight per token and keeps $2Ld$ values per token.
    \item A recommender's bytes are scattered rows; where its tables live comes first.
  \end{itemize}
  \note{%
    \mlsysnotemeta{1.5 min}{Core}%
    Together, all four segments answer why attention and embedding tables let memory set the limit, each anchored by one number. Pairwise attention scores scale as $S^2$ (240 GB per layer at 100,000 tokens if materialized for a 12-head FP16 model). A transformer block holds $12 d^2$ weights, and attention overtakes dense work only past $6d$ (9,600 tokens). Decode reads every weight per token and stores $2 \times \text{layers} \times \text{key-value width}$ values per token in the KV cache, written $2 L d$ for standard $L$-layer multi-head attention like GPT-2 XL (307.2 KB per token). A recommender reads scattered rows, so table placement (51.2 GB per table) comes first. Pick the bullet you could not have explained an hour ago and verify its anchor number from memory.
