\begin{frame}{A model is a function of four versioned inputs and the rounding}

  \note{[2.5 min] Equation 1 as a picture. Step 1: the deployed model's behavior is a function of four inputs, each identified by a version: the code (a Git commit), the data (a content hash, for example from DVC, a tool that versions datasets the way Git versions code), the configuration and hyperparameters (a config file), and the environment (a container image with pinned libraries). Floating-point addition is not associative, so sums reduced in a different order round differently, and the differences compound over thousands of steps; identical seeds can still diverge. Deterministic kernels fix the order at a cost in speed. ENGAGE: which input do teams most often fail to version? The data; the chapter's footnote says that without it the data term is unrecoverable. LINK: the reproducibility envelope across runs is reading (Benchmarking, \S12.8.2). FLEX: [CORE].}

\begin{frame}{Open questions}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.35cm}
    \item A registry promotes only artifacts with a signed feature contract and a named owner. Who signs, and what happens when the signer has left the team?
    \item Should a model that triggers irreversible purchases or trades ever act without an exposure cap? Who sets the cap?
    \item A canary doubles the accelerators that hold a large model. Is a shadow on 1 percent of traffic enough evidence? What can it not show?
  \end{itemize}
  \note{[1.5 min] No single answer. Take one or two responses to each. The first is about ownership that outlives the people who hold it; the second about where operations ends and the business begins; the third about evidence against cost, since a shadow sees inputs and outputs but never the user's response, so it cannot measure click-through. FLEX: [OPTIONAL]; assign one as a short written reflection.}
\end{frame}
