\begin{frame}{Six stages, each handing an artifact to the next}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=5.4cm,keepaspectratio]{loop_step}{3}
  \note{[3 min] This diagram returns all lecture. Step 1: the six stages in the order a project first meets them. Define the problem, collect and prepare data, develop and train the model, evaluate and validate it, deploy and integrate it, monitor and maintain it. Step 2: what each stage hands the next. Problem definition produces measurable targets and limits; data collection produces a versioned dataset; training produces weights; validation produces a release manifest, the record of evidence that a specific model version passed; deployment produces a running service. ENGAGE: ``Which arrow would a traditional software project draw thinly or not at all?'' (The return arrow.) WARN: students read the numbers as a schedule to finish once. The return arrow makes it a lifecycle, because deployment starts a phase of monitoring and retraining. LINK: the operations loop that runs this return path is Lectures 14 and 14b. FLEX: [CORE].}
\end{frame}

\mlsysnote{[0.5 min] The day-\val{day_discard} failure is one instance of a general principle. Name it. FLEX: [CORE].}
\mlsysdivider{How does one decision reach every other stage?}{ML Lifecycle, \S3.2 and \S3.4}
\section{Propagation}

\mlsysnote{[2 min] The constraint propagation principle, the key idea of the lecture. Read it aloud. A trained model, a dataset, a validation report, and a deployment package are all records of decisions. When a limit nobody stated turns up late, every artifact that silently assumed its absence must be traced, and the ones that depended on it must be redone. The size of the rework depends on which artifacts relied on the missing limit; no fixed multiplier for lateness predicts it. Then read the second line. The remedy is to state limits where they can still shape the work. WARN: students hear ``late is expensive'' and conclude that everything must be frozen early. The chapter's point is different. Fix the operating envelope early (memory, latency, power, safety floors), and let data and model choices keep iterating inside it. FLEX: [CORE].}
\mlsysfocus{The Constraint Propagation Principle}{%
  A constraint discovered late forces rework in every artifact\\that relied on its absence.\\[0.5cm]
  {\normalsize\textcolor{white!75}{State a limit early, while it can still shape the work.}}%
}

\begin{frame}{Constraints travel backward and forward through the stages}
  \centering
  \mlsyssteps[width=0.92\textwidth,height=5.3cm,keepaspectratio]{directions_step}{2}

\begin{frame}{Takeaways}
  \small
  \begin{itemize}\setlength{\itemsep}{0.12cm}
    \item The lifecycle is a loop of six stages; monitoring sends evidence back, so deployment starts a phase.
    \item A late constraint forces rework in every artifact that relied on its absence, so trace the dependencies.
    \item Cycle time sets how many ideas a team can test; speed buys breadth of search.
    \item Requirements are numbers in three layers: statistical, physical, operational.
    \item Validation decides readiness by testing the floors on field data, per subgroup, on the device.
    \item Screen deployment for feasibility first; cost only confirms.
  \end{itemize}
  \note{[1.5 min] One line per idea. Ask students to circle the one they could not yet explain to a friend and reread that section first. FLEX: [CORE]; if the Iteration segment was cut, skip its line.}
\end{frame}
