  \end{tikzpicture}\\[0.3cm]
  \uncover<2->{\normalsize A chain of $k$ elementwise operations: $2kNb$ bytes unfused, $2Nb$ fused.}
  \mlsyscredit{ML Frameworks, \S7.3.2. FlashAttention applies the same idea to attention: up to 9$\times$ fewer HBM accesses (Dao et al. 2022).}
  \note{[2.5 min] NARRATE: blue arrows are reads from HBM, the accelerator's main memory; red arrows are writes. Step 1: three elementwise operations run as three kernels. Each reads its whole input from HBM and writes its whole output back, so the intermediate tensors make round trips that the arithmetic does not need. These operations do almost no arithmetic per byte, so their time is set by memory traffic, and each also pays a launch. Step 2: a compiler that sees all three fuses them into one kernel that reads the input once, keeps the intermediates in registers and on-chip SRAM (the small, fast memory beside the compute units), and writes once: about 3 times less traffic and one launch instead of three. The rule: for $N$ elements of $b$ bytes, a chain of $k$ operations moves $2kNb$ bytes unfused and $2Nb$ fused. ENGAGE: ``Why could the eager runtime of two slides ago not do this?'' Expected: it never sees the next operation before it launches the current one. WARN: fusion cannot drop a value the backward pass needs; we return to that in the autodiff section. LINK: Lecture 11 covers the hardware limits on fusion. FLEX: [CORE].}
\end{frame}

\mlsysnote{[1.5 min] The chapter's dispatch overhead law. Numerator: the number of dispatched operations times the host cost of each. Denominator: the device time, compute plus memory, with no overlap assumed. Above 1, the host takes more than half of every step and the workload is overhead bound. The regime depends on the size of each operation, not on the model's parameter count. FLEX: [CORE].}

Step 2: the multiply runs and, because an input requires a gradient, the framework also records a backward node, MulBackward, that knows the multiply's derivative and holds what it needs. Step 3: the add records AddBackward. The chain of nodes is the autograd tape, built during execution. Step 2: prefetch\_factor=2 lets each worker prepare two batches ahead, so up to eight batches wait in host memory. Step 3: pin\_memory=True places finished batches in page-locked memory, so the copy can run by DMA (direct memory access, a copy engine moving bytes without the CPU). Step 4: non\_blocking=True issues the copy without making the host wait for it, the overlap of the previous slide. Each argument answers one bottleneck: loading parallelism, pipeline depth, and DMA transfer. The feeding requirement: an accelerator doing 1,000 images per second at 224 by 224 needs about 150.5 MB/s of raw image data. WARN: more workers are not always better; each holds its own copy of the dataset object and its own memory, and once the pipeline keeps up, extra workers add overhead. \begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item Eager code shows the framework one operation at a time: easy to debug, about 15\,\textmu s of host time each.
    \item A captured graph lets the compiler fuse and plan; compiling pays only after enough runs.
    \item Reverse mode gets every gradient in one pass by keeping forward values, and those set training memory.
    \item The host link is 52$\times$ slower than HBM: place data once, pin it, overlap the copies.
  \end{itemize}
  \note{[1.5 min] One line per section. Ask students to star the line they could least explain tomorrow and reread that section of the chapter first. FLEX: [CORE].}
\end{frame}

\begin{frame}{Open questions}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.4cm}
    \item Should frameworks compile by default? Who should pay for the compile step?
    \item Checkpointing trades arithmetic for memory. When would you never use it?
    \item Operator coverage often decides whether a model runs on new hardware. Should the field standardize on a small operator core?
  \end{itemize}
  \note{[1 min] [OPTIONAL] No single answer. The first weighs researcher time against production throughput; PyTorch stayed eager by default and made compilation opt-in.
