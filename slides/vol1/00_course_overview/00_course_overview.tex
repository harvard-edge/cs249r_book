\begin{frame}{Google measured 864 joules for one median prompt}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=4.4cm,keepaspectratio]{energy_answer_step}{2}\\[0.2cm]
  \uncover<2->{\normalsize Charging a phone once takes the energy of about 46 prompts.}
  \mlsyscredit{Measured: Elsworth et al., ``Measuring the environmental impact of delivering AI at Google scale,'' 2025 (0.24 Wh, median Gemini Apps text prompt). Phone: Model Serving, Napkin Math 13.5.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    How close was our hundreds-of-joules estimate to production reality? In 2025, Google measured a median text prompt in Gemini Apps, its production AI assistant service, at 0.24 Wh (watt-hours), or 864 J, covering accelerators, host servers, idle reserve capacity, and facility overhead. Placing a full smartphone charge of roughly 40,000 J on the same linear scale shows that one prompt is a narrow sliver, about one forty-sixth of a charge.

    \notecue{Check}{What changes when a service answers billions of prompts every day? Although 864 J looks small next to a phone charge, multiplying a tiny sliver by billions of daily requests produces utility-scale power demand. Dismissing 864 J as negligible misses the effect of fleet scale.}

    \notecue{Watch for}{This 864 J figure represents one company's median text prompt. Long multi-step reasoning answers, video, and image generation consume substantially more energy.}

    \notecue{Next}{Multiply that measured per-prompt energy by ChatGPT's daily request volume to compare inference (applying a trained model to inputs) against training.}
  }
\end{frame}

\begin{frame}{ChatGPT's daily prompts use about half a GPT-3 run (estimate)}
  \centering
  \mlsyssteps[width=0.95\textwidth,height=3.8cm,keepaspectratio]{fleet_daily_step}{2}\\[0.3cm]
  \uncover<2->{\normalsize 2.5 billion prompts $\times$ 0.24 Wh $\approx$ 600 MWh per day.}
  \mlsyscredit{Prompts: about 2.5 billion per day for ChatGPT (OpenAI to Axios, July 2025). Energy per prompt: Elsworth et al. 2025 (Gemini median). GPT-3: Patterson et al. 2021. An estimate, not a measurement.}
  \note{%
    \mlsysnotemeta{2 min}{Core}%
    At global traffic, serving, running inference for live users, quickly overtakes training. In July 2025, OpenAI reported roughly 2.5 billion daily prompts for ChatGPT, its conversational AI service. Applying Google's measured 0.24 Wh per prompt yields an estimated 600 MWh (megawatt-hours) per day. Set beside GPT-3 (Generative Pre-trained Transformer 3), OpenAI's 2020 large language model whose one-time training run Patterson and colleagues estimated at roughly 1,287 MWh, daily serving consumes a full GPT-3 training run roughly every two days. For scale, Google Search handles more than 13.7 billion queries per day, showing even larger request volume, although per-query energy depends on whether a query invokes a large model (Introduction, \S1.1).

    \notecue{Watch for}{This calculation applies Gemini's median text-prompt energy to ChatGPT's traffic mix, which includes longer and multimodal prompts combining text with other media. Treat 600 MWh per day as an order-of-magnitude estimate. For popular services, cumulative serving energy far exceeds one-time training.}

    \notecue{Next}{Zoom out from a single AI service to the global electricity share consumed by all datacenters.}
  }
\end{frame}

\begin{frame}{One accelerator node, one part at a time}
  \begin{columns}[c]
    \begin{column}{0.26\textwidth}
      \centering\mlsysphoto[width=\textwidth,height=3.2cm,keepaspectratio]{nvidia-h100-pcie.jpg}\\[0.1cm]
      {\footnotesize\textcolor{midgray}{An H100 accelerator card}}
    \end{column}
    \begin{column}{0.72\textwidth}
      \centering\mlsyssteps[width=\textwidth,height=4.8cm,keepaspectratio]{\mlsyskit/machine_step}{4}\\[0.1cm]
      \uncover<3->{\small HBM holds the model's weights; ``out of memory'' means it is full.}
    \end{column}
  \end{columns}
  \mlsyscredit{Photo: Geekerwan (CC BY 3.0), Wikimedia Commons.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    An accelerator node built around an NVIDIA H100 PCIe card (where PCIe is the expansion bus linking cards to a host server) divides into four hardware parts. On the card, thousands of compute units execute multiply-accumulate operations, multiplying number pairs and summing the results. Beside them sits small, fast on-chip SRAM (static random-access memory). Next, high-bandwidth memory (HBM) holds model weights, the learned parameters storing what the model knows, and triggers an out-of-memory error when full. Finally, the host CPU (central processing unit) and DRAM (dynamic random-access memory, main server memory) connect over a system link. Those three memory tiers form a memory hierarchy trading small, fast storage near compute for larger, slower storage farther away, analyzed in Lecture 11.

    \notecue{Watch for}{Mapping these four components does not yet identify which tier limits a given model. Lecture 11 quantifies which tier bottlenecks each workload.}

    \notecue{Teach}{Name the four hardware components without naming a bottleneck yet, leaving the quantitative diagnosis for Lecture 11.}

    \notecue{Next}{Step back from hardware to inspect how small the model code itself is inside a production ML system.}
  }
\end{frame}

\begin{frame}{An ML system is a stack of layers}
  \begin{columns}[c]
    \begin{column}{0.61\textwidth}
      \centering
      \mlsyssteps[width=\textwidth,height=5.7cm,keepaspectratio]{\mlsyskit/stack_build}{8}

      \only<3|handout:0>{\textbf{Models}\\The architecture and its arithmetic.}%
      \only<4|handout:0>{\textbf{Training}\\Turning data and compute into weights.}%
      \only<5|handout:0>{\textbf{Serving}\\Answering requests within a deadline.}%
      \only<6|handout:0>{\textbf{Operations}\\Keeping it correct after launch.}%
      \only<7|handout:0>{\textbf{Applications}\\What users see, and whom it affects.}%
      \only<8-|handout:1>{\textbf{Data}\\Runs beside every layer.\\[0.3cm]Every lecture works on one part of this stack.}%
    \end{column}
  \end{columns}
  \note{%
    \mlsysnotemeta{3.5 min}{Core}%
    Moving from silicon up to users, the course map arranges the system into eight interacting parts. Hardware (accelerators, memory, and links) sits at the base, supporting Frameworks (ML libraries such as PyTorch and JAX that translate Python into accelerator kernels, the low-level routines running directly on the chip). Above them sit Models (architecture and arithmetic), Training (turning data and compute into weights), Serving (answering requests before a deadline), Operations (keeping quality intact over time), and Applications (user impact). Data runs vertically beside every layer because every layer consumes or produces it.

    \notecue{Check}{Which layers did the opening chatbot answer touch? A tempting answer is to name only Models and Hardware, because those visibly produce the text. In fact, every layer participated, from datacenter hardware and training to serving and post-launch monitoring.}

    \notecue{Next}{Apply this stack directly by mapping a real model that you used earlier today.}
  }
\end{frame}
