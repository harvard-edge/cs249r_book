\mlsysdivider{What sets the carbon of one computation?}{Responsible Engineering, \S15.4.1 and \S15.4.3}
\section{Joules to Tonnes}

\mlsysnote{%
  \mlsysnotemeta{0.5 min}{Core}%
  Converting electricity to emissions multiplies three terms with matching physical units. Operational carbon equals IT equipment energy in kilowatt-hours (kWh), times datacenter PUE (from Lecture 12), times grid carbon intensity in kg CO2e per kWh. Each factor is an independent engineering lever, since model and processor set IT energy, building design sets PUE, and region and hour set grid intensity. Carbon spent manufacturing hardware, called embodied carbon, sits beside this equation as a separate term.

  \notecue{Next}{Test this equation on a measured production prompt from Google's serving fleet.}
}
\mlsysfocus{Operational carbon}{%
  {\Large Carbon $=$ Energy $\times$ PUE $\times$ Grid intensity}\\[0.5cm]
  {\small\textcolor{white!75}{kWh at the IT equipment \quad facility / IT energy \quad kg CO$_2$e per kWh}}%
}

\begin{frame}{DP-SGD clips each example's gradient, then adds noise}
  \centering
  \mlsyssteps[width=0.94\textwidth,height=4.1cm,keepaspectratio]{dpsgd_mech_step}{4}\\[0.1cm]
  {\footnotesize Differential privacy: $\Pr[M(D) \in S] \le e^{\varepsilon}\,\Pr[M(D') \in S] + \delta$ for any datasets $D, D'$ that differ in one record.\\Smaller $\varepsilon$: less any one record can change the output.}
  \mlsyscredit{Responsible Engineering, \S15.5.2, after Abadi et al., ``Deep Learning with Differential Privacy,'' CCS 2016.}
  \note{%
    \mlsysnotemeta{2.5 min}{Core}%
    A randomized training algorithm $M$ satisfies $(\varepsilon, \delta)$-differential privacy (DP) if for any datasets $D, D'$ differing in one record and any output set $S$, $\Pr[M(D) \in S] \le e^\varepsilon \Pr[M(D') \in S] + \delta$. Here $\varepsilon$ sets the multiplicative bound and $\delta$ is additive slack in the inequality; smaller $\varepsilon$ strengthens privacy, whereas $\varepsilon = 8$ allows $e^8 \approx 3{,}000\times$, a weak guarantee. Abadi et al. (CCS 2016) enforced this via four-stage Differentially Private Stochastic Gradient Descent (DP-SGD). Training computes per-example gradients, clips each vector length (norm) to $C$ (unlike standard batch gradient clipping), sums them, adds normal (Gaussian) noise of standard deviation $\sigma C$ (noise multiplier $\sigma$), and updates weights. A privacy accountant tracks cumulative privacy loss and halts training when the $\varepsilon$ budget ends.

    \notecue{Check}{Why clip before adding noise? Noise scales with $C$; without capping one example's norm first, no finite noise hides an unbounded outlier.}

    \notecue{Watch for}{DP bounds statistical influence under formal assumptions. It is not encryption.}

    \notecue{Next}{Inspect PyTorch Opacus code and price per-example gradient memory.}
  }
\end{frame}
