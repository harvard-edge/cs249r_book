\begin{frame}{MinHash finds near-duplicates without comparing every pair}
  \centering
  \mlsyssteps[width=\textwidth,height=5.6cm,keepaspectratio]{minhash_step}{4}
  \mlsyscredit{Data Selection, \S9.3.2; method: Broder 1997. Page text: the C4 sentence Lee et al., ACL 2022 (arXiv:2107.06499, footnote 1) found 61,036 times. Hash values illustrative.}
  \note{%
    \mlsysnotemeta{1.5 min}{Core}%
    Trace MinHash in four steps on a real web example. First, Lee et al. (2022) found this 61-word sentence starting ``by combining fantastic ideas, interesting arrangements'' repeated 61,036 times verbatim in C4; splitting text into overlapping three-word shingles turns near-duplicate detection into set overlap. Second, hashing every shingle and keeping the minimum produces a signature whose match probability equals the Jaccard similarity; 128 hash functions yield a 128-number signature per page. Third, dividing signatures into bands and hashing each band routes likely matches into shared buckets. Fourth, comparing only pages that share a bucket replaces $3.2\times 10^{13}$ all-pairs checks on WebText's roughly 8 million pages with one 40 GB read (about 6 seconds) and 4.1 GB of signatures in host RAM.

    \notecue{Watch for}{MinHash runs on host CPUs while accelerators sit idle, so schedule deduplication as an offline CPU pipeline rather than inside a GPU training job.}

    \notecue{Next}{Inspect a production dataset card to see where MinHash sits inside a real filtering pipeline.}
  }
\end{frame}

\begin{frame}{Takeaways}
  \normalsize
  \begin{itemize}\setlength{\itemsep}{0.25cm}
    \item An example is worth the learning it returns per FLOP.
    \item Selection pays only if scoring plus subset training beats full training, at equal quality.
    \item Deduplicate first; rank the rest with a cheap proxy; keep a coverage floor.
    \item Label where the model is unsure, and compare against random labeling at the same budget.
    \item A FLOP saved becomes time saved only if storage and the host keep up.
  \end{itemize}
