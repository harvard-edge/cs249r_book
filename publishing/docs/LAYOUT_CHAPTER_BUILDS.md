# Mapped Chapter Layout Builds

`binder layout chapter` renders one chapter with the numbering context of an
authoritative full-volume PDF build. It supports rapid PDF layout review when
rebuilding the entire volume after every small prose change would be too slow.

## When to use it

Use a mapped chapter build to compare local paragraph flow, figure placement,
callouts, page breaks, and chapter start/end placement during chapter-by-chapter
editing. Use the full-volume PDF for final sign-off. A mapped build is a fast
layout approximation, not a substitute for the complete build.

The command preserves:

- the chapter number and starting printed page;
- resolved text for external section, chapter, figure, table, equation,
  listing, and algorithm references;
- internal Quarto references, which remain live inside the isolated chapter;
- custom numbered-callout prefixes generated by the book filters.

It does not modify the source QMD. It creates a temporary sibling QMD, restores
the active Quarto configuration and volume index in a `finally` block, and
deletes the generated QMD after rendering.

## Prerequisite: authoritative numbering map

The command reads LaTeX `\newlabel` records from the `.aux` file associated with
the trusted full-volume source build. Keep that `.aux` beside the full PDF and
`.tex` artifacts used as the comparison baseline. Do not use an `.aux` from a
different revision if chapter order, headings, figures, tables, or callouts have
changed.

If the normal build retained only the full `.tex`, run the full TeX source once
with LuaLaTeX in a scratch build directory to produce its `.aux`. Never generate
or refresh the numbering map from the candidate chapter build itself.

## Command

From the repository root or `book/` directory:

```sh
./book/binder layout chapter ml_workflow \
  --vol1 \
  --aux /absolute/path/to/Machine-Learning-Systems-Vol1.aux
```

The chapter argument can be a unique QMD stem such as `ml_workflow` or a path
relative to `book/quarto`, such as
`contents/vol1/ml_workflow/ml_workflow.qmd`.

Outputs are written under:

```text
book/quarto/tmp/layout-harness/<chapter>/
├── manifest.json
├── Mapped-<chapter>.tex
├── _quarto.yml
└── output/
    └── Mapped-<chapter>.pdf
```

`manifest.json` records the source chapter, chapter number, starting folio,
number of mapped references, corrected callout prefixes, numbering source, PDF
path, and restoration checks. Agents should read this manifest before visual
inspection and treat a failed restoration check as a hard stop.

## LLM workflow

1. Select a trusted full-volume baseline and record its revision, PDF, and
   `.aux` paths.
2. Render the chapter with `binder layout chapter`.
3. Confirm the command succeeded and both restoration fields in
   `manifest.json` are `true`.
4. Create a contact sheet that aligns the editor reference, trusted development
   PDF, and mapped candidate by chapter content rather than blindly assuming
   identical PDF sheet numbers.
5. Inspect every page affected by an edit and the chapter's first and last
   pages. One-line local reflow is acceptable when the downstream visual
   architecture and chapter end remain stable.
6. Keep notes on useful wording/length tactics. Prefer accuracy and genuine
   clarity fixes; avoid cosmetic compression.
7. After the chapter passes mapped review, run the authoritative full-volume
   build and verify all chapters again.

## Safety and concurrency

The renderer takes a non-blocking worktree lock because it temporarily redirects
`book/quarto/_quarto.yml` and `index.qmd`. Two mapped builds must not run in the
same worktree. For parallel rendering, use one dedicated worktree per running
build. A build in another worktree is safe because its symlinks and generated
files are independent.

If rendering fails, verify that `_quarto.yml` and `index.qmd` still point to
their original targets. The command is designed to restore them even when
Quarto or LuaLaTeX exits nonzero.

## Interpretation limits

Mapped builds preserve counters and reference widths, but a full book can still
change global indices, frontmatter, and chapter boundaries. The full-volume PDF
is therefore authoritative. Placeholder text such as `section XX.XX` should be
used only when no trusted `.aux` exists; exact mapped labels are preferred
because their word and digit widths better reproduce the real line breaks.
