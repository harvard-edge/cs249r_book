\begin{abstract}
Professional benchmarks require more than a timed model. A defensible result
binds a workload, model, data split, quality gate, system description,
measurement protocol, and evidence package. Official MLPerf suites establish
this discipline at production scale~\citep{mattson2020,reddi2020mlperf,banbury2021mlperf},
but many of their execution paths exceed the budget of a course or an
individual artifact review. We present \textbf{MLPerf EDU}, an independent,
locally executable benchmark specification for teaching and studying
single-node ML systems. The v0.1 registry contains \RegistryRows{} workloads
across \RegistrySuites{} suites. Each workload inherits an authoritative
upstream task, model, dataset and split, evaluator, and quality reference.
MLPerf EDU contributes a thin PyTorch adapter, a measurement harness,
quality-gated reporting, and content-addressed provenance. The reference
campaign contains \ReferenceEvidenceCases{} five-run cases from one clean
source revision. \ScoreBearingCases{} are score-bearing and
\PerformanceBearingCases{} are performance-bearing inference phases. Every
retained run passes its declared gate and the 5\% timing-repeatability limit.
These measurements establish local feasibility, not MLCommons verification or
performance portability. Dataset policy, cross-platform replication, naming,
and governance remain external review questions.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Machine learning systems courses increasingly cover training, inference,
compilers, accelerators, memory behavior, and data pipelines. Students can run
small PyTorch programs for each topic, but a collection of programs is not a
benchmark. Comparability requires a fixed task contract and a rule that speed
is interpreted only after correctness and quality are established.

This distinction matters in practice. A student can improve a number by
changing the dataset, shortening the sequence, measuring warmup, weakening an
accuracy target, or timing random weights. Each change may produce a valid
experiment, but none supports a comparison with the original result. The
missing learning objective is \emph{benchmarking literacy}, the ability to
reproduce, inspect, challenge, and defend a performance claim.

MLPerf EDU transfers mature benchmark discipline to laptop-scale PyTorch
workloads. Its north star is intentionally narrow. It supports teaching and
controlled single-node research on processors, memory systems, runtimes,
compilers, and model execution. It excludes distributed and datacenter-scale
claims.

\begin{definition}[Evaluation Tuple]
A benchmark configuration binds the workload, model, data, hardware, scenario,
constraints, and protocol. It produces a measurement vector containing task
quality and system metrics. We write this relationship as
$\mathcal{S}\rightarrow\mathcal{M}$. Two results are comparable only when the
evidence identifies every component of $\mathcal{S}$ and records every allowed
difference.
\end{definition}

The paper makes five contributions.

\begin{enumerate}[leftmargin=*,itemsep=2pt]
\item \textbf{A backward-designed benchmark contract.} Workloads are admitted
only when an authoritative upstream definition and a credible laptop execution
path already exist.
\item \textbf{A curated seven-workload portfolio.} The suite covers distinct
model structures, data paths, and system behaviors without turning
optimizations into workload identities.
\item \textbf{Quality-gated measurement.} Canonical timing is reportable only
after every task-quality or functional gate passes.
\item \textbf{Reviewable evidence.} Runs emit JSON, CSV, HTML, and provenance
artifacts that bind source, data, model, hardware, configuration, and lineage.
\item \textbf{Ten guarded reference cases.} Five fresh processes per case
establish feasibility and timing repeatability on a disclosed laptop system.
\end{enumerate}

The project does not replace an official MLPerf suite or imply MLCommons
approval. It provides a concrete object for technical and educational review.

\section{Design Principles}
\label{sec:design}

\subsection{Start From Authority}

The project curates rather than invents workloads. Admission requires an
upstream task, model or reference implementation, dataset and split,
evaluator, quality contract, published reference, and credible laptop runtime.
MLPerf, PyTorch, MLCommons, and widely recognized research benchmarks are
preferred sources. A missing component causes deferral or rejection. It does
not justify a project-created proxy.

This rule excludes superficially attractive tasks. MiniGo is the historically
correct MLPerf reinforcement-learning reference, but its self-play and
checkpoint contract has no authoritative laptop configuration. RL is therefore
deferred. CartPole and Pendulum are not substituted. Datacenter recommendation
and distributed training are excluded because reducing their defining scale
would change the systems question.

\subsection{Keep Workload Identity Stable}

A workload ID names a learning task. Training and inference are modes. Full,
prefill, and decode are inference phases. Precision, quantization, compilation,
batching, context length, scheduling, and serving policy are configurations.
This separation allows a class or research study to compare optimizations
without creating a new benchmark for each option.

The profiles express execution intent. \texttt{min} is a fast functional path
for setup, teaching, and CI. \texttt{max} is the canonical classroom and
comparison contract. \texttt{pro} extends the same workload into controlled
single-node research. A profile never weakens the quality rule for a promoted
result.

\subsection{Quality Before Speed}

Every score-bearing case inherits an upstream quality metric and target. Every
individual run and the aggregate must pass. Performance-bearing inference
phases must pass a functional contract and preserve training lineage. A failed
process invalidates the complete five-run attempt. The protocol does not allow
replacement of selected repetitions.

The five executions use the same canonical seed in fresh operating-system
processes. They measure execution repeatability, not seed sensitivity. The
primary timing coefficient of variation must not exceed 5\%. Seed studies are
appropriate research configurations, but they answer a different question.

\subsection{Make Evidence Reviewable}

The evidence boundary includes source revision, comparison fingerprint,
requested and executed device, model and dataset digests, quality and timing
values, acceptance decisions, and the report and manifest index. Causal
inference adds the training package, checkpoint, source report, and source
manifest digests. The three phases must share the same lineage.

Reference campaigns run on AC power with Low Power Mode disabled. Sleep,
power-policy changes, and material concurrent benchmark load invalidate the
attempt. These controls matter on laptops, where power and thermal state can
dominate short measurements.

\subsection{Perception Workloads}

Image classification directly inherits the MLPerf Tiny float ResNet8,
CIFAR-10 accuracy subset, preprocessing, and 85\% top-1 gate. Keyword spotting
inherits the MLPerf Tiny DS-CNN, fixed EEMBC MFCC accuracy set, and 90\% gate.
These rows connect the project to established MLPerf lineage while exposing
dense convolution, depthwise convolution, layout, batching, and small-tensor
accelerator behavior~\citep{banbury2021mlperf,warden2018speech}.

\subsection{Language and Retrieval Workloads}

Causal language modeling preserves nanoGPT's Shakespeare character recipe and
published validation-loss reference. Training, full inference, prefill, and
decode remain one workload. This provides an inspectable train-to-checkpoint-to-
inference chain and exposes attention training, weight reuse, autoregressive
execution, and KV-cache behavior~\citep{karpathy2015char}.

Text classification uses the pinned DistilBERT SST-2 checkpoint and the full
GLUE development split. Information retrieval uses the documented Sentence
Transformers cross-encoder example over the three named NanoBEIR subsets. These
workloads add tokenization, padding, encoder attention, query--document pair
construction, ranking, and nDCG evaluation without inventing a local language
task~\citep{sanh2019distilbert,reimers2019sentencebert}.

\subsection{Irregular and Temporal Workloads}

Graph node classification uses the official OGB GCN recipe, time split, and
evaluator for \texttt{ogbn-arxiv}. Its sparse gather, scatter, and message
passing differ materially from the dense language and vision paths
~\citep{kipf2017semisupervised,hu2020ogb}. Time-series forecasting preserves the official
PatchTST ETTm1 336-to-96 configuration, normalization, optimizer, schedule,
early stopping, split, and MSE evaluator~\citep{nie2023patchtst}. It contributes long windows,
patching, multivariate data loading, and regression quality.

\section{Experimental Results}
\label{sec:results}

The reference campaign executes \ReferenceEvidenceCases{} cases from clean
source commit \texttt{\EvidenceSourceCommit}. One canonical \texttt{max} case
represents each workload. Causal language modeling adds full, prefill, and
decode inference. Every case runs five times in a fresh process at the
canonical seed. The harness independently verifies the report, provenance,
gate outcome, comparison fingerprint, source state, and artifact index before
promotion.

own five-run distribution. Cross-platform replication is necessary before
drawing conclusions about performance portability.

\subsection{Causal Training Lineage}

The causal training campaign selects the run with median quality and packages
its checkpoint, report, and provenance. Full, prefill, and decode each verify
that package before measurement. The imported evidence requires exact agreement
on the package, checkpoint, source report, and source manifest digests across
all phases. This closes a common benchmark loophole in which inference silently
uses random, stale, or separately trained weights.

\subsection{Interpretation Boundary}

The committed summaries are small enough for source control, but raw attempts
remain outside Git because they include checkpoints and dataset-derived files.
Portable packages use relative paths, index every permitted byte, and verify
again after clean extraction. SHA-256 provides unauthenticated integrity. It
does not prove who produced a result or that the recorded computation occurred.

\section{Educational Integration}
\label{sec:education}

The benchmark contract is itself a learning object. A classroom sequence can
move through four stages.

\begin{enumerate}[leftmargin=*,itemsep=2pt]
\item \textbf{Reproduce.} Run a fixed profile and verify its report and
provenance manifest.
\item \textbf{Diagnose.} Attribute time to data preparation, model execution,
synchronization, or request behavior.
\item \textbf{Optimize.} Change one systems variable while preserving the
declared task and gate.
\item \textbf{Defend.} Explain why the comparison is valid and identify the
artifacts supporting each claim.
\end{enumerate}

The public CLI keeps this sequence concrete. A first exercise can use a
network-free \texttt{min} run to inspect JSON, CSV, HTML, and provenance. A
later assignment uses \texttt{max} to introduce real assets and quality. A
research-oriented assignment uses \texttt{pro} or an explicitly recorded
configuration sweep without changing the workload ID.

Three standalone labs complement the registered suite. The first examines
training-loop choices, the second compares naïve and KV-cache decoding while
checking token parity through an educational SUT interface, and the third
compares dense and sparse language-model training. Their outputs state
\texttt{canonical\_result=false}. They teach systems ideas but cannot be
presented as benchmark baselines.

The repository also contains a runnable first-benchmark tutorial. It invokes
the public command, reads the report as data, examines the run fingerprint, and
verifies the paired manifest. These materials establish an executable classroom
path. They do not yet establish learning outcomes. Course pilots, instructor
feedback, accessibility review, and assessment studies remain future work.

\section{Architecture and Implementation}
\label{sec:architecture}

\subsection{Native Registry and Thin Adapters}

The native registry is the single authoring source. Each workload declares its
model, data, modes, phases, measurement boundary, quality gate, canonical
configuration, upstream provenance, and runner. A generator creates flat
compatibility and package mirrors. CI rejects drift between those files.

Adapters preserve upstream semantics. The MLPerf Tiny rows map pinned TFLite
weights into equivalent PyTorch graphs. The OGB and PatchTST rows retain their
official model and evaluator behavior. Transformer rows pin checkpoint
revisions and file digests. Project code handles local execution, measurement,
and artifacts rather than redefining the task.

\subsection{CLI and Execution Profiles}

The command surface supports discovery, environment checks, fetch, run, report,
verify, package, grade, audit, and validation. Mode and phase are explicit.
Invalid combinations fail before execution.

\begin{lstlisting}[caption={Canonical training and inference under one workload identity.},label={lst:cli}]
$ mlperf doctor
$ mlperf fetch --workload \
    causal-language-modeling --profile max
$ mlperf run --workload \
    causal-language-modeling --mode training \
    --profile max --output-dir submissions/causal
$ mlperf run --workload \
    causal-language-modeling --mode inference \
    --phase decode --profile max \
    --output-dir submissions/causal
$ mlperf verify submissions/causal/*.provd.json
\end{lstlisting}

The \texttt{min} profile executes deterministic smoke fixtures and real model
operations without claiming canonical quality. The \texttt{max} profile owns
the admitted real-data contract. The default \texttt{pro} path repeats the
verified \texttt{max} runner and records subrun evidence, providing a safe base
for extended studies.

\subsection{Measurement and Reporting}

Each registry entry declares what timing includes and excludes. Fetching,
construction, and warmup stay outside the measured region unless the upstream
contract says otherwise. Accelerator runs synchronize at measurement
boundaries. Reports disclose both the requested device and executed backend.

Every run emits a JSON report, CSV view, HTML view, and \texttt{.provd.json}
manifest. The manifest binds the report, retained inputs, dataset files, model
or checkpoint, and optional sidecars by digest and byte size. Packages rewrite
machine-specific paths and reject unsafe or policy-disallowed members.

\subsection{Power and Research Measurements}

Optional power output is labeled as an aggregate estimate unless a calibrated
source is available. It can support controlled classroom discussion but not an
absolute joule claim. Roofline classifications similarly remain
\texttt{unmeasured} until a measured, digest-checked sidecar exists. The suite
fails closed instead of inferring system regimes from model names.

\section{Validation Methodology}
\label{sec:validation}

Validation is layered because one green result cannot establish every property.
Unit and integration tests cover registry invariants, runners, contracts,
device reporting, provenance, clean package extraction, evidence import,
baseline synchronization, and generators. Smoke validation executes the fast
public path and grades its artifacts. Coverage validation executes every
registered \texttt{min} path. Full validation executes canonical \texttt{max}
and combined \texttt{min}/\texttt{max} collections.

Release validation additionally requires the following checks.

\begin{itemize}[leftmargin=*,itemsep=2pt]
\item The evidence importer finds exactly seven workloads and ten cases, with
no duplicate or stale-source promotion candidate.
\item Registry baselines, the flat registry, packaged resources, review
packets, site pages, and paper snapshot match their authoring sources.
\item A wheel installs outside the checkout and can list, audit, execute,
report, package, and verify with its packaged evidence.
\item The Quarto site renders the exact seven workload pages, passes internal
link checks, and has no desktop or narrow-layout failures.
\item The paper builds without missing citations, placeholders, unresolved
references, or layout overflows.
\end{itemize}

These gates establish internal technical readiness. They do not settle dataset
rights, grant MLCommons endorsement, authenticate a producer, or replace an
independent rerun.

\section{Related Work}
\label{sec:related}

\textbf{MLPerf.} MLPerf Training and Inference established quality-constrained,
scenario-aware performance evaluation at production scale
~\citep{mattson2020,reddi2020mlperf}. MLPerf Tiny extends the methodology to
constrained embedded systems~\citep{banbury2021mlperf}. MLPerf EDU inherits the
discipline and selected workload definitions while targeting a different use
case, locally executable teaching and single-node research.

\textbf{SPEC and TPC.} SPEC emphasizes controlled conditions, disclosure, and
reproducible comparison~\citep{henning2006}. TPC demonstrates that benchmark
governance and multi-dimensional metrics are as important as workload code
~\citep{poess2000}. MLPerf EDU applies those lessons to classroom-scale ML
systems.

\textbf{DAWNBench and TorchBench.} DAWNBench connected system performance to a
fixed task-quality threshold~\citep{coleman2019}. TorchBench provides broad
PyTorch performance-regression coverage~\citep{ansel2024torchbench}. MLPerf EDU
shares the quality-first principle with the former and the executable PyTorch
surface with the latter, but adds classroom profiles, provenance, grading, and
a deliberately small governed portfolio.

\textbf{Educational frameworks.} Framework-building courses make tensor and
autodifferentiation internals inspectable. MLPerf EDU is complementary. Its
benchmark contract targets system measurement and comparability, and its
PyTorch requirement allows immediate classroom use without coupling the
specification to one educational framework.

\section{Limitations and Future Work}
\label{sec:limitations}

The current evidence comes from one Apple Silicon system. It establishes local
feasibility, not performance portability. CPU reproduction, additional Apple
Silicon reproduction, and Linux accelerator results should test whether the
quality gates and timing protocols transfer. A benchmark can publish multiple
system references without turning any one machine into a performance target.

Some canonical assets are fetch-only while rights and attribution are reviewed.
The repository records those boundaries and excludes restricted bytes from
portable packages. A component license, package-index policy, public raw-packet
hosting decision, name review, and governance path also remain open.

The standard suite is intentionally single-node. It can study kernels,
processors, memory, compilers, runtimes, and model execution. It cannot support
claims about cluster communication, distributed optimization, datacenter
serving, fleet scheduling, or large-model scaling. Those exclusions protect the
meaning of a local result.

The \texttt{min} profile uses deterministic smoke fixtures for speed and
offline use. It proves wiring and artifact behavior, not task quality. The
\texttt{pro} profile provides a research envelope, but a future specification
should define which configuration families deserve standardized scenario
names and which remain open experiments.

Power reporting needs calibrated platform counters or an external meter before
it can support absolute energy comparisons. Classroom and research studies also
need independent evaluation. The present implementation makes the experience
runnable; it does not yet measure learning outcomes or researcher adoption.

\subsection{Threats to Validity}

\textbf{Internal validity.} Five fresh processes reduce sensitivity to one
timing sample, but shared implementation error can remain. The upstream
adapters and target derivations need domain review. Hashes detect byte changes
but do not authenticate execution.

\textbf{External validity.} One laptop and one software stack cannot establish
portable runtime. The reports retain enough environment detail for future
systems to test both quality transfer and timing variation.

\textbf{Construct validity.} The project assumes that practicing controlled,
quality-gated comparisons improves ML systems judgment. That educational claim
is plausible but unmeasured. Course studies and external artifact review are
needed.

\section{Conclusion}
\label{sec:conclusion}

MLPerf EDU brings professional benchmark discipline to a scale that students
and individual researchers can execute locally. Its central contribution is
not a large collection of small models. It is a governed contract that binds an
authoritative workload, quality, measurement, configuration, and evidence
before accepting a performance claim.

The v0.1 implementation contains \RegistryRows{} workload identities and
\ReferenceEvidenceCases{} five-run evidence cases. All score-bearing cases pass
their inherited task gates, all performance-bearing phases pass their
functional and lineage gates, and every retained timing distribution satisfies
the 5\% repeatability rule. That result is strong enough for external technical
review. It is not a claim of official status.

The educational workflow is durable. Reproduce a baseline, diagnose the
system, change one controlled variable, preserve quality, and defend the
comparison with artifacts. The same workflow can remain useful as models,
runtimes, and processors change.

\subsection*{Reproducibility}

The repository contains the native registry, seven canonical runners,
reference summaries, source lock, review packets, website, labs, tutorial, and
paper generator. The public entry point is \texttt{mlperf}. Runs produce JSON,
CSV, HTML, and \texttt{.provd.json} artifacts. Quantitative paper tables are
generated directly from the committed evidence index. Larger raw packages are
retained for \mbox{local reviewer handoff}; they do not yet have public URLs.
